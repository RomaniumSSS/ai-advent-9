# Day 19 — план реализации

Статус: **выполнен локально**. Вход: [`SPEC.md`](SPEC.md), версия 0.2.
План относится только к самостоятельной папке `day19/` в ветке
`RomaniumSSS/day19-mcp-multi-tool` на базе Day 18 `0a4dd60`.

## Исходная проверка

- Код Day 18 и его worktree не изменяются; общих runtime-импортов между днями нет.
- Локально выполнено `uv run python -m unittest day18.test_architecture day18.test_offline -q`:
  **55 tests, OK**. Это проверка исходной архитектуры, а не Day 19.
- Проверка формата и обязательных контрактов `SPEC.md`: **OK**.

## Решение

Day 19 сохраняет узкий stdio MCP-клиент, SQLite как источник истины для batch,
снимка `model_seen`, preview и аудита, а также проверки draft из Day 18.
Сервер Day 19 объявляет ровно три инструмента: `collect_habr_agent_cases`
возвращает сохранённый снимок до 20 записей, `prepare_report_preview` проверяет
draft по этому снимку и создаёт preview, `save_report` записывает только
сохранённый preview в `day19/output/`.

Агенту доступен один каталог из трёх схем на каждом ходе. Общий цикл
`model → validate → MCP → observation → model` не содержит маршрута по номерам
шагов. Локальная политика проверяет имя, схему, `run_id`, размер и бюджет
каждого предложения; сервер отдельно проверяет связи `batch_id` и `preview_id`.
В финале harness сверяет статус сервера, существование файла и hash. Для
отклонённого вызова в историю модели возвращается observation с кодом ошибки.

Профиль модели выбирается перед запуском. В первой версии доступен только
DeepSeek V4.1 Flash с закреплённым DeepInfra, без fallback и SDK retry.
Граница выбора профиля отделена от агентного цикла и проверяется офлайн двумя
тестовыми профилями с fake provider; Qwen в этот план не входит. Локальный
запуск не трогает cron и Telegram Day 18.

## Порядок изменения файлов

Работать только внутри `day19/`: сначала схемы и хранилище, затем серверные
операции, потом MCP runtime и агент, после этого тесты, CLI и материалы сдачи.
Проверки можно добавлять рядом с каждым этапом; таблица выше задаёт границы
готовности. `day18/` служит образцом проверок и семантики RSS, но его код и
данные не используются во время запуска Day 19.

Перед реальным прогоном записать выбранный профиль, фактические лимиты токенов,
оценку верхней стоимости и источник RSS fixture/live. Если оценка превышает
$0.25 или DeepInfra не поддерживает нужные параметры, прогон не начинать и
зафиксировать причину. Не коммитить, не пушить и не деплоить без отдельного
указания.
