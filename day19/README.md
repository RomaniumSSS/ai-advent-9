# Day 19 — агент и три инструмента одного MCP-сервера

По запросу о применении ИИ-агентов модель сама выбрала три вызова локального stdio MCP-сервера: `collect_habr_agent_cases` → `prepare_report_preview` → `save_report`. Это **наблюдавшаяся цепочка**, а не маршрут, зашитый в harness. На каждом ходе агент снова передаёт модели каталог всех трёх инструментов, проверяет выбранные аргументы, исполняет MCP-вызов и возвращает observation с тем же call ID. Сервер хранит batch, снимок `model_seen`, preview и состояния в собственной SQLite Day 19.

| Инструмент | Аргументы модели | Результат и граница |
| --- | --- | --- |
| `collect_habr_agent_cases` | `run_id`, фиксированный RSS-профиль и период | `batch_id`, охват, упорядоченный `model_seen` до 20 с ID, выдержками и каноническими URL |
| `prepare_report_preview` | `run_id`, `batch_id` первого observation, draft по всем показанным ID | Проверенный текст, `preview_id`, SHA-256, исходные URL; второго LLM-вызова внутри tool нет |
| `save_report` | `run_id`, `preview_id` и SHA-256 второго observation | Сервер сам назначает путь под `day19/output/`, атомарно пишет и проверяет файл |

Снимок первого вызова сохраняется по **текущему** `batch_id`: до 15 новых записей, до 5 необработанных из собственной очереди, затем заполнение свободных мест до 20. У старой записи сохраняется исходный `first_batch_id`. Запись очереди считается обработанной только после успешного сохранения. Пустой полный поиск даёт `no_data`; пустой неполный поиск и нехватка бюджета дают разные коды отказа. Лимиты запуска: 5 MCP-попыток и 6 обращений к модели. Путь файла модель не выбирает.

## Офлайн-проверки

Из корня репозитория:

```bash
uv run python -m unittest day19.test_offline day19.test_report_evidence -q
```

Проверено локально: **15 tests, OK**. Тесты используют fake provider, сгенерированные RSS fixture и **настоящий локальный stdio MCP-сервер**, открывая новые соединения между вызовами. Они проверяют смену аргументов обработки при другом поиске, связь `batch_id` → draft → `preview_id`/hash → файл, снимок 15+5 и backlog, пустой/неполный поиск, неверный JSON и ID, неподтверждённую метрику, отказ записи, symlink, повторный save, восстановление после записи до фиксации состояния, бюджет и лимиты. Отдельные тесты проверяют реальные классы статей: действие агента, запуск инструмента для агентов, числа только из выдержки и осторожную формулировку `possible_case`. Два тестовых модельных профиля проходят через один агентный цикл; Qwen в тестах не вызывается.

Это **не** проверка качества реальной модели. Исходные 55 тестов Day 18 были пройдены до реализации Day 19; Day 18 не импортируется и не изменён.

## Реальный DeepSeek-прогон

Актуальные артефакты для просмотра:

- [Безопасный trace](demo/live-trace.json) — отдельный реальный CLI-прогон: 3 последовательных MCP-вызова, 4 обращения к DeepSeek V4.1 Flash через OpenRouter/DeepInfra, `usage.cost` **$0.0016357264**. Trace содержит аргументы, ID, статусы, время и usage; ключ и скрытый reasoning не сохраняются. [Фактический stdout CLI](demo/live-cli-output.json) сохранён отдельно.
- [Проверенный отчёт](output/report-17d91602-69d5-4cdf-9ea4-893cad8c6979.txt) — два подтверждённых случая с подлинными ссылками, SHA-256 `86292178f6660e776b668dd55000a8853157ecdcd23c51feaea2d627ae3d8a66`.
- [Сверка с полными статьями](evals/REPORT.md) и команда ниже для повторной механической проверки.
- [Видео](demo/day19-three-mcp-tools.mp4) — визуализация **этого сохранённого реального CLI-прогона**: запрос локальному агенту, выбранные моделью вызовы, фактический результат CLI и файл. [HTML-версия](demo/evidence.html).

Источник — [полный неизменённый RSS-снимок](fixtures/habr-real-20260927.xml), сохранённый 2026-09-27 09:40 UTC. Для демонстрационного прогона из него взяты четыре подлинных `item` в [отдельный fixture](evals/fixtures/mixed_fact_noise.xml); [метаданные](evals/fixtures/mixed_fact_noise.json) связывают их с SHA-256 полного снимка. Это **частичная выборка**, поэтому отчёт помечен как неполный и не утверждает, что охвачен весь RSS или все статьи периода.

До платного запуска CLI проверяет текущие цены и параметры закреплённого endpoint DeepInfra через [OpenRouter Endpoints API](https://openrouter.ai/api/v1/models/deepseek/deepseek-v4.1-flash/endpoints). Для зафиксированного прогона консервативная верхняя оценка с запасом 10% была **$0.155654**, при лимите **$0.25**. Маршрутизация закреплена на `deepinfra`, fallback и SDK retry выключены. Сведения о текущих ценах могут измениться; preflight запускается заново при каждом повторе.

Проверить сохранённое доказательство без ключа и без сетевых вызовов:

```bash
uv run python -m day19.evals.audit --trace day19/demo/live-trace.json
```

Команда проверяет цепочку ID и hash, файл, URL, partial label и отсутствие ключа в trace, если локальный `.env` доступен. Смысл пересказа и его ограничения сверяются отдельно в `evals/REPORT.md`. Видео собирается из сохранённого trace и stdout, а не выдаёт анимацию за запись терминала в реальном времени. В исходном stdout путь trace указывает на локальный `/tmp`; для публикации тот же файл скопирован в `demo/live-trace.json`. Первый [исторический trace](results/live-trace.json) сохранён неизменным как техническое доказательство цепочки; его [старый отчёт](output/report-b860eff3-bf8f-4525-b159-478201c8cb8c.txt) содержит отрицания, верные только для RSS-выдержки, но вводящие в заблуждение при чтении полных статей. Для демонстрации результата используйте актуальный trace и видео выше.

## Расширенная реальная проверка

[Отчёт по сценариям и сверке с полными статьями](evals/REPORT.md) отделяет
ранние ошибки классификации от повторов после исправления. В нём есть
сохранённые trace 45 запусков с реальным DeepSeek и локальным MCP-сервером:
подлинные RSS-выборки, пустой и повреждённый источник, широкий RSS и два
чтения текущей ленты из сети. [Последний сетевой trace](evals/traces/live_feed-2.json)
и [созданный файл](output/report-8ea20b95-16cc-41a6-8802-99833c00b569.txt)
показывают три вызова и явную неполноту охвата.

Проверить сохранённые trace, цепочку ID, хеши файлов и источники URL без ключа:

```bash
uv run python -m day19.evals.audit
```

Для новых оплачиваемых сценарных прогонов с отдельной SQLite на каждый запуск:

```bash
uv run python -m day19.evals.runner mixed_fact_noise wide_rss --start-repeat 8 --repeat 8
```

`runner` требует ключ, создаёт выборки из реального RSS-снимка и пишет
`evals/runs.jsonl`. Текущий агент видит только заголовок и короткую выдержку
RSS: полная статья иногда подтверждает применение, скрытое за обрезанной
выдержкой. В таком случае метка «по RSS не подтверждено» не означает,
что применения нет в статье; конкретные расхождения перечислены в отчёте.

Для нового платного прогона нужен `OPENROUTER_API_KEY` в `day19/.env` с правами `0600` либо в переменной окружения. Используйте **новую** базу SQLite: очередь ранее обработанного запуска влияет на следующий снимок. Пример с сохранённым реальным fixture:

```bash
chmod 600 day19/.env
uv run python -m day19.cli \
  --db day19/replay.sqlite3 \
  --rss-file day19/evals/fixtures/mixed_fact_noise.xml \
  --start 2026-09-22T00:00:00Z --end 2026-09-27T09:38:00Z \
  --request "Собери сводку реального бизнес- и личного применения ИИ-агентов. Отличай практику от мнений и учебных примеров; сохрани отчёт." \
  --trace day19/evals/traces/replay-manual.json
uv run python -m day19.evals.audit --trace day19/evals/traces/replay-manual.json
```

Без `--rss-file` сервер читает текущий фиксированный RSS Хабра. Модель может предложить иной draft или потребовать исправления, поэтому новый запуск не обязан повторить число попыток из сохранённого trace. Профиль задаётся перед стартом; пока для реального запуска разрешён только `deepseek`. Структура профиля позволяет позже добавить другую модель, но для Qwen потребуется отдельное решение о провайдере и отдельная оценка.

Видео можно пересобрать по уже сохранённому trace без модели:

```bash
uv run python -m day19.demo.record
```

Потребуются Chromium/Google Chrome для Playwright и `ffmpeg`. Работа выполнялась только в `day19/` отдельной ветки.
