- VPS: SSH alias `crm-agent`, Ubuntu, Python 3.12, активный системный `cron`, системная зона UTC.
- Код: `/opt/day18-agent`; исполняемый пользователь `day18` без интерактивного входа. Рабочая SQLite: `/var/lib/day18/day18.sqlite3`; закрытый конфиг: `/etc/day18/day18.env` (0600, owner `day18`). Значения секретов не копировались в репозиторий и этот отчёт.
- Дайджест установленного runtime-кода совпадает с локальным: `sha256sum day18/*.py day18/schemas/*.json day18/deploy/*.sh | sha256sum` → `09bd0b36dc24c566abdbcd9823ac1f81631c75c901aa6ef04854c22b103c3962` на обеих машинах.
- Ежедневный `/etc/cron.d/day18-agent`: `0 16,17 * * * day18 /opt/day18-agent/run-scheduled.sh`. В 16:00 UTC летом или 17:00 UTC зимой локальный guard разрешает только 18:00 `Europe/Warsaw`; второй trigger возвращает `not_due`. ## Реальный запуск cron с отправкой сейчас

Одноразовый `cron` вызвал тот же агентный entrypoint с явным `backfill --date 2026-09-26 --actor cron-demo`, чтобы увидеть доставку до ближайшего 18:00. Строка в журнале `cron`:

```text
2026-09-26 22:15:01 UTC (day18) CMD (/usr/bin/env -C /opt/day18-agent /opt/day18-agent/.venv/bin/python -B -m day18.cli --env-file /etc/day18/day18.env --db /var/lib/day18/day18.sqlite3 --model deepseek/deepseek-v4.1-flash --verified-visible-budget 20000 backfill --date 2026-09-26 --actor cron-demo >> /var/log/day18/demo.log 2>&1)
```

## Предел доказательства

Это доказанный **запуск по расписанию cron** и реальная отправка до 18:00 через явный backfill. Сам ежедневный trigger в 18:00 на момент этой записи ещё не наступил. Видео в `day18/demo/` показывает просмотр сохранённых фактов этого запуска; оно не является записью экрана в момент 22:15 UTC.
