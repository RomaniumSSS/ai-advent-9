# Day 18 — подготовка G2: реальный RSS и модель

Дата первоначального расчёта: 26.09.2026. Этот расчёт был составлен **до**
внешнего RSS-запроса и платного model call. Первый фактический run и его пределы
описаны в [G2 first run](g2-v41-first-run.md). P0–P7 и их локальные доказательства — в
[local-validation](local-validation.md). Первоначальный gate ограничивал работу
одним диагностическим `manual no-send` запуском; Telegram, VPS/cron, commit и
push в него не входили.

## Закреплённый маршрут

- Модель: `deepseek/deepseek-v4.1-flash` через OpenRouter, provider `deepinfra`
  без fallback. ID закреплён в `day18/config.py`, другой модельный ID отклоняется
  до создания клиента. Выбор MCP моделью V4.1 Flash в Day 18 ещё не проверен;
  успешный Day 17 использовал предыдущий V4 Flash 0731.
- [Страница OpenRouter для модели](https://openrouter.ai/deepseek/deepseek-v4.1-flash)
  подтверждает поддержку `tools` и `tool_choice`.
  В таблице провайдеров DeepInfra на 26.09.2026 указан базовый тариф
  **$0.20 / $0.60 за 1 млн входных/выходных токенов** и временная скидка 30%
  (**$0.14 / $0.42**). Для лимита ключа используем базовый тариф: скидка может
  исчезнуть до запуска. Усреднённая цена по провайдерам неприменима.
- [DeepSeek указывает](https://api-docs.deepseek.com/guides/thinking_mode/), что
  thinking у V4.1 включён по умолчанию. Адаптер явно посылает
  `reasoning.effort=none` через OpenRouter и требует поддержку параметров у
  закреплённого провайдера. Фактические `usage.completion_tokens_details`,
  отсутствие hidden reasoning и доступный visible budget надо проверить по
  live ответу; опубликованная поддержка tools не доказывает результат turn.

## Расчёт стоимости

Локальный guard отказывает до вызова провайдера при сериализованных
`messages+tools` >80 000 UTF-8 bytes. Для сметы принято **100 000 входных
токенов на вызов**: 1 токен на байт допустимого payload плюс запас 20 000 на
обрамление и преобразование провайдером. Это консервативное расчётное
допущение, не измерение токенизатора. Выход задан кодом: call 1 ≤1 000,
call 2 ≤8 192 токена. Reasoning и видимый ответ должны уложиться в выданный
провайдером completion limit; поведение проверяется по live usage. Если
предположение не подтверждается, дальнейшие вызовы останавливаются и смета
пересчитывается.

| Сценарий | Вход для сметы | Макс. выход | Расчёт по базовому тарифу DeepInfra |
| --- | ---: | ---: | ---: |
| Один обычный выпуск, 2 вызова | 200 000 | 9 192 | $0.04551520 |
| Тот же run с одним явным операторским resume, всего 4 вызова | 400 000 | 18 384 | $0.09103040 |

Формула: `input_tokens × 0.20 / 1 000 000 + output_tokens × 0.60 / 1 000 000`.
Расчёт не включает возможные комиссии пополнения баланса, налоги и VPS; они
не являются расходом model API. Фактический расход записывается только из
`usage.cost`, если его вернул OpenRouter; отсутствие `cost` не заменяется нулём.
Перед первым вызовом цену следует сверить повторно. Первоначально предлагался
отдельный API key с лимитом **$0.10 без сброса**: OpenRouter
[поддерживает лимит расходов на ключ](https://openrouter.ai/docs/api/api-reference/api-keys/create-a-new-api-key).
Проверка `GET /api/v1/key` 26.09.2026 показала `limit=null`, а пользователь
явно ответил «без лимита». Для этого одного диагностического запуска внешний
лимит не является условием; действуют локальные границы: ≤2 model calls,
`max_retries=0`, 80 000 bytes входа на вызов, выход ≤1 000 + 8 192 токена,
без `resume`. Прайс маршрута DeepInfra на дату проверки: скидочный
$0.14/$0.42 за 1 млн, по этой смете ~$0.03186 за обычный run; базовый тариф
выше и остаётся расчётным ориентиром.

## Точный следующий запуск после отдельного допуска

1. Убедиться, что ключ записан как `OPENROUTER_API_KEY` в корневой `.env` с
   правами `600`; запускать CLI с
   `--env-file .env`. Не показывать ключ в команде, чате или trace.
2. Сверить официальный Habr RSS link по `application/rss+xml` и фактический
   ответ фиксированного URL; при расхождении остановиться и версионировать
   source profile, не подставлять другой URL на лету.
3. Выполнить один `manual no-send` run на временной локальной SQLite БД:
   максимум два model calls, один реальный MCP RSS execution, ноль Telegram
   sends. Записать redacted provider→MCP→provider trace, batch/coverage,
   `usage` и фактический `cost` если возвращён. Не делать explicit resume без
   отдельного решения по результату первой попытки.
4. Если модель не выбрала tool, RSS profile непригоден, draft не прошёл
   validation или budget/tokenizer не подтвердился, остановить G2. G3
   (Telegram/VPS) не начинать по одному лишь факту успешного API ответа.

Пользователь запросил переход на последнюю стабильную DeepSeek и первый запуск;
scope запуска — **одно реальное чтение Habr RSS и не более двух платных
обращений к закреплённой модели**, без Telegram/VPS. Ключ задан в `.env`;
его значение в документ не вносится. `DAY18_TELEGRAM_CHAT_ID` пока пуст,
но `manual no-send` его не использует.
