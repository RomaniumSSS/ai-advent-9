# Day27 — локальный веб-чат

Свободный вопрос, потоковый ответ Qwen3 и продолжение разговора. «Новый чат» очищает
память. Завершённые пары сообщений хранятся только в текущей странице браузера;
после восьми ходов для следующего запроса остаются последние восемь. Перезагрузка
страницы тоже очищает историю. Ошибочный или оборванный обмен виден в переписке,
но не добавляется в контекст следующего вопроса.

Готово локально 08.10.2026: [живая запись 43 с](video/Day27-live.mp4),
[архив кода](Day27-code.zip), [результат и ограничения](RESULT.md),
[release notes](RELEASE_NOTES.md).
[Видео на Google Drive](https://drive.google.com/file/d/1xa1AKj_OgkX1O-xQU495QIgVuvs3UFLM/view?usp=sharing)
загружено в общую папку AI Advent и доступно для просмотра по ссылке.
Коммит и push разрешены пользователем; пользовательская сдача ещё не подтверждена.

## Запуск

Нужны Python 3.10+, запущенная Ollama и установленная `qwen3:8b` (Q4_K_M).
Новые пакеты для приложения не требуются.

```sh
python3 day27/app.py
```

Открыть <http://127.0.0.1:8067>. Backend слушает только loopback и обращается только
к `http://127.0.0.1:11434/api/chat`; системный proxy и перенаправления отключены.
Параметры: `think=false`, `num_ctx=4096`, `num_predict=384`, таймаут 300 секунд.
При достижении лимита ответ может завершиться с причиной `length` — она показана
в интерфейсе вместе с реальными метриками Ollama. Недоступная метрика отмечена «—».
История ограничена 12000 символами; при превышении нужно начать новый чат.

В приложении нет облачного fallback, RAG, постоянной памяти, импортов других дней
и журналирования пользовательских сообщений. Статус готовности проверяет наличие
модели через `/api/tags`; он не доказывает успешную генерацию.

## Проверки

```sh
python3 day27/tests/test_app.py
```

Это офлайн `unittest`: HTTP validation, порядок и передача истории, payload модели,
части ответа, настоящий `done`, ошибка провайдера, повреждённый поток, EOF,
локальный адрес, отключение proxy/redirect. Реальную модель тесты не вызывают.
Начальная красная стадия: [tdd-red.txt](tests/tdd-red.txt); итоговая зелёная:
[tdd-green.txt](tests/tdd-green.txt). Проверку UI/реального провайдера и видео выполняет
ответственный отдельно; результаты каждого живого прогона сохраняются независимо.

Для проверки настоящего браузерного интерфейса с фикстурами запустить приложение,
затем выполнить в отдельной среде записи:

```sh
uv run --no-project --with playwright python day27/tests/check_browser.py --output /tmp/day27-browser-check-new
```

Каталог должен быть новым. Это проверка истории, сброса, восстановления после ошибок,
отсутствующих метрик и трёх размеров экрана; ответы Ollama подменены явно,
реальных генераций нет. [Фактический результат](results/browser-check-1/results.json).

## Живой сценарий и запись

[Сценарий](video/SCENARIO.md) использует один скрипт для обоих режимов. Он требует
Playwright с Chromium в отдельной среде записи; для MP4 нужен ffmpeg. Запускать
при работающем приложении, последовательно с другими локальными LLM-прогонами.

```sh
uv run --no-project --with playwright python day27/video/run_demo.py --dry-run
uv run --no-project --with playwright python day27/video/run_demo.py --record
```

Каждый запуск создаёт новый `day27/video/runs/<UTC>-<id>/` либо новый каталог
`--output`. Сохраняются фактический контекст каждого запроса, полный ответ, метрики,
ошибка, снимки и (при записи) исходный WebM и MP4 без ускорения. Старые файлы
не перезаписываются. Первый ответ требует человеческой проверки уместности трёх
шагов; скрипт отдельно проверяет название проекта и арифметику. Наличие ролика ещё
требует проверки кадров и ffprobe; код сам не объявляет пользовательскую сдачу.
Проверенный дубль: [record-1](video/README.md); в нём три новых генерации без фикстур.
