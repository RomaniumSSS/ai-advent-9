# Day27 — три действия в настоящем локальном чате

Статус: сценарий по разрешённому объёму; фактические ответы и длительность ещё
не получены. Источник требований — [SPEC](../SPEC.md).

## Начальное состояние

Приложение `http://127.0.0.1:8067`, локальная Ollama и установленная `qwen3:8b`
Q4_K_M. Отдельный browser context с пустым диалогом, читаемый viewport
(ориентир 1280×1000). Отдельные каталоги для сухого прогона и записи;
старые ответы и файлы не перезаписываются. Другие локальные LLM-прогоны не запускаются
одновременно. Снимать viewport этого приложения имеющимися инструментами.

## Действия пользователя

| Шаг | Действие и точный ввод | Что должно быть видно и сохранено |
| --- | --- | --- |
| 1 | Ввести и отправить: **«Наш учебный проект называется „Маяк“. Предложи три коротких шага создания локального чат-приложения. Ответь по-русски, до 60 слов.»** | Свободный ввод, появление частей настоящего ответа, окончательный статус и метрики. Сохранить полный ввод/ответ; смысловой контроль: три уместных шага. |
| 2 | В том же диалоге отправить: **«Как называется наш учебный проект? Ответь только названием.»** | Новый request ID и настоящий ответ. В переданном контексте есть обе завершённые реплики шага 1. Ответ должен назвать «Маяк»; сохранить фактический вывод независимо от совпадения. |
| 3 | Нажать **«Новый чат»**, показать пустой диалог, затем отправить: **«Сколько будет 17 + 25? Ответь только числом.»** | Старые реплики исчезли; payload содержит новый запрос без истории первых двух шагов. Видны поток, финальный статус и метрики; ожидаемый смысловой результат — 42. |

После каждого отправления ждать окончание **этого** запроса по request ID,
реальному конечному событию и состоянию UI. Эхо ввода, надпись сценария или
истёкший таймер ответом не считаются. Таймаут выбрать с учётом наблюдённой скорости
локальной модели; не назначать длительность ролика вместо ожидания ответа.
После завершения дать время прочитать ответ; при необходимости прокрутить.

## Доказательства и оценка

Один скрипт выполняет эти действия без записи и с записью; записанный прогон делает
новые запросы. Для каждого сохранить `request_id`, время начала, точный отправленный
контекст, **actual output целиком**, финальный статус/ошибку, доступные токены,
причину завершения и длительность. Не обрезать ответ, скрывая ошибки.
Отдельно отметить транспортный успех и смысловое качество каждого ответа.

Недоступная модель и оборванный поток проверяются офлайн/контролируемыми проверками
и не требуют остановки общего Ollama ради видео. При обязательном сбое сценария
устранить причину перед записью; не выдавать неудачный дубль за готовый результат.

Закрыть свой browser context в `finally`, дождаться файла. Сохранить исходную запись
и отдельный MP4 без ускорения ожидания. Проверить длительность/размеры через `ffprobe`,
прочитать кадры старта, каждого ключевого ответа и конца. Сопоставить три request ID,
ответы и видимые метрики с журналом **этого** дубля. Указать точные пути артефактов
в результате; отсутствие видео оставляет формат «Видео + Код» незавершённым.
