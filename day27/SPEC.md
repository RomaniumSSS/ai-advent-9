# Day27 — локальная LLM в веб-чате

Статус: спецификация сформирована по обсуждённому объёму. Пользователь разрешил
параллельные планирование и реализацию; этот письменный файл отдельно ещё не просматривал.
Источник: AI Advent, сообщение **4766 от 06.10.2026** в
`ChatExport_2026-10-08/messages.html`: приложение отправляет запросы локальной LLM,
получает и отображает ответы, работает без облачных моделей. Результат — **Видео + Код**.

## Результат и границы

Самостоятельный веб-чат Day27 на `http://127.0.0.1:8067`: свободный ввод,
потоковый ответ, история в памяти браузера и кнопка «Новый чат».
В следующий запрос входят последние восемь завершённых ходов; ограничение видно в интерфейсе.
Backend — Python standard library; модель — уже установленная `qwen3:8b` Q4_K_M,
Ollama `http://127.0.0.1:11434/api/chat`. Запросы идут только локально,
без ключей, cloud fallback, новых весов и изменения зависимостей приложения. Код Day01–26 не меняется
и не импортируется. Нет RAG (это Day28), долговременной памяти и внешнего размещения.

## Критерии приёмки

1. Пользователь вводит произвольный непустой текст; приложение передаёт его в
   `/api/chat` вместе с последними восемью завершёнными ходами и выбранной моделью.
   Продолжение диалога сохраняет порядок `user`/`assistant`; более ранние сообщения
   остаются на экране, но не передаются модели. «Новый чат» очищает контекст и экран.
2. Ответ появляется по мере поступления частей. Успех отмечается только после
   настоящего конечного события Ollama `done: true`; закрытие потока само по себе
   успехом не считается. Незавершённый ответ не становится завершённой репликой истории.
3. Недоступная Ollama/модель, повреждённый или оборванный поток показываются явной
   ошибкой. Интерфейс возвращается в рабочее состояние; ошибку нельзя скрыть меткой успеха.
4. Завершённый запрос имеет идентификатор, фактическое время и доступные метрики Ollama
   (число сгенерированных токенов, причина завершения; недоступное значение не равно нулю).
   Журнал прогона позволяет связать запрос, полный ответ и окончательный статус.
5. Backend слушает только `127.0.0.1:8067`; адрес Ollama фиксирован локально.
   Приложение не обращается к облачной модели и не требует API-ключа.
6. Сценарий [видео](video/SCENARIO.md) проходит с настоящей локальной генерацией:
   свободный ввод, продолжение с историей, новый диалог. Сохранены реальные ответы
   и метрики именно записанного прогона; видео читаемо и проверено.

## Проверки и зависимости

Значимое HTTP/stream/history поведение — TDD с `unittest`/локальными заглушками:
передача истории, сброс, части потока, финальное событие, HTTP-ошибка и ранний EOF.
Моки доказывают обвязку; живой локальный прогон отдельно проверяет интеграцию и
смысловое качество. Используются имеющиеся Ollama/модель и браузер записи Day26;
Python Playwright для записи запускается в изолированной среде uv, без изменения project lock.
Отключение интернета не является обязательным шагом и не заявляется проверенным без проверки.
Код, видео, публикация и пользовательская сдача — отдельные статусы;
commit/push/merge/публикация требуют действующего разрешения.
