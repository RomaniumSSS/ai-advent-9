## Что нужно перед живым запуском

Отдельное решение пользователя должно подтвердить обе области, проверенный identity SHA замороженного индекса и новый бюджет. Прежняя авторизация Day24 не означает разрешение Day25. `BUDGET-PROPOSAL.json` — предложение, `NOT_GRANTED`. Read-only `search.manifest()` 04.10.2026 вернул SHA `6c3672a133e01288a7c8b1b59d5f017183f7a14402a000c9b5290b4f7a25f6bb`, 663 document IDs и `assignment:18`; перед live preflight повторно сверит этот SHA с обоими серверами.

| Область | Новые вопросы/поиски | Максимум генераций | Верхняя оценка резервов | Предложенный лимит |
| --- | --- | --- | --- | --- |
| public, assignment:18 | 12 | 12 | $0.05408256 | $0.06 |
| all, весь одобренный frozen snapshot | 12 | 12 | $0.05408256 | $0.06 |
| Всего | 24 | 24 | $0.10816512 | общий $0.12 либо два независимых $0.06 |

По текущему локальному коду per-call reserve: `(24000 + 2048) × $0.14 / 1e6 + 2048 × $0.42 / 1e6 = $0.00450688`. Это оценка при предельном packed messages, output2048 и текущих rate ceilings, не свежий тариф и не измеренный расход. Настоящий service запрашивает цены перед каждой генерацией, отклоняет превышение потолка и учитывает provider-reported cost/unknown резерв. У отказа из-за empty поиска генерации нет; гарантировать24 платных вызова заранее нельзя, только верхний максимум. Retries0; возможные повторные эксперименты не включены.

Видео записывает только сохранённый public чат и добавляет **0** поиска/генераций. Оно честно обозначается просмотром сохранённых результатов, а не новой генерацией. Общий счётчик требует разделить provider-reported и mock cost.

## Исполнение после отдельного разрешения

Использовать выделенные loopback сервера Day25, не рабочий Day24: обычный all на8053, `--public-only` на8054. Серверы имеют одобренный frozen identity и новую авторизацию; runner её не создаёт, не копирует и не меняет. Можно использовать один новый data-dir/общий ledger с budget$0.12, выполняя запросы последовательно, либо два data-dir с отдельными budget$0.06. Не запускать другой Service на этом же data-dir во время активного запроса: startup recovery предназначен для перезапуска остановленного процесса.

Команда подготовки живого запуска (пока **не выполнять**):

```sh
python3 day25/validation/scenario_runner.py --mode live --approved-live \
  --identity-sha256 6c3672a133e01288a7c8b1b59d5f017183f7a14402a000c9b5290b4f7a25f6bb \
  --public-url http://127.0.0.1:8054 --all-url http://127.0.0.1:8053 \
  --output day25/private/live-run-01
```

`--approved-live` только подтверждает уже существующее разрешение в сессии; не предоставляет его и не обходит runtime authorisation. All evidence дополнительно сверяет search identity и использованный authorization identity с заданным SHA. В режиме offline нужен явно помеченный synthetic server на обоих URL; реальные вызовы/SSH запрещены стендом.

Runner отправляет вопросы **через обычные формы UI**, не прямым provider API; он проверяет scope, chat ownership, свежий поиск, task-state snapshot, источники и отказы. Перед каждым действием записывает run.json/events.jsonl в закрытый output. Во время POST сохраняется ID запроса без токенов. При прерывании action остаётся неоднозначным: `--resume` не повторяет его, требуется ручное чтение результата/ledger и разбор. Никакая автоматическая retry не добавлена.

После шестого public вопроса runner сохраняет checkpoint и выходит с кодом2/AWAITING_SERVER_RESTART. Остановить только dedicated public server, запустить с тем же data-dir и повторить **ту же команду** с `--resume`. Runner GET-проверяет сохранённую память/ID архива и изменение PID до следующего POST. Если PID/состояние не подтвердились, остановка вместо фиктивного PASS. Второй all-сценарий запускается затем на8053. При неизвестном расходе новые платные ходы запрещены приложением.

Проверку человеческого смысла выполняют по `SEMANTIC-REVIEW.md` и `review-template.csv`; её результаты не заполняются автоматически. `MECHANICAL_RUN_COMPLETE` не означает завершение T5. Отчёт — `REPORT-TEMPLATE.md`, результаты — `<scenario>-NN.json`, manifest/journal — run.json/events.jsonl. All raw JSON/трассы остаются в private; публичный отчёт — только агрегаты/ограничения без исходных приватных фрагментов.
