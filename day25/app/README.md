# Day25 — локальный учебный чат

Самостоятельное приложение на базе runtime Day24. Исходные хеши в `BASELINE.json`; код и приватные результаты Day24 не изменяются и не мигрируют. Авторизация, ledger и private не копируются автоматически.

## Запуск

Из `day25/app`: `python3 -m pip install -r requirements.txt`, затем `python3 web.py --port 8053`. Сервер слушает только `127.0.0.1`. Поиск использует прежний SSH/Structure/Qwen индекс из `search.py`; без нового `private/authorization.json` облачная генерация не разрешена. Секреты передаются через прежний `--env-file`, не через содержимое чата. Каталог данных меняется `--data-dir`; права 0700 для каталога и 0600 для файлов.

Обычный интерфейс создаёт чаты по всему корпусу. Для записи на разрешённом публичном подмножестве: `python3 web.py --port 8054 --public-only`. Этот режим создаёт чаты только scope=public, скрывает private чаты и результаты с приватными материалами в любой части трассы.

## Пользовательский путь

Создай чат, явно задай цель/уточнения/ограничения в «Памяти задачи» и отправь вопрос. Продолжения остаются в том же чате. Под ответом видны источники и цитаты; полный чанк и диагностика раскрываются отдельно. Невалидный ответ не отображается как проверенный. Предложения ассистента автоматически не меняют память.

Память сохраняется с новой версией, очистка удаляет все действующие записи. Конфликт версий требует обновить чат перед сохранением; правка в форме сохраняется при сообщении об ошибке. Архив и память доступны после refresh/restart. Browser localStorage хранит только выбранный chat_id и незавершённый request ID (отдельно для режимов); токен сервера и содержимое чата туда не записываются.

Незавершённый запрос проверяется GET по сохранённым chat_id/ID; повторного POST при refresh нет. Можно проверить исход ещё раз или завершить ожидание. Новый неизвестный платный исход требует отдельной проверки ledger; переключение чатов и чтение архива не вызывают модель.

## Проверки без провайдера

Из корня: `python3 -m unittest discover -s day25/app -q` и `python3 -m unittest discover -s day25/validation -q`.

Для явно обозначенного синтетического браузерного стенда: `python3 preview_fixture.py --port 8053 --data-dir /tmp/day25-ui-check`. Для public-only — отдельный порт 8054 и отдельный каталог с `--public-only`. Стенд использует фиктивные поиск/генератор/ключ/стоимость и запрещает настоящий сетевой вызов и SSH. Он не является доказательством качества модели.

Playwright MCP `browser_run_code_unsafe` может выполнить `browser_checks.js` (8053, создаёт новые синтетические чаты), `browser_pending_checks.js` (8053, refresh во время запроса) и `browser_public_checks.js` (8054, проверяет отсутствие PRIVATE_ONLY_ при заранее подготовленной негативной фикстуре). Для restart сохрани data-dir, останови только этот стенд, запусти его снова и обнови страницу; счётчики test_metrics не должны увеличиться от чтения. В продакшене метрики фикстуры отсутствуют.

## Границы контекста и обработки

Поиск выполняется для каждого нового ID. Зависимый запрос использует один содержательный пользовательский якорь из разрешённой истории с текущей версией памяти и саму память; текст ассистента не используется для поиска. Явные дни/периоды текущего вопроса не наследуют прежние фильтры. Генератор получает свежие документы, действующее состояние и до трёх последних успешных ходов.

Лимиты: история 4000 байт, память 4000 байт в packed JSON, добавление темы поиска 2000 байт, весь поиск 18000 байт, messages 24000 байт. Усечение памяти видно в интерфейсе и диагностике. При переполнении сначала сокращается история, затем selected; отсутствие контекста приводит к локальному отказу.

Сохранённые этапы: `searching → selecting → generating → validating → terminal`. Ledger связан с ID/chat_id/версией памяти. Проверка использует снимок переданных фрагментов; verified означает подлинность цитат, не смысловую оценку. После restart локальные прерывания завершаются interrupted, неопределённая передача/расход — unknown; ID не повторяется автоматически. Unknown/inflight/cost_unknown блокируют новые платные вызовы. При ошибке терминальной записи verified не выдаётся.
