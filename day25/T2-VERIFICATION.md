Файлы: `app/conversation.py`, интеграция в `app/service.py`, `app/test_context.py`, актуализированная `app/README.md`. Runtime Day24, auth/ledger, T1 HTTP-маршруты не изменены.

Локальный macOS/Python 3.14: `cd day25/app && python3 -W error::ResourceWarning -m unittest -v test_chats test_context` — 10 тестов PASS, 0.624с. `git diff --check` — PASS. Тест снимка Day24 — PASS.

Путь тестов T2 проходит настоящий Service, локальный retrieve с синтетическими векторами, authorization по синтетическому identity, резерв ledger, мок generate_fn и настоящую проверку цитат. requests.Session.request запрещён тестом. Ключ фиктивный; SSH и провайдер не вызываются.

- Продолжение «а это?» вызывает новый search_fn с текущим вопросом, последним содержательным пользовательским вопросом разрешённой истории с действующей версией памяти и самой памятью. Текст ассистента исключён из поискового запроса. Два одинаковых вопроса с разными ID выполняют два поиска/генерации; повтор ID и чтение результата ничего не вызывают.
- Мок получает original question, task state с constraints, последние user/assistant реплики, встроенную учебную роль и свежий context_record найденного документа. Проверенная цитата принадлежит фактически переданному чанку.
- Смена цели RAG → MCP/ограничения «Без кода» → «С примером» видна в следующем запросе; очистка памяти действует на следующем ходе. Прежний snapshot/version результата сохраняется. Чужие чаты не входят в контекст.
- Текущие «день 19», 30.09.2026, последние дни и диапазон сохраняются в поиске точно как текущий вопрос, без прежних дня18/29.09.2026. Это консервативное правило избегает смешанных фильтров периода/дней; зависимая тема в этом случае не расширяется автоматически.
- История ограничена тремя последними допустимыми ходами и 4000 байтами, память — 4000 байтами, добавление темы — 2000 байтами, весь поиск — 18000 байтами, messages — 24000 байтами. При переполнении messages сначала сокращается история, затем selected; удаление получает диагностическую причину. Пустой итоговый selected ведёт к прежнему локальному отказу без генерации.
- Ошибочные/непроверенные ходы и public-history с private:note не входят в контекст. Архив с документом вне действующего authorization исключается из генерации и поиска.
- Сохранённая диагностика: original_question, search_query, search_rule, search_performed, ограниченные history/task_state и флаг task_state_truncated, фактические trace.messages/context/selected.

Ограничения: разрешение зависимой реплики — локальная языковая эвристика (русские указательные слова/«а», «подробнее», «продолжи»), не дополнительный модельный вызов. Очень большая память явно усекается в диагностике. Смысловое удержание цели и качество настоящих длинных разговоров не доказаны моками; живые прогоны относятся к T5. UI/расширенная FSM ещё не реализованы (T4/T3).

Исправления после первого gate T2: исходная тема сохраняется через пять последовательных продолжений «а это?»/«подробнее»/«продолжи», даже когда содержательный якорь вышел из последних трёх ходов. В поиск входит один ограниченный пользовательский якорь, не полный архив; `search_anchor_request_id` указывает его происхождение. Новый содержательный вопрос заменяет якорь (день18 → день19), новая версия памяти исключает устаревшие якоря (цель MCP больше не наследует день19). Assistant text не используется. Лимит памяти дополнительно проверяет итоговый `packed(state)` после JSON-экранирования; тест goal из 1000 NUL подтверждает <=4000 байт.
