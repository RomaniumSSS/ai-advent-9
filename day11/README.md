# День 11 — три слоя памяти агента

Агент дня 11 продолжает уже проверенную коробку дня 10, но его папка
самостоятельная: код не импортирует предыдущие дни. Данные лежат в SQLite;
архив разговора не удаляется из-за ограничения короткого контекста.

## Короткая схема

| Слой | Ключ области | Что в нём | Когда не виден |
| --- | --- | --- | --- |
| Краткосрочный | `session` | последние шесть пар вопрос/ответ и явно сохранённые заметки беседы | в другой сессии |
| Рабочий | `user_id + task_id` | цель, сроки, ограничения, незакрытые решения текущей задачи | в другой задаче |
| Долговременный | `user_id` | устойчивые знания, предпочтения и решения, нужные в будущих задачах | у другого пользователя |

Заметки каждого слоя находятся в **своей таблице**: `short_notes`,
`working_notes`, `long_notes`. Архив реплик — в `messages`. При сохранении
пользователь явно указывает слой командой `/save`; агент не угадывает его
скрытым вызовом модели. `reset` очищает разговор и короткие заметки, сохраняя
текущую задачу и долговременные сведения. `/forget` позволяет исправить или
удалить отдельную запись.

Перед каждым запросом агент получает отдельные блоки трёх слоёв и последние
реплики текущего разговора. `/context ВОПРОС` показывает этот состав до
сетевого вызова. Список сохранённых данных виден через `/memory`.

```bash
uv run day11/cli.py --user roman --task landing --session landing-1
uv run day11/web.py --env-file /путь/к/.env   # 127.0.0.1:8041
```

Команды в терминале:

```text
/save short ссылка https://example.test/mockup
/save working срок 18 сентября
/save long предпочтение Отвечать кратко по-русски
/memory
/context Какой срок и как мне ответить?
Какой срок и как мне ответить?
```

Для доказательства границ откройте **новую сессию той же задачи**: рабочая и
долговременная память остаются, короткая — нет. Затем откройте **новую
задачу того же пользователя**: остаётся только долговременная. Для другого
пользователя и она пуста. Сравните ответ на один и тот же вопрос до и после
записи: агент должен назвать сохранённый срок после добавления в рабочий слой
и не назвать его в чужой задаче.

В панели поля «Пользователь / Задача / Разговор» переключают область без
перезапуска сервера. Три кнопки под формой явно направляют запись в нужный слой;
карточки сверху показывают сохранённые записи. Панель слушает только
`127.0.0.1` и предназначена для локальной демонстрации.

Проверки без сети:

```bash
uv run day11/test_memory.py
```

Малый живой прогон для проверки ответов:

```bash
uv run day11/verify_live.py --env-file /путь/к/.env --out day11/results/live-memory.json
```

Готовое [немое видео кода и панели](demo/README.md) проходит один сценарий:
реальные ответы до и после записи → явный выбор слоя → новая беседа той же
задачи → новая задача того же пользователя → другой пользователь. В карточках
и ответах видно, какой слой пережил каждую смену. Запись воспроизводит уже
сохранённый живой прогон на временной базе, поэтому не делает новых API-вызовов.
Данные ключей API остаются в `.env`; значения в примерах и результатах не
публикуются.

Сохранённый [живой прогон](results/live-memory.json): девять вызовов DeepSeek V4
Flash через OpenRouter/OpenInference. До записи срок, город и кодовое слово не
назывались; после явной записи каждый факт влиял на ответ только в своей
области. Рабочая настройка «маркированным списком» также изменила форму ответа.
Все девять контрольных условий выполнены. API сообщил 2677 входных и 2085
выходных токенов, суммарную стоимость $0.000391224. На предыдущей попытке
с потолком 400 выходных токенов один ответ оказался пустым; итоговый прогон
использовал потолок 1000. Это проверка с реальной моделью, не заменяющая
просмотр панели и видео человеком.

Поля `user_id` в локальной панели нужны для демонстрации области памяти; они
не выполняют аутентификацию пользователя. Панель предназначена для локального
запуска на `127.0.0.1`, а не для публикации как многопользовательский сервис.
