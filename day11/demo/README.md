# Видео дня 11

`day11-memory-fast.mp4` — немая запись кода и локальной панели, 40,28 секунды,
1440×1100, H.264, 1,52 МБ, ускорение ×1,25. Аудиодорожки нет. Ответы на экране взяты из завершённого живого прогона
[`../results/live-memory.json`](../results/live-memory.json); во время записи
сеть не использовалась и новых расходов не было.

## Что показано

1. Три отдельные таблицы SQLite: `short_notes`, `working_notes`, `long_notes`.
2. Области видимости: разговор, пользователь + задача, пользователь.
3. Сборка запроса модели из трёх слоёв и последних реплик.
4. **Влияние рабочей памяти на ответ:** один вопрос о сроке подсвечен жёлтым
   вместе с ответом «не знаю» до записи, затем зелёным — с ответом
   «27 октября 2031 года» после записи срока в рабочий слой.
5. Явная запись кнопкой «В задачу».
6. Проверка параметра `формат ответа`: после записи агент отвечает двумя
   пунктами списка — сроком задачи и городом проживания. Это сохранённый ответ
   реальной модели; сервер записи дополнительно сверяет вопрос и memory prompt.
7. Натуральная ошибка границы: попытка открыть существующую сессию `landing-1`
   под другой задачей отклоняется самим `SqliteStore` с просьбой выбрать новое
   имя сессии; поля сразу возвращаются к фактически активной области.
8. Новая сессия той же задачи: короткая запись исчезает, рабочая и
   долговременная остаются.
9. Новая задача того же пользователя: остаётся только долговременная память.
10. Другой пользователь: все три слоя пусты. В истории виден реальный ответ
   модели «не знаю» из контрольного прогона.

`recording-source.json` фиксирует источник ответов и отсутствие сетевых вызовов,
`recording-meta.json` — фактическое содержимое карточек на четырёх областях и
ошибки страницы.

## Повторная запись

```bash
uv run day11/demo/serve_recording.py
# В другом терминале:
/opt/anaconda3/bin/python day11/demo/record.py
```

Нужны Playwright Chromium и `ffmpeg`. Сервер использует временную базу и порт
8042; рабочая `day11/history.db` не затрагивается. Исходная запись без ускорения
и промежуточные файлы остаются локальными.
