# Day29 — живая запись

Готовый файл: [Day29-live.mp4](Day29-live.mp4), 328.48 s, H.264,
1280×1000, 25 fps, без звука, ускорения и монтажа. Это запись браузера с
новыми ответами локальной Ollama, не презентация сохранённых ответов.
Историческая таблица измерений явно обозначена отдельно.

Сценарий: [SCENARIO.md](SCENARIO.md). До записи выполнен тот же dry run:
E02 исходный → E02 кандидат → E01 кандидат → E03 кандидат.
Для каждой попытки программа нажимает кнопку, ждёт реальный request ID и ответ,
сверяет текст и открывает исходные источники. Затем показывает сравнение.

[live-recording.json](../results/live-recording.json). Полный decode, девять
кадров из самого MP4 и соответствие raw receipts проверены:
[video-verification.json](../results/video-verification.json).
SHA-256: `5082b1f0b155b01a3fced5c4dd1d643787f12bd2501855f4d09e3a4420b821c3`.

Запись фиксирует статус на момент съёмки: видео ещё проверяется, финальный
аудит в работе. Текущий статус содержится в RESULT/validation; обновление
доставочных подписей после съёмки не меняет ответы и настройки эксперимента.

Воспроизведение записи из корня worktree при уже работающем приложении
`http://127.0.0.1:8069` и установленном Playwright/Chromium:

```sh
uv run --offline --no-project --with playwright python day29/video/run_demo.py --dry-run --output day29/video/runs/dry-new
uv run --offline --no-project --with playwright python day29/video/run_demo.py --record --output day29/video/runs/record-new
```

Эти команды выполняют реальные новые локальные запросы и требуют доступной
модели; не запускайте их параллельно с измерениями. `--output` должен быть новым
каталогом, старые журналы не перезаписываются. Для MP4 нужны ffmpeg/ffprobe.
Офлайн UI fixtures запускает `video/browser_check.py`; это отдельная mock проверка.
