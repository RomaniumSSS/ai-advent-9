## Проверяемое поведение

1. **Полный поиск.** До inference проверяются immutable identity/count/hash и локальные
   model digests. Все 724 чанка участвуют в семантическом и лексическом ранжировании.
   Упоминание дня не исключает discussion/personal_note без day; assignment boost
   допустим только при явном запросе задания, без вытеснения всех требуемых обсуждений.
   Запросы о позиции участников и смешанные assignment/discussion проверяются отдельно.
   Нет специальных ответов или whitelist тем под smoke. Пустой поиск даёт unknown
   без генерации; отсутствие найденного не объявляется отсутствием во всём архиве.
2. **Диалог.** История приватна и сохраняется после перезапуска. У разговоров разные ID;
   новый/сброшенный разговор не наследует контекст другого. Follow-up использует тему
   предыдущих пользовательских реплик и заново ищет источники; явно новая тема имеет
   приоритет. Неоднозначное продолжение просит уточнение. Старый ответ ассистента
   помогает понять вопрос, но не подтверждает факты корпуса. Незавершённый ход после
   перезапуска отмечается interrupted, автоматически повторно не отправляется.
3. **Источники.** Ответ содержит только допустимые ссылки на фактически переданный
   контекст. UI показывает исходный текст, тип, document/chunk ID, автора и дату из
   оригинальных members/source_sections, когда они доступны. Для составного чанка
   атрибуция привязана к пересечению исходных offsets; неоднозначная атрибуция явно
   неизвестна. Автор/дата не генерируются моделью. Валидные ссылки не равны проверенной
   смысловой поддержке: UI и отчёт различают эти статусы.
4. **Контекст и ошибки.** Системные правила, недоверенные источники и история разделены.
   Инструкции внутри архива не исполняются. Prompt включает не более трёх последних
   пар реплик и до пяти источников; полный сериализованный prompt + schema/template
   reserve + output reserve проверяется до вызова. При нехватке бюджета удаляются
   старые пары истории, затем целые менее релевантные чанки, с причиной в trace;
   текущий вопрос и свежие источники приоритетнее истории; текущий вопрос не обрезается
   молча. Проверяются завершённость ответа, JSON и refs;
   length/timeout/invalid JSON/busy показываются честной ошибкой, без скрытого retry.
5. **Приватность и изоляция.** HTTP bind только 127.0.0.1:8070, проверка Host/Origin,
   ограничение размеров запросов, безопасный текстовый рендеринг источников. Ollama
   только фиксированный loopback, без proxy/redirect/cloud fallback. Общий inference
   lock сохраняет совместимость Day28/29; одна активная генерация, понятный busy.
   История, raw responses, snippets и подробные проверки — только
   `day29/private/full-chat/` (dir 0700, файлы 0600, atomic writes, gitignored).
   Public evidence содержит лишь итог, числа/ID/hash, без вопросов и текстов private.
6. **Готовность.** Существенное поведение проходит bounded TDD, browser/API проверку
   и свежий локальный E2E по новым вопросам, выбранным из реально проверенных источников:
   discussion, personal_note и follow-up. Смешанный запрос и unknown покрываются
   целевыми проверками retrieval/context. Поддержка ответов
   сверяется с оригиналами, а не только с citation validator. Независимые Luna → Sol
   fixes → обязательное Astra; человеческая приёмка отдельно и не выдумывается.

При неверной identity, риске утечки, недоступной модели или конфликте процессов
остановить зависимый runtime, сохранить причину и продолжить безопасные offline-проверки.
Недостающие факты корпуса обозначить; не менять индекс ради прохождения кейса.
