# Полный локальный чат Day29

Свободные вопросы по доступному архиву, продолжения разговора и локальная
история: **http://127.0.0.1:8070**. Условия заданий, переписка и личные заметки
доступны в одном поиске. Исходный benchmark на 8069 имеет отдельный контракт.
Требования: [FULL_CHAT_SPEC](FULL_CHAT_SPEC.md),
[ARCHIVE_QUALITY_SPEC](ARCHIVE_QUALITY_SPEC.md); текущий прогресс —
[ARCHIVE_QUALITY_TASKS](ARCHIVE_QUALITY_TASKS.md).

## Запуск

Из корня worktree `day29-full-chat`, при запущенном локальном Ollama:

```sh
python3 day29/full_chat.py --index-root /Users/ramanpazharytski/Projects/ai-advent-9-worktrees/day28/day28/private/index-release-v1
```

Используется read-only снимок: **724 чанка / 663 документа** — 24 assignment,
694 discussion, 6 personal_note. Исходная Telegram-переписка заканчивается
1 октября 2026 года; новые сообщения автоматически не загружаются.
Переиндексация и загрузка новых весов при запуске не выполняются.

Установленные модели: `qwen3:8b` Q4_K_M и `qwen3-embedding:0.6b`, Ollama
`127.0.0.1:11434`. Закреплённые digest и embedding options проверяются по
[core.py](core.py). Генерация: temperature=0, num_ctx=8192,
num_predict=1024, think=false. Модели, digest и эти настройки не менялись
при переработке качества. Общий lock Day28/29 возвращает busy при занятом inference.

## Поиск и продолжения

При каждом содержательном вопросе заново оцениваются все 724 кандидата
семантическим и лексическим поиском. Упоминание дня не исключает переписку
и заметки без номера дня. Учитываются написания имён, падежные формы,
специфичные термины и аспекты вопроса; полного whitelist тем нет.
Для нескольких примеров предпочитаются разные первичные авторские сообщения.
Перед генерацией остаётся максимум **пять источников**, включая нужные
авторские/дневные/тематические anchors, в пределах бюджета.

Для содержательного продолжения отдельно оцениваются детали текущего вопроса
в явно запрошенном типе источника или ранее процитированном документе.
Нужны минимум два независимых содержательных признака; имена, служебные слова
и общие формы уточнения их не заменяют. При строгом улучшении текущей лексической
релевантности резервируется максимум **один исходный фрагмент внутри фактических пяти**.
Покрытие явно названных авторов, дней и технических терминов сохраняется;
Новый фрагмент и защищённые источники стоят перед менее приоритетными при удалении по бюджету.
Исходная косинусная оценка не повышается: лексическая навигация и её причины записываются
в trace отдельно; допуск ниже порога комбинированной релевантности 0.35 помечается явно.
При отсутствии улучшения выбор остаётся прежним. Неинформативное продолжение
не резервирует новый фрагмент; новая тема обходит этот шаг, смена названного автора сбрасывает
навигацию по прежнему документу. Эта эвристика не проверяет смысл и может пропустить
несколько новых аспектов или предпочесть случайное совпадение содержательных слов.

Каталог имён содержит **98 авторов из всего снимка**, а не только выбранных
источников. Он используется локально для распознавания запроса об участнике;
непопавшие в контекст сообщения не становятся доказательствами и не добавляются
в prompt. Речевые вопросы, явные роли участников и имена помогают отличить
позицию человека от поведения программы. Это ограниченные языковые эвристики:
неоднозначный вопрос или роль подлежащего могут быть распознаны ошибочно.

При вопросе об исходных репликах участников условия, объявления, сводки
и сообщения из одной ссылки остаются фоном, а не доказательством действий людей.
Прямо запрошенные условия и смешанные сравнения сохраняют соответствующие роли.
Личная заметка без подтверждённого автора подписывается «Заметка».
Ограничение роли проверяется и в схеме допустимых IDs, и при разборе ответа.

Короткое продолжение сохраняет тему и ограничения прежних пользовательских
вопросов, затем выполняет свежий поиск. Указатели `dialogue_focus` отмечают
совпадения свежих единиц с ранее процитированными оригиналами; это навигация,
не доказательство из старого ответа. Самостоятельный новый вопрос и
«Новая тема: …» имеют приоритет. Неопределимое короткое продолжение может
потребовать уточнения. Короткое подтверждение вроде «Спасибо, понятно»
получает ответ с **нулём model calls** и сохраняет тему.

## Ответ и его ограничения

За один generation call модель выбирает IDs исходных авторских единиц и
распределяет их по аспектам вопроса. Свободный фактический пересказ не генерируется:
приложение показывает точные цитаты с автором и датой из исходных метаданных.
Авторская часть до 700 символов сохраняется целиком; длинные части разбиваются
по абзацам/предложениям. Границы разных частей, авторов и дат не объединяются.
Короткое уточнение может показываться с соседней репликой и её собственной подписью.

Контракт допускает до **восьми raw selections** и пяти ссылок. Допустимые
повторения одного ID объединяются после проверки каждого item; группы аспектов
сливаются, причины нормализации сохраняются в trace. Неверные типы, поля, IDs,
аспекты и роли завершаются ошибкой. Противоречивый статус выбора приводится
к консервативному состоянию с сохранением цитат. Скрытого повторного вызова,
critic repair или автоматического verifier нет.

**Валидная ссылка не означает смысловую проверку.** Модель всё ещё может
выбрать нерелевантную цитату или пропустить нужный фрагмент. Статус покрытия
отражает её выбор, а не доказанную полноту. Unknown не доказывает отсутствие
сведений во всём архиве. Дословное цитирование сохраняет отрицание, числа и
исходную формулировку, но ответы могут быть длинными и требуют чтения источников;
автоматическая гарантия отсутствия всех галлюцинаций не заявляется.

## Контекст, история и приватность

В prompt входят текущий вопрос и максимум **три предыдущих пользовательских
вопроса текущей темы**; прежние фактические ответы ассистента не передаются.
Полная история сохраняется на машине. Бюджет сначала убирает старые вопросы
из prompt, затем целые менее приоритетные источники; текущий вопрос не обрезается.
Production использует локальный byte-BPE tokenizer установленной Qwen-модели
с Qwen2 pre-tokenizer и её vocabulary/merges из `/api/show`. Проверяются сообщения,
JSON-упаковка и фактическая schema, плюс 512 токенов запаса шаблона и
1024 токена ответа в окне 8192. Наблюдаемый prompt_eval_count также проверяется;
превышение — ошибка. Offline builder без tokenizer использует обозначенную
консервативную UTF-8 byte bound, без произвольных bytes/4 или chars/4.

`day29/private/full-chat/` содержит conversations и receipts с фактическим
payload, источниками, raw response, identity и timings. Каталоги 0700,
файлы 0600, записи атомарные; папка игнорируется Git. Новый разговор создаёт
новый ID; reset очищает текущую историю и меняет epoch. Поздний inference
остаётся в receipt и не возвращается в сброшенный разговор. После перезапуска
незавершённый ход становится interrupted и автоматически не повторяется.

HTTP фиксирован на 127.0.0.1:8070; Host/Origin проверяются. Все provider-запросы
идут через loopback без proxy, redirect или cloud fallback. Вопрос — до 500
символов; HTTP не принимает настройки моделей, пути или файлы. История и
источники выводятся через textContent; архивные инструкции — недоверенные данные.
Панель источника привязана к request ID и показывает текст, тип, document/chunk ID
и исходные части с атрибуцией; непокрытые/неоднозначные области обозначены неизвестными.

## API и проверки

| Метод / маршрут | Payload / результат |
| --- | --- |
| GET `/api/state` | scope, индекс/настройки, active request |
| GET `/api/conversations` | ID, обновление, число ходов |
| POST `/api/conversations` | `{}` → новый разговор |
| GET `/api/conversations/{id}` | сохранённая история |
| POST `/api/ask` | `{"conversation_id":"…","question":"…"}` → 202, request ID |
| POST `/api/reset` | `{"conversation_id":"…"}` → очищенный разговор |
| GET `/api/requests/{request_id}` | состояние и ответ хода |

Raw provider payload/response через HTTP не выдаются; исходники доступны в
локальной панели. Reset убирает старые receipts из API истории, сохраняя их на диске.

**264 offline tests PASS** проверяют код и синтетические границы, а не качество

проверяет desktop/tablet/mobile и сохранение/UI, без Ollama и настоящего корпуса.
**После исправления пять целевых реальных запросов — 5/5 PASS**, независимо
сверены Luna и Astra с исходными текстами. Дополнительный полный набор остановлен
по поручению пользователя после 14 из 33 запросов; полного нового результата
33 нет. Проверки UI нового разговора, ACK без генерации, reload, продолжения и
точных источников проведены на настоящем приложении. Подробные receipts и оценки
хранятся в private. Ответы могут содержать длинные и лишние подлинные цитаты;
offline tests и валидные ссылки не заменяют оценку смысловой полноты.

HTTP явно использует `EvidenceChatEngine`. Отдельный legacy `ChatEngine`
с протоколом `answer/source_refs` сохраняет совместимость прежнего critic
experiment в `quality_eval.py`; HTTP автоматически на него не переключается.
Исходные public core, профили и результаты benchmark остаются отдельными.
