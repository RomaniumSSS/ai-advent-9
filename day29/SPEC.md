## Результат и границы

Самостоятельный `day29/`: справочник по заданиям с локальным RAG, исходный и выбранный
профили, воспроизводимое сравнение и небольшой локальный экран для живого видео.
Улучшаем полноту сравнения Day19/20 (E02 из Day28), измеряем цену в скорости/памяти.
Генератор — установленная `qwen3:8b` Q4_K_M, `think=false`; embedding и неизменный
индекс Day25 те же, что в Day28. Базовый профиль **temperature=0, num_ctx=8192,
num_predict=1024**, исходный SYSTEM и протокол `source_refs` побайтно сохраняются.
Day01–28 не редактируются; runtime-импортов из них нет. Публичная оценка использует
только assignment-документы. Детали протокола, путей и лимитов — [PLAN](PLAN.md).

## Приёмка

1. **Повторяемость.** Read-only индекс с прежними generation/SHA и точный digest
   эмбеддера проверяются до запроса. E01/E02/E03, рубрика и выбранные контексты с
   порядком/источниками фиксируются до подбора настроек; каждый профиль получает
   одинаковые вопрос и контекст. Изменение prompt явно записывается. Контекст не
   сокращается для кандидата: непоместившийся профиль отклоняется до inference.
2. **Настройки.** Есть исходный профиль, небольшие однофакторные пробы temperature,
   num_predict, num_ctx, prompt и один составной кандидат; сохранены фактические
   payload, model/digest/quantization, prompt/context hashes и отклонённые варианты.
   Квантование: проверить доступность второго квантования **той же Qwen3 8B**;
   при доступности и пригодности памяти выполнить ограниченную парную пробу,
   иначе записать конкретную причину пропуска. Другая модель не считается квантованием.
3. **Честная оценка.** Свежий baseline сравнивается с замороженным кандидатом:
   E01/E02/E03 × 2 warm повтора на профиль, отдельно по одному cold E02 на профиль.
   Warm/cold и прогрев определены заранее; ошибочный режим помечается несопоставимым.
   Валидность JSON/ссылок проверяет код, поддержку фактов/полноту — отдельная рубрика
   с доказательствами из ответов. Отсутствующий бюджет E03 остаётся unknown.
4. **Метрики.** Сохраняются отдельные времена retrieval/embedding/generation/total,
   Ollama load/prompt/eval counts и durations, tok/s, наблюдаемый process RSS,
   swap до/после и размещение модели. Неизмеренное — `null` с причиной. `/api/ps size`
   не выдаётся за пиковую RAM; RSS не выдаётся за полную Apple unified/Metal memory.
   Cold и warm, подготовка RAG и повтор генерации показываются раздельно.
5. **Выбор по результату.** Кандидат не вносит ошибок ссылок, выдуманных фактов,
   ложного знания E03 или потерь ранее покрытых фактов. Оптимизация доказана при
   таком сохранении качества и хотя бы одном улучшении: полное E02 во обоих
   warm повторах при неполном свежем baseline; либо ≥10% улучшение общего warm
   медианного времени генерации или сопоставимого наблюдаемого RSS. Цена улучшения
   по остальным метрикам приводится рядом. Если условия не выполнены — итог
   «эксперимент выполнен, оптимизация не доказана», baseline сохранён, задача
   оптимизированной модели остаётся незавершённой; критерий задним числом не меняется.
6. **Поставка.** TDD RED→GREEN для существенного поведения; независимые ревью Luna,
   затем исправления Sol и обязательная Astra; рабочие код/README, исходные замеры,
   RESULT/RELEASE_NOTES и проверенное живое видео по [сценарию](video/SCENARIO.md).
   Код, видео, публикация и пользовательская приёмка имеют разные статусы.

Runtime — только loopback Ollama/локальный индекс; без платных/облачных вызовов.
Подготовительная загрузка официальных весов допускает сеть и журналируется отдельно. На Mac M2
16 ГБ inference и запись последовательны под общим lock, с учётом lock Day28.
Повторная индексация, смена эмбеддера, тонкая настройка весов, новый агентный framework
и бесконечный sweep не входят. Commit/push/merge, выгрузка видео и таблица сдачи
не подразумеваются этим пакетом. Спека, [план](PLAN.md), [задачи](TASKS.md) и сценарий
образуют один пакет; формальная state machine не нужна.
