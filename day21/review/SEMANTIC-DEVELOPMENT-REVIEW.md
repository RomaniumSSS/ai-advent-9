## Следующий ограниченный шаг

1. Подготовить новую версию development-входа с метаданными вложений,
   сохранив те же ID и тексты. Исходные результаты оставить неизменными.
2. Уточнить рубрику для непрочитанного нетекстового контекста и неоднозначных
   коротких реплик. Добавить проверки контекстных связей, которые приложение
   может установить по входным reply, без догадок о смысле вложений.
3. Перепроверить эти четыре рабочих кейса до запуска holdout. Для локальной
   модели отдельно остаётся дефект группировки C01: обязательные ID не
   гарантируют объединение вопроса с ответом.

Отбор и группировку лучше проверять отдельными показателями: покрытие ID,
обоснованность include/exclude/review и сохранность нужных контекстных связей.
Автоматически объединять всю reply-ветку нельзя: она может содержать несколько
самостоятельных вопросов. Текущих результатов недостаточно для массового отбора.

Подробный разбор каждого кейса и хеши исходных файлов сохранены локально:
`day21/private/semantic-expanded-v2-development-review.json` (0600).
Решения к принятому корпусу не применялись; объём и нарезка ещё не проверены.
