неизвестного типа — true/unknown. Неизвестность самого наличия — null/unknown;
отсутствующий HTML record приводит к ошибке подготовки, а не к ложному false.

`prepare_development_context.py` импортирует существующий TelegramParser Sol

href, пути вложений и соседние тексты не выводятся. Regex-парсер HTML не добавлен.

Проверены SHA-256 пяти исходных HTML по уже имеющемуся манифесту source_files
и совпадение source.line каждого разрешённого ID. Новые артефакты фиксируют
хеш v2-входа, рубрики v3, parser, preparer и исходных файлов; каждое сообщение
имеет attachment_provenance с source SHA, строкой и классами медиа.

## Узкое изменение рубрики

`semantic-rubric-v3.txt` содержит v2 побайтным префиксом и добавочный раздел:

- непрочитанное вложение не исключается только из-за пустого text;
  при неизвестной полезности требуется review/incomplete_context;
- include-ответ на непрочитанного медиа-родителя сохраняет parent ID в context_ids
  и incomplete_context в решении ответа; физически переданный родитель
  не добавляется в missing_context_ids;
- exclude-реплика может оставаться контекстной ссылкой без смены статуса;
- неоднозначная короткая standalone-реплика требует review/incomplete_context
  при недостатке контекста; явные благодарности/постороннее остаются exclude.

Остальная рубрика, модель и параметры не изменены. Это предложения для отбора,
не принятие документов корпуса и не объявление всех фото полезными.

Подготовка повторно завершилась с тем же входным хешем и агрегатами.
Целевой тест проверяет все 39 исходных ID/тексты/роли/поля, состав 4 кейсов,

Существующие тесты валидатора/checkpoint также проходят.

В `pilot_validation.py` добавлена отдельная `diagnose_context(case, messages,
output)`. API validate и его прежнее поведение не изменены. Guard проверяет
только include-ответ на переданного непрочитанного медиа-родителя: требует
context_ids и incomplete_context. Статус родителя может быть review/exclude;
слияния групп guard не требует. Неверная структура вывода обозначается отдельной
ошибкой диагностики. Синтетические проверки этих условий прошли.

На прежнем разрешённом cloud-ответе E34 guard обнаружил ровно два известных
дефекта: ID4170 без incomplete_context и без контекстной ссылки на ID4169.

## Ограничения и точка остановки

Metadata проверяют наличие и тип вложения по классу HTML, не его содержание,
полезность или истинность ответа. Новая рубрика ещё не проверена реальной моделью.
Не читались holdout и содержимое вложений; сеть/VPS/платные API не использовались.
Родительский агент может теперь отдельно оценить четыре recheck-кейса с v3.
