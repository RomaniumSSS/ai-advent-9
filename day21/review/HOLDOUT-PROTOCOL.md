# Контрольная проверка смыслового отбора

Правила зафиксированы 01.10.2026 после development-разбора и до просмотра
текстов контрольных кейсов родительским агентом.

## Что проверяем

20 ранее отложенных кейсов / 51 уникальное сообщение из исходной выборки40.
Состав не меняем. Используем рубрикуv3 и одинаковые метаданные непрочитанных
вложений. Не открываем фото, видео, ссылки и соседние сообщения ради улучшения
ответов на этой проверке. Недостаточность входа — наблюдаемый результат.

Облачный оценщик: отдельный свежий агент gpt-6-sol/high, без результатов
development и ожиданий проверяющего. Локальный: qwen3:8b, think=false,
temperature0, ctx8192, predict2048, JSON Schema с обязательными ID.
Параметры, digest, хеши входа/рубрики и измерения сохраняются в результатах.
Один локальный запрос на кейс; невалидные ответы сохраняются без скрытых повторов.
Облачный агент может проверить структуру инструментом; исправления учитывать
в отчёте. Это сравнение двух процессов работы, а не чистый benchmark моделей.

## Как оценим

1. Полнота ID, допустимость структуры, отсутствие выдуманных ID и потерянных
   записей. Невалидные ответы не применяются к корпусу.
2. Обоснованность include/exclude/review по рубрике. Для каждого замечания
   записать кейс, причину и неопределённость; не считать одну модель эталоном.
3. Сохранение вопроса с ответами и ссылок на необходимый контекст; отсутствие
   необоснованного объединения самостоятельных вопросов.
4. Явные ограничения: непрочитанное вложение, недостающий родитель,
   непроверенное утверждение. Формальный guard проверяет лишь часть этих случаев.
5. Время, ошибки и usage только из реально сохранённых результатов.

Родитель оценивает смысл после фиксации ответов. Это агентный аудит,
не человеческая эталонная разметка. Согласие моделей не является точностью.
Если обнаружится содержательная потеря или неподтверждённое уверенное исключение,
зафиксировать ограничение подхода; не настраивать правила и не объявлять повтор
на тех же кейсах независимой проверкой. Массовое применение по одному лишь
структурному PASS не разрешается.

## Границы

14 слишком больших веток исключены исходным sampler; эта проверка их не покрывает.
Зависимость сообщений по смыслу может существовать без reply. Истинность
технических утверждений не проверяется в этом этапе. Частота review показывает
объём неразрешённых случаев, но сама по себе не доказывает качество отбора.

Корпус не меняется. Разрешение облачной обработки ограничено тестовой выборкой.
Окончательный отбор, минимум30страниц, нарезка, эмбеддинги и индексы — следующие
отдельные результаты проекта.

## Расширение по просьбе пользователя

До смыслового просмотра holdout пользователь разрешил добавить через OpenRouter
`deepseek/deepseek-v4.1-flash` и `z-ai/glm-5.3-flash`: те же20кейсов,
общий предел расходов **$1** на обе модели. Это отдельное разрешение на тестовые
платные вызовы и передачу этой подборки; весь экспорт не входит в разрешение.

Провайдер закреплён: DeepInfra, endpoint `deepinfra/fp8` для DeepSeek,
`deepinfra/fp4` для GLM. Подмена провайдера запрещена. Эти варианты квантования
отличаются, что входит в ограничения сравнения. Зафиксированы JSON Schema,
temperature0 и max_tokens2048. Для DeepSeek запрос reasoning.enabled=false;
для GLM reasoning.effort=low, поскольку актуальный каталог OpenRouter указывает
reasoning.mandatory=true. Это выяснено до платных вызовов; отключение GLM
не поддерживается. Его reasoning может расходовать часть того же лимита выхода.
Фактический usage и возврат провайдера сохраняются; игнорирование параметра
не считать подтверждением его применения. Ошибки поддержки фиксировать.

Общий журнал расходов резервирует верхнюю оценку перед запросом. Если стоимость
не вернулась или запрос оборвался, резерв остаётся учтённым; такой запрос
автоматически не повторяется. Тариф дополнительно ограничивается через
provider.max_price. Отдельный dry-run и офлайн-проверки выполняются до запуска.
Цены и поддержка параметров сохранены в private/semantic-openrouter-provider-snapshot.json.

Основание параметров: [структурированный вывод](https://openrouter.ai/docs/guides/features/structured-outputs),
[закрепление провайдера и предел цены](https://openrouter.ai/docs/guides/routing/provider-selection).

После двух429 у GLM/DeepInfra пользователь явно разрешил **отдельный прогон
GLM через NextBit в том же общем бюджете$1**. Закрепляется `nextbit/fp8`,
остальные параметры,20кейсов и рубрика сохраняются. Старый частичный прогон
DeepInfra не заменяется. Новый журнал учитывает подтверждённую стоимость
и неизвестные резервы старого прогона как исходную занятую часть бюджета;
хеш старого журнала проверяется перед вызовами. Оба журнала используют общий
lock. Новые ответы сохраняются отдельно в semantic-holdout-glm-nextbit.json.
Это явная смена конфигурации, не автоматический fallback.
