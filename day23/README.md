# Day23: наблюдаемый отбор после поиска

Самостоятельный код по SDD v2. [Результаты](RESULT.md), [сверка требований](VERIFICATION.md),
[практическое видео](video/Day23-practical.mp4). Проведены100проверок поиска и20парответов.
Офлайн-тесты и реальные прогоны описаны отдельно.

`retrieval.py` предоставляет `retrieve(index, original_question, query_vector, config)`.
Индекс — список чанков или `{'chunks': [...]}`. Вектор должен соответствовать
`query_input(original_question)` либо `query_input(rewrite(question)['after'])`, если
включён rewrite. `Config` и словарь с его полями принимаются одинаково.
`MODES` содержит A/B/C/D; E задаётся отдельной конфигурацией. Для C пороги 0,
0.35, 0.5 задаются отдельными запусками. Переключатели rewrite/mixed/metadata
независимы. Кандидаты сохраняют cosine, lexical coverage, mixed score, исходную
позицию и отдельную причину точного добавления; selected/removed показывают
отбор, порог, K и ограничения байтов. В LLM идут только исходный вопрос,
идентификаторы и тексты выбранных чанков через неизменный промпт Day22.

Эвристика метаданных требует явного обозначения дня и слов об условии,
требованиях, сдаче, реализации, результате или сравнении. При отсутствии
такого намерения метаданные не добавляются; решение видно в metadata_rule.
Эта эвристика допускает языковые неоднозначности; реальные спорные кейсы
проверяются в отчёте. Произвольные числа днями не считаются.

## Подготовка поиска

На машине с замороженным индексом и локальным Ollama:

```sh
python prepare_remote.py --root /path/to/index-release-v1 --questions queries.json --output /private/prepared.json
```

Вход строго `{"cases": [{"id": "Q1", "question": "..."}]}`: любые дополнительные
поля кейса отвергаются, эталоны не принимаются. `--questions -` читает stdin.
`--configs configs.json` принимает mapping имён режимов к полям Config.
Генерация Structure и digest эмбеддера проверяются до embedding. Original и
rewrite сохраняются в query_vectors; батч до8, повторяющиеся входы объединяются.
Выход содержит chunks, что позволяет локально сравнивать конфигурации без
повторной эмбеддизации. Это приватный файл 0600, каталог0700.
SSH, доставка файлов и скачивание выхода выполняются отдельно оператором.

## Ответы и общий бюджет

```sh
python evaluate.py --prepared /private/jobs.json --output-dir /private/day23-budget --env-file /secure/.env --budget 1 --limit 2
```

Все прогоны, видео и повторы используют **один output-dir**. Jobs задаются
cases[].id, messages[mode] и верхним modes; стоимость старого Day22 baseline
не переписывается. ID и mode идентифицируют запрос, SHA256 payload запрещает
изменять оплаченный job. Для видео использовать новые ID. Успешные ответы
не отправляются повторно. Новые jobs можно добавлять к тому же журналу.

Перед HTTP пишется резерв; каждый повтор получает новый резерв. Неизвестные
расходы удерживают резерв. Запросы параллельных процессов блокируются flock.
Цены проверяются свежим endpoint-запросом; лимиты $0.14/$0.42 за миллион
prompt/completion. Транспорт отключает env proxies и redirects; провайдер
только DeepInfra/fp8, модель DeepSeek V4.1 Flash, temperature0/max1024/reasoningfalse.
Сырые HTTP status/body сохраняются отдельно для каждой попытки с правами0600.

Timeout/connection failure/429/5xx повторяются с backoff максимум дважды и
только при остатке бюджета. Прочие HTTP, неправильные identity и malformed
ответы останавливают выполнение. При исчерпании повторов или сбое процесса
оператор обязан проверить журнал: inflight/unknown/fatal без recovery блокируют
продолжение. Для явно принятого решения сохранить в записи `recovery: skip`
или `retry`, непустой `recovery_reason` и сохранённое `charged: actual_cost` (если известна), иначе `charged: reserve`; исходные записи
не удалять. Fatal identity/auth требуют сначала устранить причину. Ответ без
usage.cost сохранён как completed/cost_unknown с резервом и остановкой;
продолжение пропускает этот уже полученный ответ.

## Эксперимент на 100 вопросах

Набор размечен до запуска: 25 вопросов по одному условию, 15 сравнений,
30 обсуждений, 15 понятий, 5 с отвлекающими числами, 10 без предписанного ответа.
40 вопросов используются для настройки; 60 отложены до фиксации E. Одна
ветка/условие и его перефразировки не пересекают границу частей.

Эталон включает исходные сообщения и точные диапазоны текста. Оценщик
`score_retrieval.py` проверяет покрытие этих диапазонов найденными чанками;
присутствие одного document_id само по себе недостаточно. Он получает эталон
отдельно от поиска. Отсутствие предписания в условии размечено по полному тексту,
а не по неудачному поисковому запросу. Частичный контекст допустим.

Private-файлы исключены из Git: `benchmark.json`, `benchmark-manifest.json`,
результаты поиска и сырые ответы. Разметка проверена двумя агентами и сверена
с первоисточниками; это не человеческая приёмка и не оценка всего архива.

Подготовка через уже настроенный SSH выполняет Python в памяти на VPS,
читает индекс и вызывает локальный Ollama. Установка/деплой не нужны:

```sh
python3 day23/prepare_ssh.py --questions day23/private/development-queries.json --output-dir day23/private/dev-preparation
python3 day23/score_retrieval.py --prepared day23/private/dev-preparation/prepared.json --benchmark day23/private/benchmark.json --output day23/private/dev-results.json
```

Вход `prepare_ssh.py` строго query-only: массив `{"id": "...", "question": "..."}`.
Каждые восемь вопросов сохраняются отдельно. Для изменённого кода подготовки
нужно использовать новый output-dir; несовпадение хеша кода блокирует повтор.
При неизменном коде повтор использует сохранённые батчи.
Ответы DeepSeek запускаются отдельно через `evaluate.py`, не этими командами.

Финальные A/E параметры сохранены также в публичном `configs.json`.
Приватный подробный результат текущего запуска: `private/comparison.html`.
