**Finding — WARNING — `day30/server.py:83-85`, `day30/server.py:149-150`.**
TLS handshake выполняется в handler worker с socket timeout после `do_handshake_on_connect=False`; это исправляет блокировку accept loop stalled TCP. После handshake `BaseHTTPRequestHandler` читает request line, заголовки и body с тем же idle socket timeout 15 секунд, но без общего deadline. Клиент может передавать фрагмент каждые <15 секунд и удерживать handler бесконечно. `ThreadingHTTPServer` создаёт новый неограниченный thread для каждого принятого соединения, а проверка auth выполняется только после разбора заголовков. Несколько таких клиентов способны исчерпать threads/память до аутентификации. Ограничить число активных connection workers и/или задать абсолютный deadline на чтение заголовков/body; при исчерпании лимита сразу закрывать соединение. Имеющийся TLS regression проверяет один TCP-клиент, который ничего не отправляет, и успешный второй TLS request; медленно передаваемые HTTP headers не проверяются.
