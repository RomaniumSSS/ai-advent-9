# Личный наставник — план реализации v1


**Состояние 04.10.2026:** реализация и полировка Q1–Q5 завершены. Самостоятельный снимок опубликован в `day24/app` (коммит `226d5a5`); после него локально убран публичный пункт из обычного интерфейса. Пользователь подтвердил, что новая демонстрация соответствует желаемой сдаче; факт отправки задания не подтверждён. Известные ограничения качества сохранены в [результатах](../../../day24/RESULT.md).

**Разрешения:** реализация, адресные облачные проверки и публикация согласованы последовательно. Действующий прототип использует DeepSeek/OpenRouter/DeepInfra, замороженный корпус, общий лимит $0.10, retries=0; это не разрешение на новые эксперименты.

**База:** Day24, commit `be94bf73db06bdbc1ed371da031ba40e1f5d73ea`. Итог — самостоятельно используемая локальная страница, не новая серия экспериментов с поиском.

## Технические решения

- Отдельный каталог `mentor/` в текущем репозитории: Python-сервер на `127.0.0.1`, обычные HTML/CSS/JS, без сборки фронтенда. Сервер стандартной библиотеки; существующая библиотека requests для генерации. Day21–23 не редактировать и не импортировать во время работы; самостоятельный снимок Day24 разрешён отдельным запросом пользователя: необходимые небольшие модули скопировать с указанием исходного коммита.
- Mac обслуживает интерфейс и хранит результаты; SSH читает существующий Structure-индекс на VPS и вызывает его локальный эмбеддер. Сохранить проверку идентичности индекса/эмбеддера, таймауты и чтение без изменения индекса. Не создавать публичный API на VPS. В ответ SSH возвращать трассу кандидатов и нужные тексты, без всех векторов корпуса.
- Приватные результаты, снимки чанков, обратная связь и разрешение — в игнорируемом `mentor/private/`. Атомарные JSON-файлы и существующий механизм журнала расходов достаточны; отдельная БД, очередь и система оркестрации не нужны. История — журнал, не память модели.

## P1. Единый путь вопроса / R1–R5, R8

Адаптировать `day24/prepare_ssh.py`, `prepare_remote.py`, `retrieval.py`, `common.py`, `answers.py` в `mentor/`. Сервер принимает вопрос и область поиска; запускает поиск, формирует контекст, проверяет разрешение генерации, получает и валидирует ответ **до** его выдачи как ответа с проверенными цитатами. Настройки остаются K20→5, mixed 0.8/0.2, порог 0.35, rewrite=false.

Область поиска: весь локальный корпус либо явно обозначенное публичное подмножество. Последнее задаётся проверенным списком документов, не считается публичным только по метке `assignment`; фильтр применяется до поиска кандидатов. Это обычная настройка приложения и тестов, не обход для видео. Разрешение облака проверяется отдельно по фактически отправляемым вопросу и чанкам.

Метаданные источников брать из снимка переданных чанков, ссылки модели проверять по нему. Различать локальный отказ, заявление модели о нехватке фактов, ошибку формата/цитат, технический сбой и отсутствие разрешения. Заявление модели не доказывает отсутствие фактов; смысл по умолчанию не проверен. Если отказ модели не распознан однозначно, результат остаётся непроверенным. Генератор не получает инструментов или полномочий из текста корпуса.

**Проверка:** локальные примеры полного/пустого контекста, настоящей и выдуманной цитаты, частично валидного JSON и отказа модели; совпадение отбора с Day24 на одинаковых входах. Реальный поиск на VPS проверяется отдельно от подставной генерации.

## P2. Сохранение и платный вызов / R1, R4–R8

Адаптировать `day24/evaluate.py`: один общий журнал бюджета, резерв до HTTP, фактическая стоимость либо явная неизвестность; модель и провайдер фиксируются разрешением, без подмены. По умолчанию облако выключено, повторов нет. Разрешение хранит область вопроса/данных, модель/провайдер, общий лимит и условия повторов. Старое разрешение Day24 не импортировать.

Каждая отправка получает ID; сервер сохраняет его до платного вызова, повтор с тем же ID возвращает состояние, а не вызывает модель вновь. В v1 одновременно выполняется один запрос; блокировка действует и между вкладками/процессами. Закрытие вкладки не повторяет вызов. После перезапуска незавершённая операция имеет явный статус; неизвестный платный исход требует отдельного решения, расход не обнуляется.

Запись результата содержит вопрос, область, версию кода/конфигурации/индекса, найденные/переданные/процитированные чанки, исходный ответ, валидацию, время этапов и расход. Снимки позволяют открыть прежний источник после изменения индекса. Обратная связь привязана к ID. Если запись не удалась, полученный ответ показывается как несохранённый; сбой резерва до HTTP блокирует вызов. Старые 10 результатов импортируются только как исторические с исходной оценкой Q05–Q07; неизвестные старые времена не выдумываются.

**Проверка:** двойная отправка, две вкладки, бюджет/разрешение, неизвестный исход, сбой записи, обновление и перезапуск; просмотр истории и запись обратной связи дают ноль вызовов генератора.

## P3. Обычный интерфейс / R1–R8

Сделать поле самостоятельного вопроса, видимую область поиска, кнопку отправки, этап выполнения, карточку результата, сразу раскрытые списки источников и цитат, открываемые полные чанки, диагностику, историю и обратную связь. Показывать «цитаты проверены; смысл не проверен», а не гарантию правильности. Невалидный исходный ответ — только в диагностике; сохранённый результат явно подписан. При отсутствии облачного разрешения поиск остаётся доступен.

Браузер обращается только к локальному серверу: ключи остаются на сервере, тексты выводятся безопасно без исполнения HTML; проверять Host/Origin и токен локальной страницы для изменяющих запросов. Читать файлы можно только через ID результата/чанка, не произвольный путь. Реализовать ограниченные HTTP-обработчики, а не файловый сервер каталога private.

**Проверка:** браузерный сценарий ввода двух разных вопросов, открытия источника, диагностики и обратной связи; ошибки видимы, повторный клик заблокирован, приватные файлы напрямую недоступны.

## P4. Проверка и передача / A1–A5

Офлайн: ошибки A2, сохранение A3, импорт A4 и браузерные проверки с обозначенными подставными ответами. Затем реальный поиск и, после отдельного согласования данных/бюджета, небольшой живой прогон A1: вопрос по корпусу, новый вопрос пользователя, посторонний вопрос. Проверить смысл содержательного примера вручную и явно записать результат; ошибки не скрывать, качество свободных вопросов заранее не обещать.

Добавить короткую инструкцию запуска и отчёт с разделением офлайн / VPS / облако / пользовательская приёмка. Пользователь проходит обычный путь сам (A5); записать то же приложение на разрешённых публичных данных. Старые 10 кейсов не запускать платно заново без причины. Коммит, push и публикация — только по отдельному указанию.

**Границы остановки (применялись при реализации):** документы сначала согласуются; без облачного разрешения завершаются локальные работы, живые ответы остаются NOT PROVEN. Ошибка обязательной проверки чинится в её этапе; если для исправления нужно менять требования или алгоритм поиска, согласовать изменение. Завершение — A1–A5 с доказательствами, а не наличие интерфейса или ролика.

## Addendum Q1–Q5 / полировка по живой истории

По новому разрешению пользователя `mentor/` развивает исходный Day24-отбор: exact assignment metadata обходит только threshold, сохраняя scope, topK и размеры контекста. `temporal.py` интерпретирует календарные даты/архивный год и последние 7 дней от конца архива, связывает исходные offsets/source_sections/member_ids с автором, датой и ID сообщения и ограничивает выдачу до topK. В генератор передаются только соответствующие части с метаданными; snapshot/цитата остаются привязаны к исходному chunk. Неоднозначность периода объясняется без снятия ограничения.

`answers.py` допускает единственную внешнюю JSON-fence, сохраняя raw/normalization; SYSTEM требует раскрыть аспекты, различать позиции и не объявлять мнение консенсусом. MAX_OUTPUT_TOKENS=2048 и резерв используют один предел. Полученный неполный ответ с известным usage.cost — unverified, сетевой неизвестный исход/стоимость продолжают блокировать вызовы; проверка ledger предшествует запросу прайса.

Проверки: синтетические Q1–Q5 с запретом внешних HTTP; read-only VPS regression всех 24 условий без платной генерации; адресные старые случаи через обычный HTTP и единый действующий cap $0.10/retries0. Сохранённые случаи — регрессии, не holdout. Исходные ответы не переписываются, known-outcome recovery имеет отдельное доказательство; новые rows связывают old/new ID и code hash. Astra проверяет смысл и код независимо. Известные модельные ошибки и обычный threshold не скрываются; изменение модели/индекса не входит.
