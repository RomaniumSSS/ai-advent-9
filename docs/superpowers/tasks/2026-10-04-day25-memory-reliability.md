# Day25 — задачи повышения надёжности памяти

Основа: [SPEC](../specs/2026-10-04-day25-memory-reliability.md) и [план](../plans/2026-10-04-day25-memory-reliability.md). Все задачи открыты. После каждой задачи исполнитель передаёт сверщику diff, адресные проверки и ссылки на требования; сверщик фиксирует PASS/FAIL/NOT PROVEN. Исторический T5 и A1 остаются открытыми до нового живого доказательства.

- [ ] **N0 → P0. Локализовать причины.** Составить компактную матрицу известных смысловых FAIL из 2×15 по этапам «режим → запрос → выдача → чанки → ответ». Не публиковать private raw. **Gate:** каждый вывод подкреплён трассой; неизвестная причина так и обозначена. SPEC M1–M3.
- [ ] **N1 → P1, после N0. Контекст для поиска.** Реализовать единый выбор режима вопроса, состав используемых полей task state и диагностику; убрать конфликтующие старые ветви. Сохранить новый поиск на каждом ходе, приоритет явных фильтров и изоляцию чатов. **Gate:** известные сбои и новые варианты продолжений/новых тем проходят адресные и интеграционные офлайн-проверки; по трассе видны запрос и фактически переданные чанки. SPEC M1–M2, M4; B1.
- [ ] **N2 → P2, после N1. Пользовательские факты в ответе.** Отделить явное состояние и реплики пользователя от предложений ассистента; предотвратить успешное приписывание неподтверждённого выбора. **Gate:** негативные случаи не проходят как факт; подтверждённый выбор сохраняется; источники корпуса, отказ при нехватке фактов и public-only не ослаблены. SPEC M2–M4; B2.
- [ ] **N3 → P3, после N2. Независимая офлайн-проверка.** Выполнить regression и отдельный holdout с другими формулировками, проверить полную цепочку, restart/другой чат, механические инварианты и замороженные источники. **Gate:** независимый отчёт разделяет структуру, смысл, mock и реальные вызовы; найденные FAIL возвращаются в N1/N2. SPEC B1–B2.
- [ ] **N4 → P3, после PASS N3 и отдельного решения о платном прогоне.** Выполнить два новых сценария по 10–15 сообщений через UI, зафиксировать версию, лимит и ledger, оценить поздние ответы и источники независимо. **Gate:** B3/B4 и исходный A1 получили честный PASS/FAIL/NOT PROVEN; любой обязательный FAIL оставляет T5 открытой. Обновить результат и сдаваемые материалы только по фактическим данным. SPEC B3–B4.

Ни одна задача не даёт заранее гарантии A1 PASS. Коммит и push выполняются только по отдельной актуальной авторизации.
