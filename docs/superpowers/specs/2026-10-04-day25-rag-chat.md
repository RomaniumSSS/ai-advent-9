# Day25 — мини-чат с RAG и памятью задачи: SPEC

Статус: требования согласованы для планирования 04.10.2026. Основание — исходное условие Day25, присланное пользователем, и последующее обсуждение объёма. [План](../plans/2026-10-04-day25-rag-chat.md) и [задачи](../tasks/2026-10-04-day25-rag-chat.md) фиксируют исполнение и проверку.

## Цель и исходное состояние

Пользователь ведёт продолжительный разговор с учебным ассистентом по существующему корпусу. На каждом ходе приложение заново ищет контекст через RAG, отвечает с проверяемыми источниками и сохраняет цель текущего разговора.

Текущий `day24/app` уже предоставляет локальный веб-интерфейс, поиск, генерацию, проверку цитат и журнал отдельных результатов. Журнал результатов не является памятью диалога: предыдущие реплики не используются при следующем вопросе. Существующий индекс и ограничения доступа к нему сохраняются.

## Требования

| ID | Наблюдаемое поведение |
| --- | --- |
| R1. Чаты и архив | Пользователь создаёт и продолжает чат. Реплики и результаты сохраняются после обновления страницы и перезапуска. Каждый запрос и результат принадлежат ровно одному чату; данные разных чатов не смешиваются. |
| R2. Контекст продолжения | Новый вопрос получает последние реплики своего чата и действующее состояние задачи. Короткое продолжение разрешается с учётом этого контекста. Полный архив хранится, но не передаётся модели без ограничения. |
| R3. Поиск на каждом ходе | Каждый новый вопрос запускает поиск по существующему индексу. Для зависимого вопроса поисковый запрос учитывает разговор, но прежний ответ ассистента не заменяет найденный документ. Исходный вопрос, поисковый запрос и отбор чанков доступны в диагностике. |
| R4. Ответ с источниками | Содержательный ответ показывает источники и цитаты, связанные только с фрагментами, фактически переданными генератору. Приложение проверяет эту связь до показа ответа как проверенного. При недостаточном контексте ассистент сообщает «не знаю» и предлагает уточнение; отсутствие источников у отказа видно явно. Проверка подлинности цитаты сама по себе не доказывает правильность смысла. |
| R5. Память задачи | Отдельно от реплик для каждого чата хранятся цель, уточнения и действующие ограничения. Пользователь может просмотреть, изменить и удалить записи. Изменения сохраняются после перезапуска. Предложение ассистента не становится пользовательским решением автоматически. В первой версии записи обновляются явно пользователем, без отдельного платного извлечения фактов на каждом ходе. |
| R6. Постоянные инструкции | Ассистент выступает учебным помощником по материалам курса: отвечает ясно, без лишнего оформления, объясняет термины при необходимости и не выдаёт сведения вне найденных чанков за сведения корпуса. Эти правила задаются приложением; отдельного пользовательского профиля в Day25 нет. |
| R7. Состояния обработки | У запроса различимы поиск, отбор, генерация, проверка и конечный исход. Прерванный или непроверенный результат не показывается как успешный. Неизвестный исход платного вызова не приводит к автоматическому повтору. Состояние привязано к ID запроса и сохраняется для восстановления и диагностики. |
| R8. Инварианты и границы | Код обеспечивает изоляцию чатов, обязательный новый поиск, проверку источников и привязку результата к запросу. Область корпуса, приватность материалов и существующий учёт расходов Day24 не ослабляются. Секреты и приватные тексты не публикуются. |

## Ожидаемый пользовательский результат

1. Пользователь открывает локальный веб-чат, задаёт вопрос и видит ответ с открываемыми источниками и цитатами.
2. В следующих репликах он может ссылаться на предыдущий разговор; ассистент сохраняет цель и действующие ограничения, при этом выполняет новый поиск для каждого вопроса.
3. После обновления страницы или перезапуска пользователь продолжает тот же чат без повторного объяснения цели.
4. Другой чат начинается с отдельной историей и состоянием задачи.
5. При нехватке найденных сведений пользователь видит честный отказ и предложение уточнить запрос; сомнительный ответ не маскируется под подтверждённый.

## Приёмка и доказательства

| ID | Проверка |
| --- | --- |
| A1 / R1–R5 | Два разных длинных сценария по 10–15 сообщений через обычный интерфейс. В сценариях есть продолжения без повторения темы, уточнение цели и изменение ограничения. Проверяются поздние ответы, сохранение цели и наличие подтверждённых источников у содержательных ответов. |
| A2 / R1, R5 | Обновить страницу и перезапустить приложение в ходе сценария. История и состояние задачи доступны, просмотр сохранённого результата не запускает поиск или генерацию повторно. |
| A3 / R1, R8 | Создать другой чат и убедиться, что его запрос, контекст, результаты и состояние задачи не содержат данных первого. |
| A4 / R3–R4 | Для каждого нового хода проверить факт нового поиска и соответствие показанных источников реально переданным чанкам. Отдельно проверить недостаточный контекст и неверную цитату. |
| A5 / R7–R8 | Офлайн проверить прерывание, неизвестный платный исход, повтор запроса с тем же ID и сбой сохранения. Подставные сбои отделять в отчёте от реальных вызовов провайдера. |
| A6 | Подготовить код и видео обычного пользовательского пути. Для публичной записи использовать только разрешённые материалы; видео не считать доказательством качества всего корпуса. |

Отчёт о проверке указывает среду, число реальных вызовов, фактический расход, наблюдаемые ошибки и то, что не было проверено. Автоматические проверки структуры и источников отделяются от оценки смысла ответов человеком.

## Границы версии

Не входят: сжатие истории без измеренной необходимости, ветвление чатов, автоматическое накопление постоянных фактов о пользователе, пользовательский профиль, конечный автомат этапов всей задачи, новый индекс или новая модель поиска. Состояния обработки одного запроса из R7 не являются таким автоматом всей задачи.

Локальную разработку и офлайн-проверки можно выполнять в рамках запроса на реализацию. Прежний лимит облачных вызовов прототипа не считается новым бюджетом Day25: стоимость и область реальных длинных прогонов согласуются отдельно. Коммит, push и публикация не следуют автоматически из этой спецификации.
