# Личный наставник — рабочий RAG-прототип, SPEC v1


**Состояние 04.10.2026:** реализация и полировка Q1–Q5 завершены. Самостоятельный снимок опубликован в `day24/app` (коммит `226d5a5`); после него локально убран публичный пункт из обычного интерфейса. Пользователь подтвердил, что новая демонстрация соответствует желаемой сдаче; факт отправки задания не подтверждён. Известные ограничения качества сохранены в [результатах](../../../day24/RESULT.md).

**Разрешения:** реализация, адресные облачные проверки и публикация согласованы последовательно. Действующий прототип использует DeepSeek/OpenRouter/DeepInfra, замороженный корпус, общий лимит $0.10, retries=0; это не разрешение на новые эксперименты.

**Основание:** просьба пользователя получить самостоятельно используемый прототип вместо сценарной демонстрации; обсуждение Day24 и обзор реализаций других участников.

## Цель и границы

Пользователь открывает локальное приложение, вводит свой вопрос и получает результат настоящего поиска по своему корпусу, ответ и проверяемые источники. Пользоваться и проверять приложение можно без агента-разработчика и подготовки JSON-файлов.

Начальная версия — один пользователь, веб-страница на Mac, существующий индекс Structure на VPS. Это личный проект поверх накопленного результата; Day21–23 и исходный корпус не изменяются. По отдельному разрешению пользователя результат перенесён в самостоятельный Day24. Переиспользование рабочих механизмов допустимо; структура файлов и способ соединения компонентов определяются планом реализации.

## Требования

| ID | Наблюдаемое поведение |
|---|---|
| R1. Свой вопрос | Пользователь вводит произвольный самостоятельный вопрос, отправляет его и затем может задать другой. Видны выполнение, результат или конкретная ошибка. Повторное нажатие во время выполнения не создаёт второй платный запрос. |
| R2. Настоящий путь | Каждый новый вопрос проходит поиск по действующему индексу, отбор и, при разрешённом достаточном контексте, генерацию. Пользовательский режим, проверки и демонстрация используют одинаковые правила; скрытой подмены вопроса, контекста или ответа нет. Сохранённый результат обозначается как сохранённый. |
| R3. Источники | Под ответом сразу раскрыты отдельные разделы «Источники ответа» и «Цитаты»: проверенные цитаты, тип источника (условие / обсуждение / заметка), название, раздел или chunk_id. По нажатию открывается полный соответствующий чанк с выделенным фрагментом. Источник определяется по метаданным реально переданного чанка; модель не создаёт его реквизиты. |
| R4. Честные состояния | Различаются: ответ с проверенными цитатами; недостаточный контекст с «не знаю» и просьбой уточнить; непроверенный/некорректный ответ; техническая ошибка; запуск генерации не разрешён. Подлинность цитаты не обозначается как доказанная правильность смысла. По умолчанию смысл помечен «не проверен». Неподтверждённый текст не отображается как проверенный ответ; исходный ответ доступен отдельно в диагностике. |
| R5. Диагностика | Для результата доступны исходный поисковый запрос и его преобразование, если было, кандидаты, выбранные чанки, оценки и причины исключения, действующие настройки, время этапов и стоимость. Найденные, переданные модели и процитированные материалы различимы. Неизвестная стоимость обозначается как неизвестная. |
| R6. История результатов | После обновления страницы и перезапуска приложения доступны завершённые вопросы, ответы, их источники и диагностика. Просмотр не запускает генерацию повторно. Прерванная операция не выдаётся за успешную; при неизвестном исходе платного вызова приложение не повторяет его автоматически. |
| R7. Обратная связь | Для конкретного результата можно сохранить «не тот источник», «неверный вывод», «неполный ответ» и комментарий. Отметки сохраняются после перезапуска, не изменяют корпус, настройки или ответы автоматически. |
| R8. Приватность и расходы | Доступ к приложению и данным локальный. Приватные тексты и ключи не публикуются. Облачная генерация доступна только в согласованной области данных, с выбранной моделью/провайдером и общим бюджетом, включающим повторы. Поиск и просмотр доступны без разрешения облачной генерации. Повторное согласование внутри действующего разрешения не требуется. |

### Уточнения состояний

- Начальный отбор соответствует опубликованному Day24: K20→5, mixed 0.8/0.2, общий порог 0.35, rewrite выключен. Порог — настройка отбора, а не вероятность правильности. После согласованной полировки Q1 точные условия дней проходят по метаданным независимо от порога, сохраняя scope/topK/лимиты. Прежние потери Q06/Q07 относятся к исходному эксперименту, а не новой проверке.
- Если итоговый контекст пуст, выдаётся локальный отказ без вызова генератора. Равенство порогу не означает отказ. Если контекст есть, но модель сообщает отсутствие фактов, это отдельная причина отказа, а не доказательство отсутствия информации во всём корпусе.
- Подтверждать ответ как проверенный можно только при наличии источников и цитат и успешной проверке всех представленных ссылок/цитат. Ошибка JSON, выдуманная ссылка или цитата — непроверенный результат с объяснением причины. Частично валидный ответ не становится полностью проверенным.
- При отказе без доказательств списки источников/цитат пусты; это ожидаемое поведение. При сбое поиска/провайдера отображается ошибка, а не «не знаю». Ошибка сохранения также видна: уже полученный ответ не скрывается и не выдаётся за надёжно сохранённый.
- История R6 служит журналом результатов. В v1 предыдущие реплики не используются для разрешения «а это?»; интерфейс просит самостоятельную формулировку. Память беседы — отдельное расширение.

## Приёмка

- **A1 / R1–R5:** из обычного интерфейса выполнить вопрос по корпусу, новый вопрос пользователя, не заданный в демонстрационном коде, и вопрос вне темы. Наблюдать путь поиска, ответ или отказ; проверить соответствие открываемого источника реально переданному чанку. Для содержательного примера цитата должна подтверждать ответ; не обещать это для любых вопросов.
- **A2 / R4, R6, R8:** отдельно проверить пустую выдачу, недоступный поиск/провайдер, ошибочный формат/цитату, отсутствие разрешения, исчерпание бюджета, повторное нажатие, прерывание и сбой сохранения. Подставные сбои явно отделены от реальных запросов.
- **A3 / R6–R7:** обновить страницу и перезапустить приложение; проверить сохранённые результаты, привязку обратной связи и отсутствие повторных платных вызовов при просмотре.
- **A4 / R2, R5:** прежние 10 кейсов доступны как подписанные исторические результаты Day24. Без нового прогона они не выдаются за измерение новой версии. Известные ошибки Q05–Q07 остаются видны. Сохранённый вопрос, настройки, индекс и ответ позволяют отличить старый результат от нового.
- **A5 / R1–R8:** пользователь сам проходит обычный сценарий. Запись показывает то же приложение, без специальной подмены входа или контекста. Для публичной записи разрешены только публичные материалы; ограничение области поиска явно показывается в служебном запуске public-only. По уточнению пользователя 04.10 публичный пункт убран из обычного интерфейса; обычный запуск ищет по всему корпусу. Публичная запись не публикуется автоматически.

## Вне первой версии

Новая модель-реранкер или эмбеддер, объединение оригинального и переписанного запросов, изменение порога, пересборка/автоимпорт корпуса, отдельная модель-судья, память диалога, мобильное приложение, многопользовательский сервис и публичный деплой. Это возможная следующая полировка, не скрытые условия завершения v1.

## Условия перед выполнением

После согласования SPEC подготовить короткий план и задачи с привязкой к текущему коду. Реализация начинается по разрешению пользователя. Область данных и бюджет для произвольных облачных вопросов ещё не согласованы: разрешение Day24 на Q01–Q08 и $0.10 не переносится на весь корпус. Локальную разработку и проверки без облака это не блокирует. Коммит, push и публикация требуют отдельного разрешения.

## Согласованная полировка по живой истории, 03.10.2026

Пользователь попросил исправить обнаруженные ошибки после разбора 18 свободных запросов. Этот раздел заменяет запрет изменения отбора только в перечисленных пределах; опубликованные дни неизменны.

- Q1: явно запрошенное условие конкретного дня выбирается по метаданным независимо от семантического порога, в пределах области доступа и бюджета контекста. Поддержать «условие 18», day18, русские формы и наблюдаемую опечатку; даты/произвольные числа не считать днями задания. Для обычных вопросов порог сохраняется.
- Q2: для сообщений в контексте и источниках доступны автор, дата, ID и связь с текстом; атрибуция берётся из сохранённых метаданных. Смешанные по дате чанки не выдаются за целиком относящиеся к одному дню.
- Q3: явно указанная календарная дата ограничивает поиск до отбора. Год при его отсутствии берётся из дат архива и показывается как интерпретация. «Последние дни» интерпретируются как 7 дней до конца архива с явным диапазоном; это не текущие новости. Неоднозначный период/нет сведений — честное объяснение без скрытого снятия ограничения.
- Q4: ответ раскрывает запрошенные аспекты по найденному материалу, различает позиции и мнения, не требует от пользователя уже известный номер/дату повторно; не выдаёт перечень хранилищ за объяснение назначения индекса. Общие знания вне корпуса не добавляются скрыто. Новая модель или память диалога не входят.
- Q5: разрешена безопасная обработка единственной внешней Markdown-обёртки JSON с сохранением raw; произвольное исправление содержимого запрещено. Офлайн-тесты не обращаются к сети; неизвестный платный исход блокирует новые вызовы до запроса прайса.

Проверка: сохранённые кейсы являются регрессионными, не независимым holdout. Добавить новые синтетические формы/негативные случаи, затем адресный живой прогон через тот же путь приложения в действующем общем лимите $0.10, без автоматических повторов. Старые ответы/расходы не переписывать; новые результаты связать с исходными и версией кода. Публичный отчёт без приватных текстов, подробности private. Полную смысловую правильность не обещать по одним тестам.
