# День 4: температура

Дата: 2026-09-03

## Задание

Выполнить один и тот же запрос с temperature = 0, 0.7 и 1.2. Сравнить ответы по точности,
креативности и разнообразию. Сформулировать, для каких задач подходит какая настройка.
Формат сдачи: видео + код.

## Проблема, которую решает дизайн

Задание требует «один и тот же запрос», но точность и разнообразие — разные оси измерения.
Точность существует только там, где есть проверяемый ответ. Разнообразие существует только
там, где ответов может быть много. Один запрос не может дать честный сигнал по обеим осям
одновременно: если у задачи один правильный ответ, «разнообразие» — это просто доля ошибок,
а не творческая вариативность.

Решение — два запроса вместо одного, каждый бьёт по своей паре метрик:

- **аналитический** — проверяемый эталон, считается кодом, даёт точность
- **открытый** — без единственного верного ответа, даёт разнообразие и креативность;
  точность здесь измеряется иначе — не сходством с эталонным текстом, а выполнением
  явных требований, зашитых в сам промпт

Тот же принцип, что в дне 3: правильность не назначает человек на глаз, её считает код.

## Аналитический запрос: капкан для токенизации

```
Сколько букв «с» в слове «рассредоточенность»? Ответь только числом.
```

Эталон: `"рассредоточенность".count("с")` = 3, посчитан кодом.

Задача выбрана не случайно. Классические капканы вроде `9.11 vs 9.9` и подсчёта букв
в `strawberry` больше не работают на `deepseek-chat` — проверено вживую: обе версии
сравнения чисел (заезженная и свежая пара) модель решила верно при `temperature=0`.
Значит эти примеры измеряли бы не баг, а патч.

Подсчёт букв в словах с двойными буквами всё ещё воспроизводимо ловит модель:
из шести проверенных реальных слов пять дали неверный ответ при `temperature=0`,
и всегда в одну сторону — модель завышает счёт на единицу. «рассредоточенность» —
не мем, реальное слово, ошибка воспроизведена: правильно 3, модель ответила 4.

## Открытый запрос: гаджет с зашитыми требованиями

```
Придумай название для нового гаджета, который ещё не существует. Ответь ровно
3 предложениями. Обязательно укажи цену (целым числом, любая валюта) и одно
конкретное преимущество. Не используй слово «революционный» и его однокоренные формы.
```

Цена оговорена целым числом сознательно — иначе десятичная точка в цене ломает
подсчёт предложений по `.`.

### Точность: четыре требования, все проверяются кодом

1. ровно 3 предложения (разбивка по `.!?`, с учётом конца строки)
2. есть цена — регэксп на число рядом с валютой (`₽`, `руб`, `$`, `USD`, `€`, `EUR`)
3. есть выгода — эвристика по ключевым словам, два семейства: глаголы действия
   (`позвол`, `помога`, `экономит`, `увеличива`, `снижа`, `преимуществ`, `благодаря`)
   и прилагательные качества (`прочн`, `надёжн`/`надежн`, `качеств`, `долговечн`,
   `сил[её]н`, `мощн`, `быстр`, `лёгк`/`легк`, `удобн`, `эконом`). Первая версия
   списка (только глаголы) не прошла человеческий эталон — «силён своей кожей»
   не совпадало ни с одним словом. **Ограничение**: это ключевые слова, не понимание
   смысла — эвристика может пропустить выгоду, сформулированную без них вообще.
   Осознанный компромисс: разбор смысла без API невозможен в принципе.
4. нет корня «революцион» (регистронезависимо) — `революционный`, `революционно`
   ловятся, `революция` — нет, в ней этого корня нет (`революци` + `я`, без `он`)

Точность на прогон = доля из четырёх выполненных, точность на температуру = среднее
по 10 прогонам.

### Человеческий эталон

Отдельно от эталона-проверки — эталон-пример. Роман пишет один гаджет-питч руками,
соблюдающий все 4 требования, который ему реально нравится.

> Деловой чемодан. Цена 19₽. Он силен своей кожей, крокодильей, не поверишь.

Проверка сразу отработала как задумано: с первой версией списка ключевых слов
выгоды (только глаголы действия) эталон проходил 3 требования из 4 — «силён своей
кожей» не совпадало ни с одним словом. Список расширен прилагательными качества
(см. ниже), после чего эталон проходит 4 из 4.

Он:

- ставится на панель как визуальный якорь рядом с 30 ответами модели
- получает ту же оценку от судьи, что и все остальные — если судья не поставит
  человеческому примеру высокий балл, это повод не доверять судье, а не человеку

### Разнообразие

Доля уникальных полных ответов среди 10 прогонов на температуру (текст нормализуется:
нижний регистр, схлопнутые пробелы). Заимствовано из формата, который уже используют
в чате челленджа (колонка «Уникальных» в отчётах других участников) — рабочий,
проверенный вид метрики.

### Креативность: судья

Отдельный вызов на каждый из 30 ответов плюс на человеческий эталон (31 вызов):

```
Оцени оригинальность этого питча гаджета по шкале от 1 до 10, где 1 — банально,
10 — очень оригинально. Ответь только числом.

{answer}
```

Судья оценивает каждый ответ **по отдельности**, не видя остальные — иначе оценка
смещается относительно порядка показа, а не самого текста.

На видео — сверка вручную: до того как увидеть оценку судьи, Роман сам ставит
1–10 двум-трём ответам из тридцати, и сравнивается, совпадает ли с судьёй.
Это первый прогон LLM-as-judge, приём обсуждался в чате челленджа 02.09
(Гладков про синтезирующего агента и `LLM-as-a-judge`).

## Метрики целиком

| | точность | разнообразие | креативность |
| --- | --- | --- | --- |
| аналитический (буквы) | доля совпадений с эталоном (3) на 10 прогонов | не считается — один правильный ответ, здесь это шум | не считается |
| открытый (гаджет) | доля из 4 требований, средняя на 10 прогонов | доля уникальных ответов на 10 прогонов | судья 1–10 на каждый ответ + человеческий эталон |

## Структура

```
day04/traps.py       оба запроса, эталоны, проверки. Без API вообще
day04/temperature.py вызовы к DeepSeek: прогоны + судья. Здесь API
day04/test_traps.py  офлайн-тесты проверок
day04/results.json   сырые ответы + оценки судьи (для --report без API)
day04/web.py         локальный сервер панели, как day03/web.py
day04/web/index.html панель в стиле Гвинта
```

`traps.py` не обращается к API — эталон буквы и проверка четырёх требований
считаются бесплатно и мгновенно, как `build.py` в дне 3.

## Измерение

3 температуры × 2 запроса × 10 прогонов = **60 вызовов** на измерение,
плюс до 31 вызова судьи (только открытый запрос + эталон) = **до 91 вызова всего**.

Прогоны идут параллельно, пул потоков — как в дне 3. Сырые данные пишутся
в `results.json`, флаг `--report` пересчитывает таблицы без единого обращения к API.

## Панель: тема Гвинта

Метафора: три ряда боя в Гвинте (ближний/дальний/осадный) → три температуры.
Каждый ответ модели — карта в своём ряду.

- **ряд = температура** (0 / 0.7 / 1.2)
- **сила карты** = оценка судьи 1–10 (открытый запрос) или ✓/✗ (аналитический)
- **рамка карты**: золото — все 4 требования выполнены, бронза — часть,
  трещина — ответ не распарсился
- **карта-лидер** — человеческий эталон, отдельно над рядами, не в общей колоде
- **сумма ряда** — средняя точность/креативность температуры, крупно над рядом

Технически — та же панель, что в дне 3 (`/api/state`, `/api/check` аналог, кнопка
живого прогона), только вёрстка карточками вместо строк таблицы. Палитра:
фон тёмная кожа/дерево `#1c130c`, текст-пергамент `#e8dcc0`, бронза `#976006`,
золото `#CFB53B`. Только CSS, без внешних изображений — текстура и рамки
градиентами и `box-shadow`.

## Обработка ошибок

- сбой запроса к API — прогон помечается несостоявшимся, в статистику не идёт,
  количество печатается отдельно
- ответ на аналитический вопрос не парсится как число — отдельная категория,
  не засчитывается ни в точность, ни в ошибку
- ответ на открытый вопрос — каждое из 4 требований проверяется независимо,
  частичное совпадение не «ошибка», а частичный балл
- судья вернул не число — прогон исключается из среднего по креативности,
  считается отдельно

## Тесты (офлайн, без API)

`test_traps.py`:

- `letter_truth()` возвращает 3
- `check_gadget()` — каждое из 4 требований нарушается по отдельности и ловится:
  не 3 предложения, нет цены, нет ключевых слов выгоды, есть корень «революцион»
- `check_gadget(HUMAN_EXAMPLE)` — эталон проходит все 4 требования
- разбор числового ответа на аналитический вопрос — с лишним текстом,
  прописью вместо цифры (не парсится, отдельная категория), пустой ответ

## Что попадает в сдачу

- панель с обоими запросами, тремя температурами, картой-лидером
- таблица/вывод: для каких задач какая температура точнее, разнообразнее, креативнее
- отдельный вывод про капканы: почему классические (9.11, strawberry) больше
  не ловят модель, а подсчёт букв в словах с двойными буквами — ловит
- сверка человек-vs-судья на 2-3 примерах, с честным выводом, если разошлись

## Что сознательно не делается

- третий запрос ради полноты: два уже дают сравнение между типами задач,
  задание просит «запрос» в единственном числе — два и так превышение
- разбор смысла «выгоды» без ключевых слов: потребовал бы второго LLM-вызова
  внутри самой проверки точности, а это уже не код-эталон, а ещё один судья
- батч-оценка судьи (все 30 ответов в одном вызове): дешевле, но теряет
  независимость оценки каждого ответа
