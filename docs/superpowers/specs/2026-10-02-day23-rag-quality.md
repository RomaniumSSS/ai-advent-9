## 2. Предлагаемые механизмы (гипотезы, не доказанные улучшения)

- Rewrite: нормализация явных Day21 / 21-й день в «День 21», без добавления
  сведений ответа или угадывания номера. Несколько дней сохраняются; вопрос
  без подходящего обозначения остаётся прежним. Записываем before/after/applied.
  Ответная LLM получает исходный вопрос; поиск — преобразованный, если включён.
- Кандидаты: по умолчанию 20 вместо 5. Второй score = 0.8 × cosine + 0.2 ×
  доля уникальных слов поискового вопроса, присутствующих в чанке. Слова:
  Unicode-буквы/цифры, casefold, длина от 3; при пустом наборе доля = 0.
  Это эвристика, не вероятность. Веса фиксированы для первого эксперимента.
- Метаданные: только при явном вопросе об условии/требованиях названного дня
  добавить assignment с совпадающим day; не использовать эталонные ответы.
  Поддержать несколько дней; число страниц/цена/время не считаются номером дня.
  Условие — кандидат, не гарантия наличия ответа. Объединение по chunk_id.
- Отбор: точные условия идут первыми по отдельному правилу метаданных;
  остальные — по второму score с порогом. Отчёт отдельно показывает два пути:
  точное совпадение не выдаётся за прохождение similarity-порога.
  Проверяем пороги 0 / 0.35 / 0.5; равные score разрешаются по chunk_id.
- K_before = 20 относится к векторным кандидатам; добавленные по метаданным
  считаются отдельно. K_after ≤ 5 и прежние пределы: контекст ≤ 18000 байт
  UTF-8, сообщения ≤ 24000 байт. Это не число токенов. Чанки не разрезать.
  Пустую выдачу сохранять пустой и явно отмечать недостаток контекста.

## 3. Набор проверок: 100 вопросов, из них 20 для ответов

Основные непересекающиеся категории (варианты формулировки — дополнительные теги):
25 вопросов по одному условию; 15 сравнений условий; 30 по техническим
обсуждениям; 15 по понятиям/заметке без номера дня; 5 с отвлекающими числами;
10 с отсутствующим в корпусе ответом. Итого 100, включая прежние 10 Day22.

Каждый кейс: id, вопрос, категория, expected_facts, source_document_ids,
исходные ID сообщений/раздел и подтверждающий фрагмент или диапазон текста,
answerable и основание разметки. Для отсутствующего ответа: что именно
неизвестно, проверенные близкие материалы; отсутствие не доказывать лишь
провалом векторного поиска. Не требовать пустой выдачи при полезном частичном контексте.
Новые вопросы проверяет родитель по первоисточникам; генератор вопросов сам
не считается независимым проверяющим. Неоднозначные кейсы исправить/заменить
до фиксации; сомнительные не выдавать за надёжный эталон. Эталоны приватные.

Разделение до запусков: **40 для настройки (включая прежние 10), 60 отложенных**.
Одна смысловая группа (тот же факт/условие/ветка и её перефразировки) не попадает
в обе части. Составить вопросы можно по корпусу; результаты поиска и ответов
отложенной части не смотреть до фиксации настроек E. После просмотра её не
использовать для подстройки с сохранением названия «независимая проверка».
Это проверка по ограниченному набору, не оценка всего архива/будущего наставника.

Заранее выбрать 20 вопросов генерации: прежние 10 + 10 из отложенных,
включая обсуждения, сравнение дней, отсутствие ответа и числа не про день.
Нельзя выбирать их после просмотра удачности поиска. Разметка и группы
фиксируются отдельным манифестом с хешами до первой настройки.
Если квоты нельзя заполнить проверяемыми и различающимися кейсами — сообщить
конкретный дефицит; не добивать количество дублями или придуманными фактами.

## 4. Ограниченный эксперимент

| Вариант | Изменение относительно исходного A |
|---|---|
| A | Cosine top-5, без rewrite/второго фильтра/метаданных |
| B | Только rewrite, cosine top-5 |
| C | Без rewrite: 20 кандидатов → второй score/порог → до 5 |
| D | Без rewrite: исходные 5 + условия по метаданным → до 5, условия первыми |
| E | Сочетание полезных механизмов после A–D; параметры фиксируются |

A–D и выбор E — только на 40 вопросах настройки. На 60 отложенных — A/E один
раз после фиксации. Rewrite и фильтр остаются переключаемыми, даже если отдельное
изменение не улучшило результат. Никакого автоматического широкого поиска настроек.

Для всех: ожидаемые источники/опорные фрагменты в кандидатах и в итоговом
контексте, позиции, причины добавления/отсечения, объём, пустые выдачи, время.
Присутствие document_id не доказывает, что найден нужный абзац. Чужой ID не
означает нерелевантность: смысловую релевантность просматривать у спорных результатов.
Отчёт содержит метрики по категориям, answerable/unanswerable и двум частям.

Выбор: больше answerable-вопросов со всеми нужными опорными фрагментами;
без потери ранее найденных источников на старых 10; при равенстве — меньше
смыслового шума, затем проще вариант. Старое 5/10 не сравнивать с долей на 100.
Эталоны доступны оценщику, но не rewrite/поиску/генератору ответов.
Если пользы нет — сохранить отрицательный результат и завершить сравнение,
не начинать другой круг моделей/пересборку. Улучшение не обещать и не выдумывать.

## 5. Ответы, бюджет, приватность

DeepSeek V4.1 Flash / OpenRouter / только DeepInfra/fp8. Промпт, temperature=0,
max_tokens=1024 и reasoning=false как в Day22; генератор не меняем одновременно
с поиском. Старые 10 RAG-ответов — сохранённый baseline, получить 10 ответов E;
для новых 10 — A и E. До 30 новых успешных вызовов + живая пара для видео = 32.
Старый baseline записан раньше: это ограничение сравнения, не одновременный A/B.
Ответы сравнивать по ожидаемым фактам, ошибкам, подтверждению контекстом и
корректному признанию неизвестного. Проверяет родитель, без платной модели-судьи.
Ошибка генерации Q10 не считается автоматически исправленной новым поиском.

Общий cap **$1**, включая прогоны, видео, все попытки и неизвестные расходы.
Единый журнал бюджета: резерв до отправки, фактический usage после ответа,
блокировка параллельных отправок, продолжение без повторов успешных запросов.
Временные сетевые ошибки можно повторять с учётом предыдущего резерва;
ошибки авторизации/модели/провайдера и нехватка бюджета останавливают новые вызовы.
Провайдер не подменяется. Бюджет — потолок, остаток тратить не требуется.

В облако — только выбранные вопросы/чанки, включая обсуждения и заметку;
не полный экспорт, не поля авторов и не локальные пути. Private: 0700/0600.
100 вопросов и их разметка готовятся локально/в текущей согласованной среде;
сырой экспорт для генерации вопросов новым внешним сервисам не отправлять.
Утверждение SDD разрешает указанные вызовы и выбранные контексты Day23.
