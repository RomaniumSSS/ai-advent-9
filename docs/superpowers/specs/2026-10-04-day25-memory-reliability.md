# Day25 — надёжность памяти и ответа: дополнение к SPEC

Статус: проект изменений, 04.10.2026. Основа — [основная SPEC](2026-10-04-day25-rag-chat.md), A1 и фактические [2×15](../../../day25/T5-SESSION15-MECHANICAL.md). Это дополнение не меняет исходное условие и не объявляет A1 пройденным. Связанные [план](../plans/2026-10-04-day25-memory-reliability.md) и [задачи](../tasks/2026-10-04-day25-memory-reliability.md).

## Проблема и границы

В живом прогоне короткие продолжения теряли тему при формировании поискового запроса; диапазон учебных дней трактовался как календарный; поздний ответ приписал пользователю не сделанный им выбор. Последние две локальные правки устранили известные формы первых двух сбоев в офлайн-повторе, но повторного живого прогона не было. Исторический A1 — FAIL.

Действующее состояние задачи вводится пользователем явно и хранится по чату. Новое автоматическое извлечение памяти из каждой реплики, новая модель, общий профиль пользователя и изменение корпуса не входят в эту работу.

## Требования

| ID | Проверяемое поведение |
| --- | --- |
| M1 / R2–R3 | Перед каждым поиском приложение фиксирует, является ли текущий вопрос продолжением, новой темой или явно ограниченным запросом. Для продолжения поисковый запрос включает подходящую действующую цель и релевантные ограничения/уточнения; для самостоятельной новой темы не наследует старую цель. Явно названные день, дата и область текущего вопроса имеют приоритет. Если связь неоднозначна, приложение не выдаёт догадку о теме за подтверждённый факт и предлагает уточнение либо безопасно ищет без спорного ограничения. Решение и использованные поля видны в диагностике. |
| M2 / R5 | Версия task state, использованная для поиска и ответа, совпадает с версией выбранного чата на момент запроса. Явный пользовательский выбор сохраняется как уточнение только действием пользователя; текст ассистента и найденных документов не становятся пользовательским выбором. После изменения цели или ограничения устаревшее состояние не действует. |
| M3 / R4–R5 | Содержательный ответ не приписывает пользователю конкретный выбор, цель или запрет без соответствующей записи пользовательского состояния либо явной реплики в этом чате. При отсутствии такой опоры ответ использует условную формулировку или просит уточнить. Проверка источников корпуса остаётся обязательной и отдельной от проверки пользовательских фактов. |
| M4 / R4, R8 | Если найденного контекста недостаточно, приложение сохраняет честный отказ/уточнение; не ослабляет проверку цитат и не подставляет историю беседы вместо источника корпуса ради повышения доли ответов. Изоляция чатов, public-only и учёт расходов сохраняются. |

## Приёмка

| ID | Доказательство |
| --- | --- |
| B1 / M1–M2 | Офлайн-набор по разнообразным формулировкам: короткие продолжения, новая тема, явные дни/даты, смена цели, отмена ограничения, другой чат. Проверять не только выбранную ветку, но и состав запроса, версию состояния, фактически переданные чанки и отрицательные случаи. Старые известные вопросы входят в regression, отдельные новые — в holdout. |
| B2 / M3–M4 | Офлайн-проверки запрещают приписывать выбор из ответа ассистента или документа и сохраняют отказ при недостатке фактов; реальные ответы оцениваются отдельно по смыслу, источникам и фактам о пользователе. Технический статус `verified` сам по себе не означает смысловой PASS. |
| B3 / A1 | После изменений нужны два новых разговора по 10–15 сообщений через обычный интерфейс с разными формулировками, поздними продолжениями, новой темой и изменением состояния задачи. Независимая оценка проверяет удержание цели, корректность источников и отсутствие приписанных решений. PASS только при выполнении исходного A1 в обоих разговорах; любой обязательный смысловой FAIL оставляет A1 открытым. Непроверенный ответ не засчитывается как PASS. |
| B4 / R8 | До платного прогона фиксируются область корпуса, точный общий лимит, число вызовов, запрет автоматических повторов и исходная версия кода. Неизвестный расход останавливает прогоны. Старые raw-результаты и оценки не переписываются. |

## Статус сдачи

Существующие код и видео демонстрируют мини-чат, RAG, источники и task state. Два длинных сценария проведены, но их смысловая оценка A1 — FAIL. Поэтому наличие сдаваемых материалов подтверждено, а выполнение требования «не теряет цель» пока не подтверждено. Новая работа направлена на этот пробел, без гарантии результата до B3.
