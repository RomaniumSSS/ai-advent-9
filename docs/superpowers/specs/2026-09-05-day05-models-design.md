## Выбор моделей

| --- | --- | --- | --- | --- | --- |

| сильная | `zai-org/GLM-5.3:deepinfra` | 753B | 1.20 | 4.00 | 74 |

Разброс по параметрам — в 6.4 раза. Числа взяты с карточек моделей на HuggingFace,
цены и пропускная способность — из таблицы `huggingface.co/inference/models`.

«Слабая» здесь означает младшую из трёх, а не слабую вообще. В отчёте формулировать как
«младшая / средняя / старшая по числу параметров», иначе получается, что флагманская
открытая модель OpenAI названа слабой.

### Почему все три на одном провайдере

Одни и те же веса раздают несколько независимых провайдеров, и скорость с ценой у них
разные. Замер на разных провайдерах меряет их железо, а не модели.

Доказательство из таблицы HF — `gpt-oss-120b`, файл везде идентичный:

| провайдер | выход $/1M | т/с |
| --- | --- | --- |
| cerebras | 0.75 | **970** |
| groq | 0.75 | 425 |
| baseten | 0.50 | 207 |
| deepinfra | 0.17 | **41** |

**Разброс в 24 раза по скорости и вчетверо по цене на одной модели.** Эта таблица идёт
в отчёт: она доказывает делом то, что остальные участники вчера утверждали на глаз.

`deepinfra` — единственный провайдер, обслуживающий все три выбранные модели, и у всех
трёх он самый дешёвый. Поэтому провайдер закрепляется явно суффиксом `:deepinfra`,
а не отдаётся роутеру на усмотрение: иначе цена и скорость поедут от запуска к запуску
и колонка стоимости станет выдумкой.

### Почему не Kimi K3

Рассматривалась как «сильная» (2.8T, разброс в 24 раза). Отклонена по цене: на deepinfra
$2.85 / $14.25 против $1.20 / $4.00 у GLM-5.3, то есть выход дороже в 3.6 раза.

В деньгах при ответе на 500 токенов:

| | n=3 | n=10 |
| --- | --- | --- |
| с Kimi K3 | $0.022 | $0.073 |
| с GLM-5.3 | $0.0065 | $0.021 |

При месячных кредитах $0.10 Kimi оставляла четыре сравнения, GLM оставляет пятнадцать.
Строгость замера (много прогонов) важнее ширины разброса.

**Побочное следствие, которое надо честно отработать в выводе.** На одном железе
получается 41 / 43 / 74 т/с — самая крупная модель самая быстрая. Наивное «больше значит
медленнее» не подтверждается, и причина в разреженности MoE: у активного счёта параметров
своя арифметика, не совпадающая с общим числом.

## Доступ: HF Inference Providers

Все модели зовутся одним токеном HuggingFace через общий роутер.

```
base_url = "https://router.huggingface.co/v1"
api_key  = HF_TOKEN
model    = "<org>/<модель>:<провайдер>"
```

Эндпоинт OpenAI-совместимый и только для chat completions — этого достаточно.

**Права токена.** Обычный токен инференс не разрешает: первый заход дал
`403 — This authentication method does not have sufficient permissions to call Inference
Providers`. Нужен fine-grained токен с галочкой **«Make calls to Inference Providers»**.

**Деньги.** Free-аккаунт получает **$0.10 кредитов в месяц**. HF берёт цену провайдера
без наценки. Кредиты кончились — доступ продолжается только после покупки.

**Экономия.** Свой ключ провайдера можно вписать в настройки HF; тогда эти вызовы
оплачивает провайдер напрямую и кредиты HF не тратятся. Для DeepSeek у Романа
оплаченный ключ уже есть. В первой версии не используем, но путь записан.

### Что показала разведка (05.09, `/tmp/hf_probe.py`)

Промпт «Назови три цвета. Ответь одной строкой, без пояснений.», `max_tokens=100`:

| модель | время | вход | выход | stop | видимый ответ |
| --- | --- | --- | --- | --- | --- |
| Kimi K3 | 3.06 с | 108 | 100 | length | «Красный, син» |
| DeepSeek V4 Flash | 1.01 с | 21 | 70 | stop | «Красный, синий, зелёный.» |
| gpt-oss-120b | 0.51 с | 82 | 100 | length | «красный,» |

Три вывода, заложенные в дизайн:

1. **`completion_tokens` ≠ длина ответа.** У двух моделей из трёх почти весь бюджет ушёл
   в невидимые рассуждения, и до ответа они не доехали. Значит `MAX_TOKENS` должен быть
   с запасом, а в стоимость войдёт то, чего не видно на экране.
2. **Один и тот же промпт стоит разного числа входных токенов** — 21 против 108, впятеро.
   Разные токенизаторы плюс служебные обёртки провайдера. Метрика «количество токенов»
   частично меряет обёртку, а не модель, и это надо оговорить в отчёте.
3. **`usage` вернули все трое** — обязательное требование задания выполнимо.

### `models.py`

Словарь моделей. У каждой:

```python
"gpt-oss-120b": {
    "id": "openai/gpt-oss-120b:deepinfra",
    "params": "117B",
    "params_num": 117,            # для сортировки и подписей
    "price_in": 0.04,             # $ за 1M токенов
    "price_out": 0.17,
    "hf": "https://huggingface.co/openai/gpt-oss-120b",
}
```

Помимо трёх основных в каталог кладутся для выпадашек: `gpt-oss-20b` (21B),
`Qwen3.6-27B` (27B), `GLM-5.3-Flash` (321B). У всех — реальные цены из таблицы HF
и закреплённый провайдер.

**Правило каталога: модель без известного числа параметров в него не попадает.** Параметры
это ось, по которой строится всё сравнение; модель без них нечем подписать.

Функции:

```python
def cost(prompt_tokens: int, completion_tokens: int, model: str) -> float
def estimate_calls(models: list[str], runs: int, judge: bool) -> int
def estimate_worst_cost(models: list[str], runs: int, judge: bool) -> float
```

`cost` — чистая арифметика, тест на известных числах. `estimate_calls` нужен панели,
чтобы показать «будет N вызовов» до запуска.

`estimate_worst_cost` считает **верхнюю границу по `MAX_TOKENS`**, а не типичный расход.
Это принципиально: при `MAX_TOKENS = 4000` и цене GLM $4.00 за 1M один вызов в пределе
стоит $0.016, а прогон на трёх повторах — до $0.048, то есть половину месячных кредитов.
Типичный расход в восемь раз меньше, но панель обязана показывать границу, за которую
не выйдет, а не среднее, которое ничего не гарантирует.

Ссылка на HF лежит здесь же не для красоты: задание требует «выводы + ссылки»,
и панель их показывает.

### `compare.py`

```python
def ask(question: str, model: str) -> dict
```

Возвращает запись: `answer`, `finish_reason`, `elapsed`, `prompt_tokens`,
`completion_tokens`, `reasoning_tokens`, `cost`, `model`, `error`.

`reasoning_tokens` берётся из `completion_tokens_details.reasoning_tokens`, если провайдер
его отдал. Отдаст не каждый — поле опциональное, отсутствие не считается ошибкой.

`usage` тоже может не прийти: тогда токены и стоимость записываются как `None`,
а не как ноль. Ноль соврал бы, что вызов был бесплатным.

```python
def compare(question: str, models: list[str], runs: int = 3, judge: bool = False) -> dict
```

Гоняет каждую модель `runs` раз, собирает записи, считает по каждой модели среднее время,
средние токены, суммарную стоимость и разброс времени (мин/макс).

Сбой одного вызова не роняет прогон: запись помечается `error`, агрегаты считаются
по успешным. Это поведение уже отработано в дне 4.

`MAX_TOKENS = 4000` — с запасом, потому что рассуждения едят бюджет раньше ответа.

Судья — необязательный отдельный вызов, оценка 1–10 за каждый ответ, по умолчанию
выключен. Код судьи переносится из `day04/temperature.py` с одной поправкой: судьёй
работает самая дешёвая модель каталога, а не подсудимая.

CLI: `uv run day05/compare.py --question "..." --runs 3`.

### Хранение

Результаты не перезаписываются, а копятся — вопросов будет много:

```
day05/results/2026-09-05T19-14-obyasni-rekursiyu.json
```

Имя файла: метка времени плюс транслитерированное начало вопроса. Каждый файл — одно
сравнение целиком: вопрос, модели, все записи, агрегаты.

### Панель

Своё оформление под сравнение, не тема Гвинта из дня 4.

Сверху форма: поле вопроса, три выпадающих списка моделей, поле числа прогонов
(по умолчанию 3), галочка судьи (по умолчанию выключена), строка «будет N вызовов,
максимум $X» и кнопка запуска. Стоимость показывается как верхняя граница по `MAX_TOKENS`,
а не как ожидаемая — см. `estimate_worst_cost`.

Середина — три колонки. В каждой: имя модели ссылкой на HF, число параметров и четыре
величины: время, токены входа, токены выхода, стоимость. Полоски для сравнения глазами.
Ответ разворачивается по клику.

Низ — история прошлых сравнений из `results/`: вопрос, дата, три модели, итоговые числа.

Панель одна и та же для обоих режимов. При загрузке она проверяет, доступен ли локальный
эндпоинт запуска: доступен — форма активна, недоступен — форма показана, но заблокирована
с подписью «запуск только с машины владельца». Так публичный зритель видит, что тут
происходит, и не думает, что панель сломана.

Колонка качества показывается только когда включён судья. Без него её нет — эталона
у открытого вопроса не существует, и рисовать пустую оценку значит подменять измерение
видимостью измерения.

### Доступ: чтение и запуск разведены по адресам

**В процессе сервера живёт токен HF.** В дне 4 панель поэтому слушала только `127.0.0.1`.
На VPS она становится доступна из сети, и эндпоинт, который на каждый POST ходит
в платный API, нельзя вешать в интернет открытым.

Выбранный режим: **смотреть могут все, запускать — только с самой машины.**

| адрес | что отдаёт |
| --- | --- |
| `0.0.0.0:8035` | `GET /`, статика, история из `results/` — публично, ссылку можно показывать |
| `127.0.0.1:8036` | `POST /api/compare` — запуск, снаружи недостижим |

Публичная панель рисует историю и результаты; кнопка запуска на ней неактивна с понятной
подписью. Чтобы задать вопрос, Роман поднимает туннель `ssh -L 8036:127.0.0.1:8036 hetzner`
и работает с панелью как с локальной, либо зовёт CLI прямо на сервере.

**Почему так, а не пароль.** Домена у машины нет, TLS сходу не поставить, а без TLS любой
секрет уходит по сети открытым текстом — замок есть, но ключ от него слышно по дороге.
Разделение адресов не смягчает эту дыру, а убирает: **по открытому каналу не передаётся
ничего секретного вообще.** Кредиты недостижимы снаружи в принципе.

Отклонены:

- **общий секрет в заголовке** — работает только поверх TLS, которого нет
- **полностью открытый запуск** — кредиты сгорят на первом обходчике
- **только SSH-туннель на всё** — тогда ссылку не покажешь, а смысл выкладывания в этом

**Путь к TLS, если понадобится.** Домен покупать не обязательно: бесплатный поддомен
(DuckDNS) плюс Caddy, который сам берёт и обновляет сертификат Let's Encrypt. Это апгрейд,
а не предусловие — схема выше от него не зависит и переезжает без переделки. Понадобится,
если захочется дать кнопку кому-то ещё.

Токен HF на сервере лежит в `.env`, файл вне git, права `600`.

## Обработка ошибок

- Сбой вызова к модели: запись с `error`, прогон продолжается, агрегаты по успешным
- Битый JSON в POST: `400` с внятным текстом, сервер не падает (эти грабли уже ловили в дне 4)
- Нет `usage`: токены и стоимость `None`, не ноль
- Кончились кредиты HF: провайдер вернёт ошибку, она доедет до панели как текст, а не как
  молчаливый пустой ответ
- Неизвестная модель в запросе: `400`, не попытка сходить в API

## Тесты

`day05/test_models.py` — без сети, как `day04/test_traps.py`:

- `cost` на известных числах: 1000 входных и 500 выходных токенов у каждой модели каталога
- `cost` на `None` вместо usage возвращает `None`
- `estimate_calls`: 3 модели × 3 прогона без судьи = 9, с судьёй = 18
- `estimate_worst_cost` не занижает: результат равен сумме `cost` по всем вызовам,
  посчитанной при `completion_tokens = MAX_TOKENS`
- каждая запись каталога имеет все обязательные поля, провайдер закреплён явно,
  цены положительные
- транслитерация имени файла сессии не даёт пустое имя и не выходит за папку `results/`

## Что сознательно не делаем

- **Автоматическую оценку качества без судьи.** Эталона у открытого вопроса нет.
- **Замер одной модели на нескольких провайдерах.** Обсуждали как вторую ось (те самые
  24 раза). Данные из таблицы HF в отчёт идут, а свой замер по этой оси — вне объёма.
- **Сравнение скорости между провайдерами.** Все три закреплены на deepinfra именно
  чтобы этой переменной не было.
- **Общий модуль с днём 4.** Обоснование выше.
- **Хранение истории в базе.** Файлы в `results/` достаточны для десятков вопросов.
