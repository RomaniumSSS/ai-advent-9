# Day33 — TeamDesk

[Видео Day33, 68.2 с](https://drive.google.com/file/d/1CNtHo7ruiEZpUN7VGUeeQiHJGXTPJYLt/view?usp=sharing). Загрузку и доступ «Anyone with the link / Viewer»
координатор проверил через UI. Пользователь ещё должен оценить результат.

Код опубликован: [код Day33](https://github.com/RomaniumSSS/ai-advent-9/tree/day33-support/day33), [коммит `c6e54e2`](https://github.com/RomaniumSSS/ai-advent-9/commit/c6e54e2ffbb8ed0cab19393c32f3f22563933075).
Таблица сдачи (строка 132) заполняется координатором; user_acceptance=false.

Независимый мини-сервис поддержки: серверный demo-сеанс → настоящий MCP stdio
(JSON-RPC initialize / initialized / tools/list / tools/call) → поиск FAQ → один ответ.
Синтетическая CRM read-only, UI слушает только `127.0.0.1`. Переключение demo-пользователя
не является production-аутентификацией. Контекст другого пользователя отклоняется до модели.

Для приложения и основных тестов достаточно Python 3.12+ и стандартной библиотеки.
Команды выполняются из корня репозитория. `uv sync --dev` устанавливает зависимости
из корневого `pyproject.toml`; runner требует Playwright и установленный Google Chrome
(`channel=chrome`), запись дополнительно требует системные ffmpeg/ffprobe.
Корневой baseline зависимостей публикуется без изменений.

```sh
python3 day33/test_app.py
uv run python day33/app.py
# http://127.0.0.1:8133
uv run python day33/video/run_demo.py
```

По умолчанию модель **MOCK**: детерминированные ответы, без API. Реальными остаются
дочерний MCP-процесс, чтение JSON, retrieval и HTTP. Три сценария: Алиса/T101 — подтверждение
почты; Борис/T102 — новое приглашение; Алиса/T103 — уточнение ошибки. Поиск ранжирует
фрагменты по диагностическим кодам и словам вопроса, возвращает максимум два из четырёх,
сохраняет ID. Без известного диагностического события сервер после MCP/RAG возвращает
фиксированное безопасное уточнение без вызова модели и бюджета; трасса отмечает
`response_kind=rule_based_clarification`, model/provider отсутствуют. Ответ модели проверяется на точное соответствие ссылок выбранным источникам. После проверки source_ids отсутствующие inline-ссылки
добавляются детерминированно из этих ID; чужие/необъявленные ссылки и дубли ID отклоняются.
Проверка ссылок не доказывает смысловую корректность живого ответа модели.

Live включается явно `--live --budget-ledger /absolute/shared.sqlite` и требует
`OPENROUTER_API_KEY` в окружении. Ledger заранее создаётся оператором через
`Budget.initialize(path)` **один раз для обоих дней**; приложение не создаёт и не сбрасывает его.
Модель `qwen/qwen3.8-max-0902`, единственный provider `alibaba/us-east-1`, fallback и retries
отключены. Профиль: max_tokens4096, reasoning low/exclude. Резерв до сети считает UTF8 bytes
запроса +4096 overhead по $2/M и максимум output по $6/M. SQLite BEGIN IMMEDIATE защищает
общий лимит $1 между процессами. Неизвестная стоимость/ошибка сохраняет полный резерв;
известная стоимость сохраняется идемпотентно. Превышение сохраняется и блокирует новый резерв.
Usage/cost неизвестны — `null`, а не ноль. Ключ не попадает в ответы или трассы.

`test_app.py` проверяет реальный MCP/HTTP, cookies двух клиентов, cross-user deny,
разные источники, уточнение, пустой RAG, ошибки и model boundary с подменённым HTTP,
атомарный общий ledger и concurrent reserve. Отсутствие диагностики отдельно проверено на отсутствие model/network call.
Живой провайдер этими тестами не проверен.
`video/run_demo.py` выполняет ровно три новых UI-запроса (два model, один rule-based),
проверяет ожидаемые причины/шаги и сохраняет ответы `/api/ask` с trace, тайминги,
скриншоты ответа и контекста в новый каталог каждого запуска. Проверки по словам —
сценарный smoke check; смысл ответа и кадры записи необходимо прочитать человеку.
Режим сервера проверяется до отправки вопросов. Собственный browser/context закрывается
в `finally`; `--record` пишет viewport 1280×1000, конвертирует webm в mp4 без ускорения
и сохраняет ffprobe. Требуются Playwright/Chrome, при записи — ffmpeg/ffprobe.

```sh
# Офлайн отдельный mock-сервер; не использовать порт живого оператора.
uv run python day33/app.py --port 8135
uv run python day33/video/run_demo.py --url http://127.0.0.1:8135 --mode mock
uv run python day33/video/run_demo.py --url http://127.0.0.1:8135 --mode mock --record
# Только live-оператор: сухой прогон и запись — отдельные оплачиваемые запросы.
uv run python day33/video/run_demo.py --url http://127.0.0.1:8133 --mode live
uv run python day33/video/run_demo.py --url http://127.0.0.1:8133 --mode live --record
```

По умолчанию пауза чтения каждого ответа/контекста 7 секунд, timeout запроса 120 секунд
(серверный model timeout 90 секунд). `--output-dir` должен указывать новый путь;
без него создаётся уникальный `/tmp/day33-runs/<timestamp>-<id>`. Ошибка оставляет
`result.json`, полученные ответы и доступные кадры. Завершённый runner сам по себе
не означает, что обязательное видео просмотрено и принято.

Проверенная среда live на этом Mac — `uv run python`: системный Python не прошёл TLS CA.
При ошибке модели HTTP502 возвращает run_id и безопасный model_error: stage/code,
identity, finish_reason, usage/cost, reservation и visible/parsed content. Reasoning,
ключи и заголовки исключены; runner сохраняет этот JSON также при неуспехе проверки.

Офлайн-регрессии расширенных границ: `uv run python day33/test_robustness.py`.
Исходное demo не меняется; дополнительные фикстуры лежат в `data/robustness/`,
сравнение до/после — `results/robustness-offline.json`. Fuzzy/лексический routing
консервативен и ограничен входом/приглашениями; это не универсальный классификатор.
Неизвестные или разные диагностические коды, противоречие статуса и отсутствие
FAQ дают уточнение без вызова модели. Порядок событий без времени не определяет последнее.
Текст FAQ и тикета остаётся недоверенным: проверка ID ссылок не доказывает смысл
ответа и устойчивость LLM к injection. Mock-проверки доказывают права/ветвление,
семантику живого ответа проверяют отдельно по `data/robustness/live-cases.json`.

Операторский runner (запускает оплачиваемый API только с `--live`): `uv run python day33/live_robustness.py --live
--ledger <существующий-ledger> --case auth-typo --output <новый-evidence.json>`.
Один case за запуск; ошибка и вход сохраняются, вердикт требует независимой оценки.
Лимит accounted по умолчанию $0.767852 — согласованный операторский потолок данной
серии; ledger не инициализируется и не сбрасывается. Оператор запускает оба дня
последовательно. Сеть модели ограничена общим дедлайном 90 с и телом 1 MB;
по истечении дедлайна transport-процесс прекращается, неизвестная стоимость остаётся hold.
