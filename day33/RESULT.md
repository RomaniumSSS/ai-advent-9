Lexical/fuzzy gates ограничены и могут пропустить формулировку либо излишне уточнить.
Prompt-коррекция и выборочные live PASS не гарантируют обобщение на все симптомы
или injection. ID ссылок не доказывают смысл ответа. Overrides live-фикстур вводятся
после настоящего MCP scope read; это не проверка доставки изменённых fixtures MCP.
Mock не подтверждает семантику Qwen. Оценку выполнил ассистент-координатор,
**user_acceptance=false**; пользовательская сдача не подтверждена; код опубликован: [код Day33](https://github.com/RomaniumSSS/ai-advent-9/tree/day33-support/day33), [коммит `c6e54e2`](https://github.com/RomaniumSSS/ai-advent-9/commit/c6e54e2ffbb8ed0cab19393c32f3f22563933075).

TeamDesk читает синтетическую CRM через настоящий read-only MCP stdio,
выбирает до двух FAQ-фрагментов и отвечает с учётом тикета. Серверный demo-сеанс
изолирует пользователей; чужой тикет отклоняется до модели. При отсутствии диагностики
после MCP/RAG возвращается фиксированное уточнение без model call.

[Код и запуск](README.md), [проверки](test_app.py), [runner](video/run_demo.py).
Проверенная среда приложения — `uv run python`. UI доступен только loopback.
Модель: `qwen/qwen3.8-max-0902`, provider `alibaba/us-east-1`, без fallback/retries.

В предыдущей версии: 10 app tests и 3 runner checks PASS; независимые Luna → исправления → Astra
и targeted rechecks выполнены. Офлайн-проверки модели используют mock и не заменяют live.
Live dry05 (локально: `results/live-dry-05/result.json`) — PASS: три новых HTTP-ответа,
две реальные генерации и одно rule-based уточнение. Ответы прочитаны оператором.
