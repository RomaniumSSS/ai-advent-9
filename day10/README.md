# День 10 — стратегии управления контекстом

Три стратегии и переключатель между ними, без суммаризации. Архив в SQLite
остаётся полным всегда; меняется только то, что уезжает в модель.
Модель по умолчанию — **DeepSeek V4 Flash 0731** через OpenRouter.
Код дня 10 самостоятельный; старые дни не изменены.

```bash
uv run day10/web.py --env-file /путь/к/.env     # панель, 127.0.0.1:8040
uv run day10/run_strategies.py --dry-run --all  # прогон без сети и без денег
```

## Три стратегии

| Стратегия | Что уезжает в модель | Служебные вызовы |
| --- | --- | --- |
| **Полная история** | вся переписка | нет |
| **Sliding Window** | последние `N = 6` сообщений | нет |
| **Sticky Facts** | блок `facts` + последние `N = 6` сообщений | один на каждый ход |

Выбор живёт в `strategies.py` целиком: `context_history(config, history, facts)`.
Агент видит только объект стратегии и не знает, как собран его контекст, —
поэтому переключатель это подмена одного поля, а не набор `if` по файлу.

**Ветвление** сюда намеренно не входит и лежит в `branches.py`. Стратегии
отвечают на вопрос «сколько истории отправить», ветки — на вопрос «какая это
история». В одном переключателе это был бы выбор между литрами и цветом.

## Память «ключ-значение»

Ключи фиксированы списком: `проект`, `цель`, `ограничение`, `срок`, `бюджет`,
`решение`, `отменённое_решение`, `предпочтение`, `договорённость`. Ключ вне
списка отбрасывается.

Без фиксации извлекатель плодит синонимы: «цель» на третьем ходу, «задача» на
девятом, «что делаем» на четырнадцатом. Это три записи об одном, старая не
перезаписывается, и в запрос уезжают все три — включая устаревшую.

Удаление запрещено: пустое значение и `null` игнорируются, а не стирают факт.
Иначе модель без спроса «прибирает» то, что сочла неактуальным, и пропажа
обнаруживается только когда агент перестал помнить. Изменение решения —
перезапись значения, отмена — ключ `отменённое_решение`.

Оба правила взяты из чужих сдач дня 10, где до них дошли постфактум.

Отказ безопасен. Битый JSON, пустой ответ, ключи не из списка — память остаётся
прежней, ход не роняется, причина попадает в `facts_event` и на экран. Служебный
вызов оплачен в любом случае и записан в журнал как `kind='facts'`: спрятать его
в общий счёт значило бы сравнивать стратегии по неполной цене.

## Ветки

Ветка — обычная сессия в том же файле базы, а не новая сущность: изоляция
сессий уже есть и уже переживает перезапуск. `fork(checkpoint)` одной
транзакцией копирует сообщения до границы и текущие facts в сессию `main/a`;
дальше ветки независимы, и расход у каждой свой.

Копия, а не ссылка на общий префикс. Ссылка была бы экономнее, но тогда всякий
читатель истории должен был бы знать про склейку, а очистка одной ветки уносила
бы начало другой.

## Что показывает панель

Порт 8040, слушает только `127.0.0.1`. Переключатель стратегии, кнопки веток,
видимый блок facts, счётчики хода и накопленный итог с отдельной строкой на
память. Сообщения, которые в модель уже не уезжают, показаны бледными и
подписаны «вне контекста» — архив пользователя не режет ни одна стратегия.

## Результаты

Сценарий «Планирование проекта» из `scenarios.py`: 16 фиксированных вопросов,
одни и те же для всех стратегий. Контрольные ходы 9, 14 и 16 прямо просят
назвать факты — по ним и видно, что стратегия потеряла.

Живой прогон 12.09.2026, DeepSeek V4 Flash через OpenInference FP8:

| Стратегия | Вызовов | Вход | Выход | Всего токенов | К полной | Цена | Факты |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Полная история | 16 | 159 903 | 20 097 | 180 000 | — | $0.003591 | 12/15 |
| Sticky Facts | 32 | 54 494 | 12 757 | 67 251 | −62.6% | $0.003195 | 12/15 |
| Sliding Window | 16 | 31 675 | 10 685 | 42 360 | −76.5% | $0.002122 | 3/15 |

Вход первого хода у всех одинаков — 91 токен. К шестнадцатому: 20 358 у полной
истории против 2 286 у Facts и 2 185 у Sliding. Растёт не вопрос, а история.

**Sticky Facts помнит столько же, сколько полная история, при втрое меньшем
входе.** Из 16 её служебных вызовов вышло 19 668 токенов и $0.000833 — пятая
часть собственного счёта стратегии. Эта цена окупилась здесь, но она постоянная:
на коротком разговоре Facts обойдётся дороже полной истории, потому что платит
за память там, где памяти ещё нет.

**Sliding Window дешевле всех и помнит 3 из 15.** На девятом ходу она ещё
назвала срок и языки — поправка была внутри окна. К четырнадцатому не осталось
ни названия, ни бюджета, ни срока: выпали из шести последних сообщений.

**Неожиданное: полная история ответила неправильно.** На всех трёх контрольных
ходах она назвала «актуальный срок: 18 октября» — тот самый, который сценарий
отменил на шестом ходу. Данные были в контексте целиком, и именно поэтому
рядом лежали обе даты. Facts и Sliding ответили «25 октября».

У Facts отмена хранится отдельным ключом, и в конце прогона память выглядела так:

```
проект              : сайт записи на занятия «Маяк»
бюджет              : 1200 евро
срок                : 25 октября
предпочтение        : обязательные языки: русский и польский
решение             : подтверждение записи отправляет администратор вручную
отменённое_решение  : срок: 18 октября
```

Ради этой строки ключ `отменённое_решение` и заводился: без него отменённое
значение либо теряется, либо перезаписывает актуальное.

Единственная непройденная проверка у Facts и полной истории — «онлайн-оплата
упомянута». Это лексическая проверка, и она ищет слово, а не отрицание: ответы
просто не повторяли исключённую функцию. Читать такие места нужно глазами.

Ветвление: точка на 16 сообщениях, две ветки по два хода, каждая унаследовала
16 сообщений и facts. В исходной сессии после этого осталось 16 сообщений —
ветки её не тронули.

Из 76 вызовов один упёрся в 429 и прошёл со второй попытки. Всего потрачено
около $0.009 из $0.50; ещё два вызова ушли на запись видео.

[Видео: код, переключение стратегий, ветки и живой ход](demo/README.md) —
57,8 секунды без звука.

Сравнение честно ровно настолько, насколько одинаков вход. Вопросы одинаковы,
но ответы расходятся, а с ними расходится и история: числа сравнивают три
реальных разговора, а не эффект обрезки одного и того же текста. Один прогон
каждой стратегии — это наблюдение, а не статистика.

## Проверки

```bash
uv run day10/test_strategies.py        # сборка контекста каждой стратегии
uv run day10/test_facts.py             # разбор JSON, фиксированные ключи, запрет удаления
uv run day10/test_store_v4.py          # facts и ветки в SQLite
uv run day10/test_agent_strategies.py  # агент, служебный вызов, переключение
uv run day10/test_branches.py          # checkpoint, независимость веток
uv run day10/test_web.py               # HTTP, повтор request_id, Origin, ветки
```

Все шесть используют подставной API и временные базы, сети не трогают.

Живые прогоны запускаются отдельно и стоят денег:

```bash
uv run day10/run_strategies.py --env-file /путь/к/.env --all
uv run day10/analyze.py
uv run day10/quality.py
```

Бюджет $0.50, сохраняемый (`results/budget.db`), резерв берётся до каждого
платного вызова. Провайдер закреплён OpenInference FP8 без fallback — как в
дне 9 и по той же причине: подмена железа тихо испортила бы столбец расхода.
Временные 429/502/503/504 допускают три явных повтора с паузой 20 секунд;
повторы сохраняются в результате отдельным списком.
