# День 26 — локальная LLM

В исходном прогоне Qwen3 8B работала на этом Mac через Ollama; Python обращается напрямую к
`127.0.0.1:11434`, без прокси и облачного API. Установленные Ollama и веса
использованы повторно. Модель: `qwen3:8b`, 5,2 ГБ; машина: Apple M2, 16 ГБ RAM.

## Повторить

Если Ollama и модель ещё не установлены:

```sh
brew install ollama
```

В отдельном терминале запустить сервер (оставить работающим):

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 ollama serve
```

Если модель ещё не скачана, выполнить `ollama pull qwen3:8b`.
Скачивание требует интернета, последующая генерация выполняется локально.
Если сервер уже работает, второй экземпляр запускать не нужно.

```sh
ollama list
python3 day26/demo.py
ollama ps
```

Прямой HTTP-запрос:

```sh
curl http://127.0.0.1:11434/api/generate \
  -H 'Content-Type: application/json' \
  -d '{"model":"qwen3:8b","prompt":"Сколько будет 2+2?","think":false,"stream":false}'
```

Используется [официальный API генерации Ollama](https://docs.ollama.com/api/generate).
`demo.py` требует только стандартную библиотеку Python. Повторный прогон
перезаписывает `results/run.json` и занимает время на локальном GPU.

## Три запроса

1. Простой: арифметика, `17 + 25`.
2. Средний: различия `list` и `set`, пример удаления дубликатов.
3. Сложный: функция объединения интервалов, результат, сложность и пустой вход.

[Полные ответы и метрики](results/run.json), [вывод прогона](results/transcript.txt).
JSON содержит версию сервера, локальный каталог моделей, точные запросы,
ответы, длительности, число токенов и снимок загруженной модели `/api/ps`.
Получение ответа не означает общую проверку качества модели.

Проверено 08.10.2026 на macOS arm64 / Apple M2: три непустых законченных
ответа, без обрезания лимитом. Время HTTP-вызовов: 5,60 / 30,81 / 70,37 с;
выходные токены: 3 / 122 / 286. `/api/ps` подтвердил Qwen3 8B Q4_K_M,
контекст 4096, 5,94 ГБ в GPU-памяти; `ollama ps` показал `100% GPU`.
Простой ответ — `42`. В сложном ответе корректно указаны `[[1,6],[8,12]]`,
`O(n log n)` и пустой список, но **запрошенный код функции отсутствует**:
модель описала алгоритм. Этот недостаток не скрыт и повтором не заменён.
Проверка с физически отключённым интернетом не проводилась.

## Проба агентных задач: 8B и 9B

После исходной демонстрации добавлен [agent_probe.py](agent_probe.py): три
одинаковых сценария для `qwen3.5:9b-q4_K_M` и `qwen3:8b` через `/api/chat`.
Инструменты работают только с синтетическим каталогом: поиск товара,
зависимый расчёт заказа и повторный расчёт после ошибки недостаточного остатка.
Реальных заказов, shell-вызовов и внешних API у модели нет.

Для каждой задачи проверяются финальные JSON-поля, фактическое использование
инструментов и отсутствие недопустимых аргументов. В третьей задаче дополнительно
проверяется исправление запроса после ошибки инструмента. Самостоятельный
выбор стратегии для произвольной задачи этой проверкой не доказан.

Параметры одинаковы: `think=false`, контекст 8192, `temperature=0.2`, `seed=42`,
до 384 выходных токенов на ответ и до пяти шагов на сценарий. Выполняется по
одному прогону на модель: это небольшая проба, не статистический бенчмарк.
Инструменты симулируются, генерация выполняется реальными локальными моделями.
После проверки каждой модели её веса выгружаются из RAM; файлы на диске остаются.
При критическом давлении памяти перед следующим шагом прогон останавливается.

Пакет 9B потребовал обновить Ollama с 0.17.7 до 0.33.3. Сравнение обеих моделей
выполняется на обновлённом сервере. Исходные ответы и видео 8B сохранены.

```sh
ollama pull qwen3.5:9b-q4_K_M
python3 day26/agent_probe.py --output day26/results/agent-comparison/run02
```

Перед повтором `ollama ps` должен быть пуст; каталог результата должен быть новым.
[Состояние и ответы первого прогона](results/agent-comparison/run01/run.json),
[вывод](results/agent-comparison/run01-transcript.txt),
[журнал установки](results/agent-comparison/actions.jsonl).
Офлайн-проверки обвязки (7 проверок инструментов и 3 проверки отказа при
ответе без вызовов) сохранены отдельно в [offline-checks.json](results/agent-comparison/offline-checks.json).

Первый прогон завершён 08.10.2026: обе модели прошли 3/3 сценария,
сделали по 9 HTTP-вызовов и по 6 вызовов инструментов. Ни один ответ не обрезан
лимитом; каталог был синтетическим, все модельные ответы получены локально.

| Модель | Поиск | Зависимый расчёт | Исправление ошибки | Суммарно | Память модели по `/api/ps` |
|---|---:|---:|---:|---:|---:|
| Qwen3 8B Q4_K_M | 22,04 с | 17,55 с | 24,88 с | 64,47 с | 6,63 ГБ |
| Qwen3.5 9B Q4_K_M | 29,52 с | 31,96 с | 42,45 с | 103,92 с | 6,31 ГБ |

Время — сумма HTTP-вызовов, включая загрузку модели в первом сценарии;
выгрузка и сбор системных метрик в него не включены. Модели выдавали разное число
токенов: 231 у 8B и 294 у 9B. Память указана для текстовых задач с контекстом 8K,
это снимок модели, а не полный расход приложения и не измерение пика системы.
Изображения не тестировались. Скорость измерена одним последовательным прогоном
9B → 8B, без изоляции фоновых приложений и повторов.

На этой пробе преимущество 9B в качестве не выявлено: обе завершили задачи,
8B была быстрее. 9B доступна для дальнейших экспериментов, включая изображения.
Во время 9B зафиксировано повышенное давление памяти (`2`), во время 8B —
нормальное (`1`); после проверки — нормальное. Swap был уже занят до проверки
(4,72 ГБ), после прогона — 5,07 ГБ; весь swap нельзя приписывать моделям.

Сервер остаётся доступным на `127.0.0.1:11434` с отключённым облаком.
По завершении `ollama ps` и `/api/ps` пусты: обе модели выгружены из RAM.
Их файлы сохранены на диске (8B: 5,2 ГБ, 9B: 6,6 ГБ). Удаление файла
8B ради освобождения RAM не требуется. Интерактивный запуск новой модели:

```sh
ollama run qwen3.5:9b-q4_K_M
```

После разговора: `ollama stop qwen3.5:9b-q4_K_M` для выгрузки из памяти.
