# День 26 — живая запись

Для сдачи: `Day26-live.mp4` и `../Day26-code.zip`.

Видео записывает содержимое браузера во время трёх настоящих потоковых запросов
к Qwen3 8B через Ollama на этом Mac. Playwright записывает viewport Chromium;
запись не включает рабочий стол и системную рамку браузера. Скорость 1×,
без озвучки, вставки сохранённых ответов и ускорения ожидания.

## Повторить демонстрацию

При работающей Ollama и скачанной `qwen3:8b`:

```sh
python3 day26/live_demo.py
```

Открыть http://127.0.0.1:8066 и нажать три кнопки последовательно.
Python использует только стандартную библиотеку. Ответы и исходные потоковые
сообщения API сохраняются в новый каталог `day26/results/live-ДАТА-ВРЕМЯ/`.

Для автоматической записи нужны Python-пакет `playwright`, браузер Chromium
(`python3 -m playwright install chromium`) и `ffmpeg`:

```sh
python3 day26/video/record_live.py
```

Перед новой записью переместить прежний `video/live-capture` в архив:
скрипт намеренно отказывается перезаписывать этот каталог.

`Day26-demo.mp4` — предыдущая презентация сохранённых результатов,
оставлена как исторический артефакт. Для новой сдачи использовать `Day26-live.mp4`.

## Проверка записи 08.10.2026

Длительность 145,64 с (2:26), H.264, 1280×1000, без звука.
Три вызова: 6,76 / 26,15 / 74,78 с; все завершились `stop`.
Доказательства: `../results/live-20261008-153716/`.

В третьем ответе присутствует код. Пример из запроса и пустой вход прошли проверку.
Контрпример `[[1,2],[3,4]]` выявил ошибку: модель объединяет интервалы с зазором
из-за `current[0] <= last[1] + 1`. Ответ не редактировали; это ограничение качества
модели, а не сбой локального запуска. Проверка сохранена в `answer-review.json`.
