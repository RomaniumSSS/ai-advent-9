# Реализация Дня 15

- `day15/` — самостоятельная копия Дня 14 с серверным шлюзом переходов.
- `Agent.apply_task` принимает утверждение плана и финала только из сохранённого
  предложения текущей версии; ручной `submit_result` отклоняется. Успешный ход
  workflow проводит `execution → validation` через optimistic version check.
- `SqliteStore` хранит отказы отдельно от журнала успешных переходов; схема v6
  читает прежние базы v0–v5. Возврат с замечанием фиксируется атомарно.
- Явная команда перескочить этап в чате получает локальный отказ без model call.
  UI показывает этап, разрешённое действие и причины отклонённых попыток.
- После REVIEW граф доступных этапов выводится из единой таблицы переходов;
  даже допустимый следующий этап нельзя запустить прямой командой в чате.
- После DEMO `done` стал терминальным и для `pause`; UI показывает `done`
  вместо служебного статуса `active` и скрывает кнопку паузы.
- Добавлен `.github/workflows/day15.yml` для офлайн-проверок после push/на PR.
  Playwright добавлен в dev-зависимости для записи видео.
- После первого красного GitHub Actions run установка через `pip install -e .`
  заменена на `uv sync --no-dev --locked`: репозиторий содержит много плоских
  `dayNN/`, поэтому его нельзя автоматически собрать как один пакет.
- По диагностическому реальному прогону workflow теперь останавливается на
  `finish_reason=length`: обрезанный план/результат/проверка не меняет этап.
  Для живой проверки добавлен `live_validation.py` с реальным OpenRouter,
  закреплённым DeepInfra, лимитами вызовов и стоимости и durable трассой.

GitHub Actions не выполнялся; локальные проверки и браузерный прогон описаны
отдельно.
