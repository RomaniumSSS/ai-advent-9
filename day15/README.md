# День 15 — контролируемые переходы состояний

Самостоятельная копия накопительного агента Дня 14. Профиль, три слоя памяти,
инварианты, история и полуавтономный workflow сохранены. Новое правило: этап
меняет только сервер через разрешённое событие и проверку его источника.

```text
planning ── утверждён сохранённый план ──▶ execution
execution ── успешный ход workflow ─────▶ validation
validation ── принятие пользователем ──▶ done
validation ── замечание пользователя ──▶ execution
```

На `planning` и `validation` workflow сохраняет предложение с версией задачи.
Пользователь принимает именно это предложение. Произвольный текст в ручном
`/api/task/action` не заменяет план или проверку. Ручной `submit_result`
отклоняется: переход в `validation` возникает только после успешного model turn
в workflow и повторной проверки версии/status перед записью в SQLite.

Прямая команда сменить этап в чате, включая «перейди в execution» и
«перейди сразу в validation», получает локальный отказ без вызова модели.
Отказ сохраняется в отдельном `transition_denials`; этап,
версия и предложение не меняются. Пауза сохраняет этап и предложение, а после
нового экземпляра агента `resume` продолжает с той же точки. Проверка может
вернуть задачу из `validation` в `execution` с замечанием. `done` терминален:
новые переходы и пауза запрещены.

## Локальный запуск

```bash
uv run python day15/web.py --db /tmp/day15-demo.db --port 8045
# http://127.0.0.1:8045
uv run python day15/cli.py --offline --db /tmp/day15-cli.db
```

Без `--env-file` используется офлайн-клиент. Он проверяет путь приложения и
переходы, но не качество генерации реального провайдера.

Длинный реальный прогон запускается отдельно с файлом ключа:

```bash
uv run --no-dev python day15/live_validation.py \
  --env-file /путь/к/секретному/openrouter.env \
  --output day15/results/live-run-01
```

Скрипт использует настоящий OpenRouter и модель DeepSeek V4 Flash через
DeepInfra без fallback и повторов SDK. Лимиты: 16 вызовов и $0.02 по
фактически полученному `usage.cost`; результат и ответы сохраняются в
`report.json`, локальная SQLite не добавляется в Git. Для повторного запуска
нужен новый каталог вывода.

Видео пишется командой `uv run python day15/demo/record.py`, пока локальная
панель запущена на `127.0.0.1:8045`. Playwright входит в dev-зависимости;
скрипт использует локальный Chrome, а при его отсутствии — браузер Playwright.

## Проверки

```bash
uv run python day15/test_controlled_transitions.py
uv run python day15/test_task_state.py
uv run python day15/test_workflow_loop.py
uv run python day15/test_invariants.py
uv run python day15/test_web.py
node --check day15/web/app.js
uv run python -m compileall -q day15
python3 experiments/day15-codex-machine/machine.py check
```

CI конфигурация — `.github/workflows/day15.yml`. Она запускает эти офлайн
проверки после push и на pull request. Зелёный локальный прогон не означает,
что GitHub Actions уже выполнился.

Реальный прогон: [отчёт](results/live-run-01/report.md) и
[метаданные вызовов](results/live-run-01/report.json). Он проверяет три
текстовые задачи, 10+ реальных вызовов, запрещённые переходы, доработку,
паузу и восстановление из SQLite до финального принятия.

Граница доказательства: текстовый ответ модели сохраняется как результат
текстовой задачи. Он не подтверждает фактическую публикацию, создание файла
или другое внешнее действие без отдельного инструмента и проверяемого артефакта.
