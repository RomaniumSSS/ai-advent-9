# Личный наставник — локальный прототип

Текущая версия: личный прототип и самостоятельный снимок [Day24](../day24/README.md). Генератор — `deepseek/deepseek-v4.1-flash` через OpenRouter, закреплённый провайдер `deepinfra/fp8`, без автоматической подмены. Эмбеддер — `qwen3-embedding:0.6b` на VPS. Модель генерации в рамках этой синхронизации не менялась.

Из корня репозитория:

```sh
python3 -m pip install -r mentor/requirements.txt
python3 mentor/import_history.py
python3 mentor/web.py --env-file /secure/.env
```

Открыть http://127.0.0.1:8050. Нужны SSH alias `crm-agent`, действующий Structure-индекс и локальный Ollama на VPS. Сервер слушает только loopback. История, снимки чанков и обратная связь находятся в игнорируемом `mentor/private/` (каталог 700, JSON 600). Остановка — Ctrl+C. Для нового вопроса нужна самостоятельная формулировка: история не передаётся модели.

Поиск работает без облачного разрешения. 03.10 пользователь разрешил произвольные вопросы и выбранные чанки всего **текущего** корпуса для проверки: DeepSeek через OpenRouter/DeepInfra, общий лимит $0.10, без повторов. Это новое разрешение, не разрешение Day24. Оно хранит конкретные 663 документа и fingerprint идентичности индекса; изменение снимка блокирует генерацию. Исторические 10 результатов Day24 можно просмотреть без повторного вызова. В них сохранены старые оценки и ошибки Q05–Q07; они не измеряют качество новой версии.

Исходная база — Day24 (`be94bf73db06bdbc1ed371da031ba40e1f5d73ea`, provenance в модулях). После согласованной полировки: K20→5, mixed 0.8/0.2, обычный threshold 0.35, rewrite=false; явно запрошенные условия дня проходят по metadata независимо от threshold, сохраняя область/контекстные лимиты. Календарная дата фильтрует сообщения до topK; год определяется по архиву, неоднозначность требует уточнения. «Последние дни» — 7 дней от конца архива, не live. Сообщения передаются с автором/датой/ID и точными offsets исходного чанка. Модули теперь развивают базу Day24, а не являются точными копиями. Runtime imports из опубликованных дней отсутствуют. Индекс открывается read-only с проверкой поколения и идентичности эмбеддера; SSH возвращает только трассу и снимки кандидатов.

Обычный интерфейс ищет по всему текущему корпусу; публичного пункта в переключателе больше нет. Под ответом сразу показаны «Источники ответа» с source/section/chunk_id и отдельные «Цитаты»; полный чанк открывается кнопкой.

Служебная публичная область — явно перечисленный `assignment:18`, условие из прежней публичной записи VIDEO01/Q04. Это не все документы типа assignment. Фильтр применяется перед поиском кандидатов; он может дать пустой контекст на пороге .35. Пустая выдача не доказывает отсутствие факта в корпусе.

Разрешение находится в локальном `private/authorization.json`: `approved`, `question_policy` (`arbitrary`), конкретные `document_ids`, `identity_sha256`, `scopes`, `model` (`deepseek/deepseek-v4.1-flash`), `provider` (`deepinfra/fp8`), общий `budget` (0.10), `retries` (0). Для ограниченного разрешения также поддерживаются точные `questions`. Новые разрешения не создавайте без решения пользователя. Перед каждым резервом сервер сверяет цены официального OpenRouter API. Резерв общий для всех результатов в `private/ledger.json`; неизвестный исход/стоимость блокируют следующие вызовы, автоматических повторов нет.

Ключ читает только сервер из указанного защищённого `.env` (опция `--env-file`); значения не попадают в браузер или разрешение. Альтернативно используется переменная `OPENROUTER_API_KEY`. В интерфейсе видны действующий режим и расход; поиск доступен даже когда генерация заблокирована. Передача чанков обозначается отдельно от выбора; при неизвестном исходе запроса факт доставки не подтверждается.

Для восстановления неизвестного расхода нужна отдельная проверка фактического исхода; готовой кнопки списания неизвестного расхода в v1 нет. При сбое финальной записи расхода полученный проверенный ответ сохраняется, а ошибка журнала явно видна; следующий вызов блокируется по оставшемуся резерву.

При сбое сохранения уже полученный ответ показывается как несохранённый. После остановки незавершённый запрос помечается прерванным либо с неизвестным платным исходом. Повтор ID с тем же содержимым возвращает прежний результат; изменение вопроса с тем же ID запрещено. Одновременно выполняется один вопрос, включая разные вкладки/процессы.

Проверки без сети/облака:

```sh

python3 mentor/test_quality.py
python3 mentor/test_public.py
```

## Проверка условий и полировка

`python3 mentor/check_assignments.py` проверяет read-only реальный индекс для всех 24 условий через локальный Ollama на VPS; платной генерации нет. `live_regression.py` — адресные уже диагностированные вопросы через обычное приложение, требует действующего разрешения, использует общий ledger и постоянные IDs для защиты от повторного вызова. Не запускайте его для публикации: часть вопросов/источников приватна. Старые ответы не переписываются.

Единственная внешняя Markdown JSON-обёртка допустима, raw/normalization сохраняются; содержимое не исправляется. Полученный неполный ответ с известным расходом — непроверенный результат, не неизвестный сетевой исход. Лимит вывода 2048 токенов согласован с расчётом резерва. Публичная запись ограничена служебной областью assignment:18; публикация приватной переписки не разрешена.

## Служебный запуск для публичной записи

```sh
python3 mentor/web.py --port 8052 --public-only --data-dir /absolute/path/to/mentor/private
```

Тот же общий бюджет и разрешение; отдельный бюджет не создаётся. Сервер ограничивает область assignment:18 и защищает history/get/feedback от приватных результатов. Плашка видна постоянно. Два примера только заполняют вопрос; поиск запускается кнопкой отправки. Диагностика показывает настоящие cosine/mixed и решение для реальных кандидатов, полная трасса сворачивается отдельно. Не публикуйте обычный приватный режим/историю или содержание произвольных вопросов без соответствующего разрешения.
