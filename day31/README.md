# Day31 — DevHelper

Браузерный помощник и CLI `/help <вопрос>` объясняют знакомый Git MCP из Day17.
Это самостоятельный модуль: старый день не импортируется и не изменяется.

## Устройство

Код ищет фрагменты README и docs через SQLite FTS5, затем вызывает настоящий
stdio MCP `git_context` и передаёт источники и Git-контекст модели одним запросом.
Модель получает провайдер-совместимую wire JSON Schema и пишет ответ с
идентификаторами источников; код применяет полную локальную JSON Schema и
проверяет эти ссылки. Только uniqueItems опущен в wire из-за подтверждённого
отказа DeepInfra; локально дубли source_ids по-прежнему запрещены.
Валидные inline-ID из текста добавляются в source_ids без изменения текста/статуса;
любой неизвестный ID приводит к ошибке. Поиск лексический, без embeddings:
небольшой RU/API-словарь расширяет технические термины, но перефразировки вне
словаря могут не найти материал.
Проверка ссылки доказывает существование фрагмента, но не смысловую верность ответа.

## Запуск

Из корня репозитория с Python 3.12 и установленным существующим lock:

```bash
uv sync --frozen
uv run python -m day31.cli '/help Как устроен Git MCP?'
uv run python -m day31.web
```

Браузер: http://127.0.0.1:8071. Без `--live` работает явно отмеченный офлайн-режим:
извлечение фрагмента вместо генерации, но с настоящим MCP. Облачные команды и
лимит расходов описаны в [docs/run.md](docs/run.md). Облачная модель —
`deepseek/deepseek-v4.1-flash` через OpenRouter, только `deepinfra/fp8`, без fallback
и retry; reasoning выключен. Платные запросы требуют разрешённого бюджета.

## Объект знаний

[docs/git-mcp.md](docs/git-mcp.md) — документированный снимок Day17 из commit cf3603e.
Его `get_recent_commits` читает историю; новый Day31 `git_context` читает ветку.
Это разные инструменты. История, FSM и чат Day17 в Day31 не переносятся.
[docs/provenance.md](docs/provenance.md) фиксирует исходные файлы и SHA256.

## Ограничения

Только чтение документов README/docs и Git. Модель не выбирает инструменты,
не задаёт пути и не выполняет команды. Каждый вопрос независим, истории чата нет.
Пустой поиск возвращает честное «нет данных». Ошибка MCP или модели — ошибка,
а не успешный ответ. Ключ OPENROUTER_API_KEY остаётся в серверном процессе.

Финальный профиль — DeepSeek V4.1 Flash/DeepInfra, вывод до 1600 токенов,
reasoning выключен. В [pilot после wire-fix](results/compare-compatible-pilot-20261016/summary.json)
получены три ответа с валидным внешним JSON и корректными source ID. Однако T3
содержит псевдо-JSON вместо валидного JSON-примера: source guards не проверяют
смысл и формат примера внутри текста. Это ограничение сохранено явно.

[Первый pilot трёх моделей](results/compare-models-pilot-20261016/summary.json)
завершился девятью API/response-ошибками; после wire-fix GLM5.3 получил обрыв по
length и HTTP429, Qwen — HTTP404. Недоступные ответы не дают рейтинга качества.
Исторически GLM4.7 также давал неполный код и неверное type=func при формально
валидном внешнем JSON. Автоматического выбора модели или fallback нет.

## Проверки

```bash
uv run python -m unittest discover -s day31/tests -v
```

Офлайн-проверки с fake provider отдельно проверяют контракт. Тесты MCP запускают
настоящий stdio-сервер и Git во временном репозитории. Реальная облачная генерация,
смысловая оценка ответов и видео требуют отдельного разрешённого бюджета.
