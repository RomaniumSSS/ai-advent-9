## Проверенные границы

- `ProviderProfile` валидирует поля, фиксируется frozen dataclass и копирует
  reasoning в MappingProxyType. Внешнее изменение исходного словаря reasoning
  не меняет профиль. Общий builder используется и планом, и реальным адаптером;
  schema копируется в запрос. Профиль задаёт model/route, тарифные потолки,
  output cap и reasoning явно, без автоматического выбора кандидата.
- Preflight проверяет активный точный tag, поддержку всех используемых
  параметров и тариф без скидки относительно потолков конкретного профиля.
  В запросе закреплён единственный маршрут, fallback выключен,
  require_parameters включён, SDK retries=0. Финальный content и счётчик
  reasoning tokens сохраняются; отдельный скрытый текст reasoning не читается
  и не записывается. Различающиеся режимы reasoning/output cap не скрыты.
- CLI требует существующий общий ledger по фиксированному пути и лимит $0.50;
  новый путь или сброс бюджета не предлагаются. Вся серия из девяти запросов
  проходит preflight и совокупный бюджетный расчёт **до** запуска worker.
  Этот precheck не является резервом серии: каждый API-вызов отдельно выполняет
  прежний атомарный SQLite reserve. При конкурентном расходе резерв может
  отказать; серия получает partial_budget, новые вопросы прекращаются,
  уже зарезервированные вызовы завершаются и сохраняются. Обхода ledger нет.
- ThreadPoolExecutor содержит три worker, по одному на профиль. Внутри каждого
  Q6/P1/T3 выполняются последовательно, provider/client независимы. Общая SQLite
  connection между потоками не используется. Файлы разделены по профилям,
  журнал защищён lock, summary собирается главным потоком после workers.
- Для каждого вопроса retrieval и MCP читаются один раз до workers.
  SourceChunk неизменяемы, Git-контекст копируется; все кандидаты получают
  одинаковые messages, SYSTEM и schema. Проверка fingerprint корпуса выявляет
  изменение во время подготовки. Runner не читает gold-ответы. Фактическая
  повторная сборка запроса провайдером использует тот же builder и тот же
  snapshot, который сохранён в plan и record.
- Режим по умолчанию — plan: возврат происходит до создания clients и вызова
  модели. Бесплатные metadata GET и реальные локальные retrieval/MCP не
  выдаются за inference. Отдельный execute нужен явно; ошибки не запускают
  повторные запросы.
