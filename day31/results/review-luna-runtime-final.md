## Findings

Существенных замечаний не найдено. Обработчик валидирует JSON и непустой текст, проверяет все объявленные и распознанные inline-ID по множеству реально найденных фрагментов **до объединения**, затем сохраняет порядок declared IDs, добавляет отсутствующие валидные inline IDs по порядку текста, удаляет повторы и повторно валидирует JSON Schema. Поэтому неизвестные ID не теряются при нормализации; `ok` без источника отклоняется. Текст и status не переписываются, trace отмечает детерминированные добавления. Ограничение schema на восемь уникальных ID действует и после объединения.

Retrieval сохраняет исходные термины, ограничивает выдачу 24 исходными и 16 уникальными дополнительными терминами. Слова действия расширяются только при наличии MCP/Day17/server/tool контекста; общие слова «данные», «доступны», «понимает», «передать» не становятся синонимами. В коде нет привязки к gold-вопросам или повышающего веса для конкретного файла. Свежесть корпуса остаётся основана на fingerprint содержимого allowlist-файлов, ID фрагмента — на пути, строках и хеше текста.

Корпусный факт о `model_tools()` соответствует Day17: discovery-поля `name`, `description`, `input_schema` превращаются в function tool с `parameters=input_schema`; `_allowed_tool` проверяет разрешённое имя и JSON Schema, а `parse_arguments` валидирует аргументы. Граница Day17 snapshot / Day31 runtime описана явно. Предыдущее замечание к примеру запуска закрыто: документация использует `uv run --frozen python ...`.
