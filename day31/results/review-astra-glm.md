## Основания одобрения

- `provider.py:12–16`: модель `z-ai/glm-4.7-flash`, маршрут `venice/fp8`, предел
  вывода 1600 и резервные тарифы `$0.06/M` input / `$0.40/M` output согласованы
  с SPEC и сохранённым публичным снимком выбранного endpoint.
- `provider.py:49–72`: preflight выбирает активный точный tag, проверяет
  reasoning, response_format, structured_outputs, max_tokens и temperature.
  Другой tag, неактивность, нехватка параметров, недоступные/невалидные данные
  или тариф выше резерва останавливают запуск. Небольшой допуск `1e-10` в
  сравнении тарифов устраняет погрешность float, не является значимой скидкой.
- `provider.py:149–178`: один запрос с strict JSON Schema,
  `reasoning={"enabled":false}`, `provider.only=["venice/fp8"]`,
  `allow_fallbacks=false`, `require_parameters=true`; SDK `max_retries=0`.
  Вызов tools моделью не добавлен. Ошибки, неполное завершение и пустой ответ
  не превращаются в успешный результат. Прежняя последующая проверка JSON и
  source IDs обработчиком не изменена.
- Ledger по-прежнему резервирует до транспорта, сохраняет ненулевую сумму
  при неизвестной стоимости/неоднозначном сбое и не повторяет запрос
  автоматически. Замена констант тарифа используется именно при резерве,
  а не только в документации; меньший тариф не сбрасывает прошлые записи ledger.
- Самостоятельно проверена публичная документация: полный slug варианта можно
  использовать для выбора endpoint, `only` ограничивает провайдеров,
  `require_parameters` запрещает маршрутизацию к неподдерживающему параметры
  провайдеру. [OpenRouter: Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection#targeting-specific-provider-endpoints).
  Поле `reasoning.enabled=false` документировано как выключение reasoning;
  снимок выбранной модели отмечает reasoning как необязательный.
  [OpenRouter: Reasoning Tokens](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
  Это подтверждает форму запроса, но не фактическое поведение ещё не вызванного
  GLM/Venice.
