## Текст задания

> Реализуйте простого агента, который:
> - принимает запрос пользователя
> - отправляет его в LLM через API
> - получает ответ
> - выводит результат в вашем интерфейсе
>
> (простой чат, CLI или web, запросы через HTTP-клиент)
>
> **Важно:**
> - агент должен быть отдельной сущностью, а не просто один вызов API
> - логика запроса и ответа должна быть инкапсулирована в агенте
>
> **Результат:** агент принимает запрос и корректно вызывает LLM через API
> **Формат:** видео + код

Текст почти дословно повторяет день 1, и в чате это заметили. Всё отличие — в слове
«инкапсулирована», поэтому уточнения ниже важнее самого задания.

## Что получилось

Коробка — `agent.py`: `AgentConfig` (модель, роль, температура, `max_tokens`) и `Agent`
с собственной историей. Наружу торчит одна дверь: `ask(текст) -> Reply`. Сборка запроса,
вызов, разбор ответа, токены и деньги — внутри.

Два решения, которые определяют всё остальное:

- **состояние в полях объекта, клиент — общий на процесс.** История и конфиг у каждого
  агента свои, иначе второй агент молча затирал бы первого. HTTP-клиент, наоборот, один:
  он разговора не помнит, а сто клиентов означали бы сто пулов соединений впустую.
- **системный промпт не хранится в истории**, а подставляется при каждой сборке запроса.
  Иначе `reset()` стирал бы роль, а будущая обрезка контекста выбрасывала бы её первой —
  роль же самая старая запись в стеке.

Проверено живым прогоном на gpt-oss-20b: левый агент на вопрос «как меня зовут» отвечает
«Твое имя Роман», правый в том же процессе — «Извини, я не знаю». Три вызова стоили
$0.000045.

**Замеренное, чего не ждали.** Тот же правый агент при `max_tokens=100` вернул пустой
ответ с `finish_reason=length`: 100 токенов целиком ушли в скрытые рассуждения, до видимого
текста дело не дошло. Отсюда `finish_reason` и пометка об обрыве в строке дебага —
без них «модель промолчала» и «ответ обрезали» выглядят одинаково.
