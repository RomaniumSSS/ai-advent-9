# Проверка дня 8 — 09.09.2026

## Итог по критериям

Код считает текущий запрос как `prompt_tokens`, накопленный расход входа как
сумму `prompt_tokens`, ответ как `completion_tokens`. Проверены короткий диалог
(2 хода), длинный (12 ходов), запрос с историей за реальным окном модели и
восстановление после отказа. Пустой оплаченный ответ учитывается после перезапуска.
После проверки подготовлена [немая запись кода и панели](demo/README.md) с новыми API-вызовами.
Видео и код доступны локально; публикации и сдачи не было.

## Среда и границы

- macOS, локальный `uv`, Python 3.12.12, зависимости из `uv.lock`.
- Настоящий OpenRouter API, `openai/gpt-oss-20b`. В тестовом клиенте провайдер
  закреплён явно; конфиг обычного чата не менялся.
- Каталог endpoint получен перед каждым прогоном: окно DeepInfra и CoreWeave —
  131072 токена. Снимки каталога сохранены внутри JSON-отчётов.
- Только временные SQLite-базы и синтетические сообщения. Пользовательская база не открывалась.
- Длинный диалог построен добавлением одинаковых порций учебных заметок; это
  проверка роста контекста, не оценка качества ответов на разнообразные задачи.
- `max_tokens=1500`, для пустого ответа — 1. `transforms=[]`, автоматические
  повторы SDK выключены. Тестовый клиент ограничивает маршрутизацию ценой
  $0.10/$0.50 за миллион входных/выходных токенов и резервирует бюджет по байтам
  входа плюс потолку ответа. Полный прогон имеет бюджет $0.10.
- Поля usage описаны в [документации OpenRouter](https://openrouter.ai/docs/cookbook/administration/usage-accounting),
  единицы max_price — в [документации маршрутизации](https://openrouter.ai/docs/guides/routing/provider-selection#max-price).

## Что не прошло и что исправлено

1. **Потеря расхода пустого ответа.** [Исходный реальный тест](results/empty-before-fix.json):
   `prompt_tokens=128`, `completion_tokens=1`, `usage.cost=$0.00000660`, а итог
   сессии — NULL. Исправлено отдельной таблицей `calls`: пустой ответ не попадает
   в переписку, но расход сохраняется. После исправления CoreWeave вернул
   123 → 1 и $0.00000382; эти числа восстановились из базы точно.
2. **DeepInfra недоступен для обычного диалога.** [Первый полный прогон](results/live-20260909T160052Z.json)
   получил 429 `engine_overloaded`. Его нельзя считать успешной проверкой диалога.
   При этом большой запрос получил настоящий 400 `context_length_exceeded`:
   135258 входных токенов, окно 131072. Для дальнейшего диалога явно выбран CoreWeave.
3. **Слишком узкая проверка текста ошибки.** [Прогон CoreWeave](results/live-20260909T160220Z.json)
   прошёл 11 из 12 исходных проверок. При переполнении сервер вернул HTTP 400:
   `max_tokens must be at least 1, got -12566`, хотя отправлялось +1500.
   Это наблюдённое поведение провайдера при переполнении, не ошибка локального
   параметра. В тест добавлено распознавание этого конкретного варианта при
   условии, что оценка входа превышает реальное окно и отправленный лимит положителен.
   Исходный отчёт с неуспешной проверкой оставлен без подмены результата.
4. **Отсутствующее usage выдавалось за ноль.** В `/growth` и итогах теперь `?`;
   неполная сумма не выдаётся за полный расход. Нулевой замер из API остаётся нулём.
   Это проверено отдельно подставным клиентом, не выдаётся за реальный пропуск usage.
5. Локальный токенизатор принимал строку `<|endoftext|>` за запрещённый маркер.
   Теперь она считается обычным текстом пользователя; регрессия проверена офлайн.

## Переполнение и восстановление

[Повтор затронутых сценариев](results/live-20260909T160329Z.json) — **11/11**:

- короткий диалог сохраняется после создания нового агента;
- сумма входов совпадает с API;
- пустой оплаченный ответ учтён после повторного открытия базы;
- большой запрос отправлен в API с положительным `max_tokens`, получен HTTP 400;
- тип отказа CoreWeave — `negative_output_reserve`;
- история в памяти и SQLite не изменилась;
- локальная защита на таком же большом запросе не вызывает API;
- после отказа короткий вопрос проходит, модель вспоминает `СЕВЕР-824`.

Ошибка без usage не доказывает нулевое списание: JSON хранит неизвестные поля
как null. Сумма **известных** `usage.cost` всех этих проверок, включая исходную
проверку дефекта, — **$0.00185542**. Для запросов с ошибкой usage не получен,
окончательный биллинг по ним отдельно не сверялся.

## Офлайн-регрессии и воспроизведение

```bash
uv run day08/test_agent.py       # 31/31
uv run day08/test_accounting.py  # 8/8

# Платно, нужен OPENROUTER_API_KEY в окружении или .env:
uv run day08/test_live.py
uv run day08/test_live.py --overflow-only
# Другой доступный endpoint выбирается явно:
uv run day08/test_live.py --provider deepinfra
```

Скрипт получает актуальное окно и создаёт новый JSON в `day08/results/`.
Для ключа из другого checkout можно передать `--env-file /путь/к/.env`.
Ключ и заголовки авторизации в отчёт не пишутся.

Офлайн-проверки покрывают миграцию v1 → v2 без повторного учёта, отсутствие usage,
пустые ответы, сбои записи, изоляцию сессий и очистку. Старая база пользователя
не мигрировалась в этой проверке; старые несохранённые расходы восстановить нельзя.
Позднее при записи панели проверены четыре настоящих API-вызова, накопленный
расход после обновления страницы и локальный отказ. Добавлена строка общей
суммы расхода. Видео проверено на читаемость, декодирование и отсутствие аудио.
