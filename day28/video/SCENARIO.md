# Day28 — сценарий живого локального RAG

Статус: сценарий подтверждён вместе со [SPEC](../SPEC.md) пользователем 09.10.2026.
Требования сценария: Astra (`gpt-6-astra`, high), 09.10.2026. Скрипт и
финальная адаптация к готовому UI — Sol / Sonnet. Длительность определяется
измерениями dry run; фиксированное обещание числа минут не задаётся.

## Начальное состояние

На Mac готовы точный локальный снимок Structure и обе локальные модели.
Приложение открыто на `http://127.0.0.1:8068`, scope `public`; видны модель,
локальный retrieval и generation. Новый отдельный каталог прогона, без прошлых
ответов на экране. Облако не вызывается; очередь других LLM/записей свободна.
Индекс содержит приватные discussion-материалы, но фильтр допускает в кадр,
ответ и API только assignment-документы. Секреты и приватные receipts не открываются.

## Видимые действия и доказательства

1. **Локальное состояние.** Показать адрес приложения, имя генератора/эмбеддера,
   сокращённую identity прежнего индекса и scope public. Пояснить, что индекс
   перенесён без пересчёта; получение моделей и снимка было этапом подготовки.
2. **Прямой вопрос.** Ввести «Что требуется сделать в задании дня 18?» и отправить.
   Дождаться настоящего конечного статуса по request ID, показать новый ответ,
   источник assignment18 и дословную цитату. Видны времена retrieval/generation/всего.
   Точная ожидаемая информация берётся из assignment18 при фиксации набора.
3. **Составной вопрос.** Ввести «Чем отличаются требования заданий дней 19 и 20?»
   Дождаться нового ответа, раскрыть фрагменты двух assignment-документов.
   Оценить полноту по фактическому тексту заданий, показать ограничение, если
   часть вопроса не раскрыта в контексте.
4. **Неизвестный факт.** Спросить «Какой точный бюджет в евро установлен для
   выполнения задания дня 18?» Перед фиксацией набора проверить, что такого факта
   нет в assignment18; при наличии выбрать другой отсутствующий факт и записать замену.
   Показать честное отсутствие сведений без выдуманной суммы и источника.
5. **Стабильность и сравнение с облаком.** Показать краткий итог ранее завершённой
   оценки 3×2, явно подписанный её отдельным run ID; три новых запроса записи
   не выдавать за весь оценочный набор. Показать сводку качества по replay: исходные
   messages идентичны для пары, облачные ответы исторические, локальные получены
   в Day28. В кадре только assignment-кейс или обезличенные агрегаты, без discussion
   и приватных ответов. Исторические времена не показывать как свежий benchmark.
6. **Итог результата.** Показать реальные времена записанных запросов и известные
   ограничения качества. Указаны отдельные статусы «код проверен», «видео проверяется»
   и «не опубликовано»; пользовательская сдача не утверждается.

## Автоматизация и проверка

`run_demo.py` выполняет одинаковые действия в dry run и record. Каждый из этих
прогонов создаёт три **новых** локальных запроса; dry run не воспроизводится
вместо записи. Скрипт ждёт статус конкретного request ID и проверяет фактический
ответ/источники, а не таймер или собственное эхо. Если вместо ожидаемого ответа
получена ошибка/необоснованный факт, сохранить evidence и устранить причину либо
зафиксировать незавершённый обязательный шаг; успешный дубль не выдумывать.

Записывается настоящий viewport приложения с ожиданием локальной модели.
Прежние ролики сохраняются; новый дубль имеет новый путь. Ускорение/монтаж
ожидания — только по выбору пользователя с сохранением исходника и длительностей.
После записи проверить длительность/размер ffprobe, вручную прочитать начало,
каждый ключевой ответ и конец; сверить request IDs/времена/число запросов с журналом.
Открытие файла и разрешение кадра не заменяют проверку читаемости и приватности.
