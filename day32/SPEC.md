**Результат.** Локальный reviewer замечает настоящий PR/новый head SHA,
автоматически анализирует изменения и показывает текст ревью в небольшом браузерном UI.
Объект — небольшой Git-инструмент по идее Day17, самостоятельная реализация
в target/ с provenance. Старые дни и готовность Day31 не являются runtime-зависимостями.

**Учебный предмет.** Небольшой самостоятельный Git-инструмент в `target/` на основе
идеи Day17 с provenance; без зависимости от runtime старого дня. Он возвращает последние
коммиты и принимает целое `limit` от 1 до 10 включительно. Подготовленный тестовый diff
меняет верхнюю границу на строгую: допустимое значение 10 ошибочно отклоняется.
Ожидаемое замечание — нарушение документированного диапазона с точной строкой и источником.
Для учебного объекта достаточно Git-функции и её документации, новый MCP-сервер не нужен.

**Эксперимент.** Один и тот же снимок можно отдельно обработать в режимах `diff`,
`files` (diff+изменённые файлы), `rag` (diff+файлы+docs/code retrieval). Сохранять фактические
входы/ответы/стоимость отдельно, не считать улучшение RAG заранее доказанным.
Watcher использует `rag`; эксперимент запускается явно и имеет отдельный mode в dedupe.
Offline provider явно маркируется fixture, не имитирует доказательство качества Qwen.

**Триггер.** Watcher опрашивает реальный GitHub PR настроенного репозитория.
Новое сочетание PR/base/head запускает обработку; повтор того же снимка не вызывает
повторную генерацию. Это polling, не GitHub Actions. CLI/fixtures — только отладка.

**Пайплайн.** PR → закреплённые SHA → merge-base diff, изменённые файлы и их содержимое →
FTS5 RAG по документации **и коду** соответствующего снимка → один запрос модели →
проверка ссылок/строк → отчёт. Read-only Git/gh, отдельный cache; код/тесты PR не выполняются.
Слишком большой/неполный набор данных получает статус limited, а не полное ревью.
UI показывает стадии, diff, файлы, найденные источники docs/code, точный модельный контекст,
результат и доступные время/стоимость. Проверка ссылок не доказывает смысловую точность.

**Отчёт.** PR/SHA; findings с категорией bug/architecture/recommendation, файлом,
проверяемой строкой, основанием и предложением. Категория может быть пустой:
дефекты не придумываются ради трёх разделов. Источники и ошибки доступны в UI.

**Приёмка.** Создание/обновление настоящего PR запускает review без ручного запуска
анализа. Неизменившийся PR не вызывает новую генерацию; новый SHA получает новый
отчёт. В контексте присутствуют diff, файлы, найденные docs и code. Ссылки относятся
к зафиксированному снимку. На подготовленной маленькой регрессии оценивается
конкретное замечание; промах модели не объявляется успехом качества.
Сбой/лимит бюджета сохраняются без автоматического платного повтора.

**Проверки.** Unit/integration fixtures, обработка dedupe/смены SHA/ошибок/лимитов,
Luna → исправления Sol → Astra; отдельно реальный PR-trigger и реальная модель.
Код+живая запись по [сценарию](video/SCENARIO.md), RESULT/RELEASE_NOTES.

**Среда и границы.** Python/существующий lock, localhost127.0.0.1:8072, отдельные
SQLite/данные. OpenRouter, закреплённый model/provider, без fallback/retry.
Для Day32 пользователь выбрал Qwen. Технический профиль — проверенный в Day31
`qwen/qwen3.8-max-0902`, только `alibaba/us-east-1`, reasoning low, output4096.
Каталог endpoint проверен read-only; live ещё не проверен. Лимит Day32 $0.50 отдельно подтверждён пользователем; общий ledger
`day32/.runtime/live/state.sqlite3` используется во всех live-прогонах. Старые qwen3.8-27b и
пакет$1 на31+32 были предложением, не утверждённым бюджетом. ЛимитDay31 не переносить.
При первоначальной подготовке PR не было; актуальное состояние проверить заново.
Fixture не заменяет обязательный live-trigger.
Разрешены baseline/regression commit+push и учебный PR в baseline;
не делать merge, не отправлять комментарии и не менять secrets автоматически.

**Расширение по просьбе пользователя.** Много разных офлайн-проверок и более длинное
живое видео. Вживую: верхняя граница, исправление, bool/type, игнорирование limit,
инъекция инструкций в PR, сравнение diff/files/rag и dedupe/новый SHA.
Отдельно, явно SIMULATED: timeout, невалидный/усечённый ответ, неверные ссылки,
превышение лимитов и budget_blocked. Сохранять ожидания и фактические исходы;
не выдавать заранее подготовленные ситуации за случайные или смоделированные отказы
за сбой настоящего провайдера. Длительность видео определяется ходом сценария и
паузами чтения, ориентир несколько минут вместо короткого ролика.
