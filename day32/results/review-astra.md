## История: первоначальное замечание (исправлено)

**P2 — day32/review.py:203–205.** Проверка finding использует полный blob
snapshot и не проверяет присутствие строки в фактически отправленном контексте.
Поэтому в diff-only, а также после удаления файлов из prompt из-за лимита,
модель может сослаться на не показанную ей строку и получить статус validated.
Это расходится с SYSTEM «Ссылайся только на переданные строки файлов» и
назначением локальной проверки источников. Это механическая ошибка проверки,
а не требование автоматически доказывать смысловую правильность замечания.

Независимое воспроизведение на настоящем временном Git: long.py содержит100
строк value_N = N; новый commit меняет только строку50. В context(diff)
files={} и sources=[], diff содержит hunk47..53. Finding head:long.py:1 с
пустыми source_ids принимается validate(), хотя строка1 не передавалась.
Вывод проверки: `line1 sent: False files: 0 sources: 0`, затем accepted finding.

Минимальное исправление: кроме существования строки в закреплённом blob
проверять допустимую строку по переданным data.files, диапазонам data.sources
и разобранным координатам diff hunks (head/merge_base, +/−/context).
Не ограничивать finding только изменёнными строками: любая переданная строка
изменённого файла допустима. Нужны негативные проверки unseen diff-only line
и строки удалённого из prompt файла, позитивные — hunk/context и полный
переданный файл вне hunk. После исправления требуется повторный просмотр.
