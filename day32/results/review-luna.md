## Открытое замечание

🟡 **[WARNING]** `day32/review.py:92` — слишком большой Git tree полностью прерывает snapshot вместо сохранения ограниченного отчёта со статусом `limited`. `git()` выбрасывает `ValueError`, когда вывод `ls-tree -r -z` превышает 200 000 байт; этот вызов не перехвачен. По той же причине большой список имён изменений может прервать построение на `review.py:77–78` при лимите 100 000 байт. В обоих случаях исключение уходит из `GitSnapshot.build()` и CLI пишет только `poll_error`; запись отчёта/dedupe со статусом `limited` не создаётся. Это расходится со SPEC: слишком большой или неполный набор данных должен получить `limited`. **Воспроизведение:** подтвердил на временном локальном Git-репозитории с 5 000 `.py` файлов: `GitSnapshot.build(repo, ..., base=head)` выбрасывает `ValueError: Git output exceeds bounded read`. **Исправление:** обрабатывать превышение лимита как явное ограничение snapshot и сохранять частичный результат с `limitations`; для списка изменений либо безопасно разбирать bounded prefix с отметкой неполноты, либо вернуть ограниченный snapshot без утверждения о полном ревью.
