# Day22 — первый RAG-запрос

## Результат и границы

CLI с режимами `rag` и `plain`, десять контрольных вопросов, сравнение ответов,
код и видео. Условие: экспорт 2026-10-01, messages5.html, строка 4653.
Используем неизменённый корпус и индексы Day21. Нового отбора, реранкера,
автоматического пополнения и полноценного наставника в этом этапе нет.

## Последовательность

1. Зафиксировать вопросы, ожидаемые факты и ID источников до прогонов.
2. Открывать индекс только для чтения через current.json. Structure — начальный
   вариант; Fixed доступен параметром. Проверять совместимость эмбеддера.
3. Получать вектор вопроса той же Qwen3-Embedding-0.6B с query-инструкцией,
   проверенной по официальной карточке модели. Косинусный поиск по всем векторам.
4. Выбирать top-5 с ограничением контекста; конкретный бюджет и способ подсчёта
   зафиксировать в конфигурации при выборе ответной модели. Передавать текст
   и идентификаторы источников, не исполнять инструкции из документов.
5. Один и тот же вопрос отправлять одной ответной модели с одинаковыми
   настройками, отдельно без контекста и с найденным контекстом. Независимые
   запросы без общей истории. Сохранять ответы, найденные ID и настройки.
6. Проверить офлайн математику поиска, ограничение контекста, два режима,
   обработку повреждённых данных и ошибок модели. Затем реальный прогон 10 пар.
7. Сравнить найденные источники с эталоном отдельно от качества ответов:
   обязательные факты, ошибки и утверждения без подтверждения. Сохранить
   результаты по каждому вопросу, включая неудачи; подготовить видео.
