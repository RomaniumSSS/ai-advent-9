# Day22: первый RAG

[Практическое видео](video/Day22-practical.mp4) · [Результаты](RESULT.md) · [10 вопросов](questions.json)

`rag.py` самостоятельно читает опубликованный SQLite-индекс Day21: импортов
соседнего дня нет. Подготовка вызывает только локальную Ollama, генерация —
OpenRouter с DeepSeek V4.1 Flash и единственным провайдером `deepinfra/fp8`.
Повторы, перенаправления HTTP и fallback отключены.

```sh
python3 -m pip install -r day22/requirements.txt
python3 day22/test_rag.py
python3 day22/rag.py prepare --root /opt/day21/private/index-release-v1 --questions day22/questions.json --output day22/private/prepared.json --ollama-url http://127.0.0.1:11434
python3 day22/rag.py evaluate --prepared day22/private/prepared.json --output-dir day22/private/run --env-file /secure/path/.env --budget .10 --limit 2
python3 day22/rag.py evaluate --prepared day22/private/prepared.json --output-dir day22/private/run --env-file /secure/path/.env --budget .10
```

Подготовку выполняют на машине с индексом и Ollama. До облачного запуска
нужно проверить выбранные тексты в `private/prepared.json`. В запрос модели
попадают только системная инструкция, вопрос, текст выбранных чанков и ID
источников; эталонные факты, исходные пути и метаданные авторов не передаются.
Режимы используют одинаковые настройки и независимую историю.

Одиночный запрос действительно генерирует один ответ. Для `plain` индекс
и Ollama не нужны; для `rag` добавьте `--root` и при необходимости `--ollama-url`:

```sh
python3 day22/rag.py ask --mode plain --question 'Что требуется в Day22?' --output day22/private/single.json --output-dir day22/private/single-run --env-file /secure/path/.env --budget .10
```

Контекст ограничен 18000 байт UTF-8, сериализованные сообщения — 24000 байт.
Это консервативные ограничения по байтам, а не измеренные токены DeepSeek.
Чанки не разрезаются. Для оценки расходов к байтам сообщений добавляется
1024 единицы резерва на оформление плюс максимум 1024 выходных токенов.
Перед запуском обновляется тариф конкретного endpoint; повышение выше
$0.14/M входных или $0.42/M выходных останавливает работу. Общая верхняя
оценка всех оставшихся запросов должна помещаться в бюджет, максимум $0.10.

`ledger.json` сохраняется до каждого платного вызова. Повторный запуск
пропускает завершённые вызовы; `--limit 2` делает пилот первой пары без
дополнительных запросов. Блокировка запрещает два одновременных процесса.
При неизвестной стоимости резерв считается занятым и работа останавливается.
Неоднозначный сетевой сбой или незавершённая запись запрещают автоматическое
продолжение: сначала нужна проверка фактического состояния у провайдера.
Удаление ledger ради повторного запуска может привести к повторной оплате.
Ответы, ошибки и ledger сохраняются с правами 0600, каталог — 0700.

Офлайн-тесты проверяют косинусное ранжирование, повреждённые векторы,
контекст без разрезания, настройки провайдера, бюджет, checkpoint, продолжение
и неизвестную стоимость. Они не доказывают качество реальных ответов.
Качество поиска и генерации оценивается отдельно по `EVALUATION.md`.

Для подготовки с Mac используется SSH-конфигурация `crm-agent`. Скрипт
передаёт исходник `rag.py` и вопросы через stdin существующему Python на VPS,
вызывает локальную Ollama там и сохраняет JSON на Mac. Файлы и сервис на VPS
не устанавливаются; API-ключ остаётся на Mac. На VPS нужны существующие
индекс, Ollama и окружение `/opt/day21/pipeline-venv/bin/python` с `requests`.

```sh
python3 day22/prepare_remote.py --questions day22/questions.json --output day22/private/prepared.json
python3 day22/rag.py evaluate --prepared day22/private/prepared.json --output-dir day22/private/run --env-file /secure/path/.env --budget .10 --limit 2
python3 day22/rag.py evaluate --prepared day22/private/prepared.json --output-dir day22/private/run --env-file /secure/path/.env --budget .10
```

Подготовка заново делает локальные эмбеддинги вопросов. Для продолжения
имеющегося прогона используйте его существующий `prepared.json` и каталог
ledger. Эти команды не разрешают повтор неоднозначно завершившегося вызова.


## Сохранённый результат

[Сравнение первого прогона](RESULT.md): 20 ответов (21 попытка, один разрешённый повтор после таймаута).
[Практическое видео без звука](video/Day22-practical.mp4):61с, запись браузера.
Ввод вопроса, настоящий поиск на VPS, открытие найденного задания, переключение
сохранённых реальных ответов DeepSeek и итоги20ответов. В кадре явно отмечено:
ответы читаются из прежнего прогона, новых облачных вызовов нет. Тексты
обсуждений скрыты; проверено совпадение нового контекста с исходным прогоном.
Прежняя презентация video/Day22-demo.mp4 оставлена как дополнительный обзор.

Пересоздать только локальный отчёт, без сетевых и платных вызовов:

```sh
python3 day22/report.py --prepared day22/private/prepared.json --run-dir day22/private/run-v1 --output day22/private/comparison.html
```

Первый прогон хранится в `private/run-v1`. Не используйте новый каталог
для его продолжения: новый журнал означает новые оплачиваемые вызовы.
Таймаут не считается бесплатным: его резерв сохраняется. После отдельной
проверки запись может быть отмечена `review=skip_without_retry` с причиной;
тогда продолжаются только остальные запросы. Это не повтор сбойного вызова.
Таймаут чтения HTTP для следующих вызовов —90с, соединения —10с.

После разрешения пользователя на повторы запись сбоя можно отметить
`review=retry_authorized` с причиной; следующий запуск повторяет только
неполученный ответ, сохраняет старую попытку и её резерв в общем бюджете.
Сетевой клиент сам не делает скрытых повторов. Успешные ответы не повторяются.

Формат query-инструкции эмбеддера сверён с
[официальной карточкой Qwen3-Embedding](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B):
инструкция добавляется к вопросу; тексты документов остаются исходными.


## Данные и воспроизводимость

Приватный корпус, индексы и ответы не входят в репозиторий. Офлайн-тесты
создают собственный синтетический индекс и запускаются без этих данных.
Для настоящего поиска нужен индекс формата Day21 и соответствующий ему
локальный эмбеддер; пути в примерах указывают на среду выполненного прогона.
Панель съёмки и report.py дополнительно требуют локальные артефакты run-v1.
Для Chromium вне стандартной установки Playwright задайте
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` (путь к исполняемому файлу браузера).
