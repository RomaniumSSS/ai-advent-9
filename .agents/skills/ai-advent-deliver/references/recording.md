# Запись браузерного приложения на этом Mac

В Day26 уже есть рабочий пример: `day26/video/record_live.py` и
`day26/video/README.md`. Использовать его подход в новом скрипте дня,
сохраняя сданные файлы Day26. Не переносить его фиксированные URL, вопросы и пути вывода.

1. Проверить наличие Playwright, Chromium и ffmpeg в выбранной среде и доступность
   локального приложения. Переиспользовать установленное, не менять зависимости других дней.
2. Создать отдельный browser/context и фиксированный viewport, например 1280×1000.
   Снять и прочитать пробный кадр. UI должен быть читаемым, с видимыми действиями и ответами.
   Использовать `record_video_dir` / `record_video_size`; это запись viewport приложения.
3. Реализовать один сценарий, вызываемый и в сухом режиме, и при записи. При записи новые
   ответы получает само приложение; подменять API или проигрывать старые ответы нельзя.
   Дожидаться конечного состояния нового запроса. Новый контекст исключает старые маркеры.
4. На ключевом ответе выдержать паузу для чтения. Если ответ длинный, прокрутить экран
   после завершения и показать нижнюю часть. Не сокращать сырой ответ для сокрытия ошибок.
5. Получить `page.video`, закрыть context и сохранить webm. Закрытие context/browser
   оформить через `finally`, в том числе при таймауте сценария. Не использовать пользовательский
   Chrome-профиль с открытыми Drive, таблицей или другими окнами для автоматической записи.
6. Конвертировать собственный webm в новый mp4 через ffmpeg без ускорения,
   с `libx264`, `yuv420p`, `+faststart`; не использовать `-y` для существующей сдачи.
   Пример аргументов: `ffmpeg -i input.webm -c:v libx264 -crf 20 -pix_fmt yuv420p -an
   -movflags +faststart output.mp4`. Передавать пути как аргументы subprocess, без eval.
7. Проверить длительность через ffprobe; извлечь несколько кадров на разных этапах
   и прочитать их через просмотр изображений. Результаты проверки и данные запросов
   должны относиться к этой записи. Запись без успешного обязательного шага — не готовая сдача.

Если пользователь выбирает запись всего рабочего стола, уточнять готовность экрана нужно
только при наличии открытых личных окон, которые захватит выбранный рекордер. Запрашивать
такую готовность для изолированного viewport не требуется. Отключённый интернет или полную
изоляцию сети считать проверенными только после реальной проверки, не по адресу localhost.

Полноэкранный `record_screen.sh` из репозитория Ивана пока не установлен и не запущен:
его общий PID-файл и платформенные команды требуют отдельной адаптации. Для наших
браузерных заданий уже проверенный подход Day26 достаточен.
