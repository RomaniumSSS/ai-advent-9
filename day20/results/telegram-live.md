# Day 20 — живой Bot API, исследование и продолжение

28.09.2026, `crm-agent`, разрешённый приватный чат существующего бота.
Отдельный poller Day 20 получил реальный входящий update; chat/user ID и
токен не сохранены в репозитории. Пользователь подтвердил, что **первый ответ
виден** в Telegram. Проверка использовала настоящие Qwen3.8 27B на DeepInfra,
Habr MCP, официальный GitHub MCP v1.12.2 и Bot API; fake-сервисы не участвовали.

| Шаг | Сохранённый результат |
| --- | --- |
| Исходный запрос | входящий `message_id=13`, request `d1cb3881-8266-4b4c-b9e9-5f92173ee428` |
| Ответ | `verified`, исходящий `message_id=14`, статус `delivered`; пользователь подтвердил видимость |
| Trace | [первый trace](telegram-live-trace.json): 8 модельных ходов, 7 предложенных MCP-вызовов, 6 успешных observations из Habr и GitHub, полная статья и README, `article_link`, стоимость по `usage.cost` $0.0097887 |
| Продолжение | входящий `message_id=17`, parent — исходный request, тот же URL статьи и репозиторий |
| Ответ на продолжение | `verified`, исходящий `message_id=25`, статус `delivered`; пользователь подтвердил видимость |
| Trace продолжения | [второй trace](telegram-followup-trace.json): 5 модельных ходов, 4 успешных observations из двух MCP, полная статья и README, `article_link`, $0.00544005 |

На VPS хеши всех 6 и 4 успешных observations сверены с закрытой папкой
`/var/lib/day20/evidence/`. Суммарное фактическое списание двух запросов —
$0.01522875. Неподтверждённых повторных отправок ответов не было.

Первый живой follow-up вскрыл ошибку состояния: агент установил связь
репозитория со статьёй, но запрос сохранил `link_basis=unconfirmed`.
Обработчик несколько раз попросил подтверждение. Poller остановили;
после резервной копии SQLite сохранённый `article_link` сверили с trace,
восстановили **первый** follow-up и пометили три лишние ветки `superseded`.
Повторные сообщения бота уже были доставлены и не скрываются в отчёте.
Исправление сохраняет доказанную связь в запросе, направляет обычный текст к
последнему ответу/уточнению и объединяет повторные подтверждения. После
исправления 37/37 офлайн-тестов прошли локально и на VPS, продолжение
завершилось один раз. Резервная копия БД осталась только в закрытом каталоге
`/var/lib/day20/`.

Техническая метка `verified` означает полный охват требуемых источников, а не
истинность каждого вывода. Ручной просмотр: `list_issues` действительно
вернул `totalCount=0`, причём схема официального MCP без фильтра включает
открытые и закрытые issues. Само число подтверждено на момент чтения, но
вывод модели «низкая зрелость/активность» из отсутствия issues и одного
**прочитанного последнего** релиза не доказан; историю релизов не читали.
Первый шаг во втором ответе предлагает запуск в тестовой среде без аудита
кода; это рекомендация модели, фактический запуск не выполнялся.

Короткая [запись экрана](../demo/telegram-evidence-walkthrough.mp4), сделанная
**после** второго ответа, показывает сохранённые trace и доставку, но не
доказывает живой запуск. Отдельная [запись нового живого запроса](../demo/telegram-live.mp4)
началась до его получения; её trace и проверка описаны в
