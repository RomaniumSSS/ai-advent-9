# Day 20 — офлайн-проверки и прямой MCP probe

28.09.2026, macOS arm64, Python 3.12, проектный `mcp` 2.2.0. Команда
`uv run python -m unittest day20.test_offline -q` → **37 tests, OK**
(5.541 с после исправления follow-up и сохранения связи статьи с репозиторием).
Управляемые fake provider/Bot API использованы только там, где
внешние сервисы не требуются.

Проверены два отдельных stdio MCP с одинаковым исходным именем `echo`:
alias направляет вызовы на правильный сервер, неизвестный write tool закрыт,
JSON Schema отсекает неверные аргументы, `isError`, большой ответ и таймаут
не становятся успешным observation. Нормализатор принимает текстовый и
ресурсный блок. Habr snapshot переживает новое соединение/открытие SQLite;
пропуск части и обрезанный текст не дают `complete_read`.
`run_id` чтения статьи привязан к текущему запросу и скрыт из схемы для модели;
GitHub README с путём
`/README.md` и `README.md` проходит одинаковую проверку источника.

Fake provider проверяет связь `tool_call_id`/observation, один исполняемый
вызов на ход, подсчёт всех предложений, резерв стоимости при отсутствии
`usage.cost`, проверку источников и один ограниченный ремонт финального JSON.
Подтверждение репозитория пользователем без прямой ссылки/встречной ссылки
оставляет `limited`; встречная ссылка в README допускает `verified`.
Видимая инструкция внутри статьи или README не расширяет разрешённый каталог:
попытка вызвать write tool возвращает ошибку. Второй tool меняется при другом
содержимом Habr observation.
Профиль OpenRouter фиксирует `qwen/qwen3.8-27b`, DeepInfra и отсутствие fallback.
Fake Bot API проверяет два URL в reply на сводку, выбор после рестарта,
личную цель, отдельный GitHub-кандидат с подтверждением, follow-up,
повтор `update_id`, чужой chat/user, чужого автора reply, недоступный текст
сводки, `unknown` после неопределённой отправки, активный webhook и OS lock
второго poller.

Прямой сетевой probe через настоящий router с локальным Habr MCP и официальным
GitHub MCP v1.12.2: Habr `/articles/1007122/` выдан в двух частях через разные
stdio-соединения; GitHub `get_file_contents README.md` публичного
`vuguzum/self-aware-mcp-server` дал текстовый блок и resource
(3 352 символа), `get_latest_release` и `list_issues` ответили. Секрет GitHub
передавался только дочернему GitHub MCP. Версия/asset и прямой первоначальный
probe — в [P0](p0-compatibility.md).
