# Day 20 — реальный локальный прогон Qwen + два MCP

28.09.2026, запрос про пригодность Self-Aware MCP Server для диагностики Linux
VPS; входная статья — [Хабр](https://habr.com/ru/articles/1007122/), её прямая
ссылка ведёт на [публичный GitHub-репозиторий](https://github.com/vuguzum/self-aware-mcp-server).
Модель `qwen/qwen3.8-27b` была закреплена за DeepInfra без fallback. Перед
платным вызовом live preflight подтвердил `tools`, `tool_choice=auto` и
консервативный worst case **$0.246224 ≤ $0.25** для 10 модельных ходов.

Итоговый локальный run `1dfe7a19-720f-46f1-855d-b21c3aeb954d`:

- 6 модельных ходов, 6 предложенных MCP-вызовов, из них один отклонён
  правилом «один исполняемый вызов за ход» и повторён моделью следующим ходом.
- Habr: обе части статьи, `complete_read=true`, текст не обрезан,
  snapshot `ca9102b1-47a3-48b5-863f-6b065771acac`. При известном URL
  RSS-поиск не показывается модели и не расходует ход.
- GitHub: корень репозитория,
  [README на commit `3ef2e676`](https://github.com/vuguzum/self-aware-mcp-server/blob/3ef2e676e5ed68c8786e672dff351b0566908a42/README.md)
  и [релиз v1.0.2](https://github.com/vuguzum/self-aware-mcp-server/releases/tag/v1.0.2).
  `list_issues` в этом запросе не вызывался. Вызовы шли через официальный MCP,
  а не отдельный GitHub HTTP-клиент для исследования. Отдельный HTTP-запрос
  используется только как guard, подтверждающий публичность репозитория.
- `usage.cost` по 6 ходам — **$0.00741585**; резерв вместо нуля не требовался.
  Статус ответа — `verified` по техническому критерию SPEC. [Безопасный trace](real-local-trace.json)
  фиксирует порядок, alias/server, call ID, время, аргументы без личного текста,
  статусы и hash observations. Полные публичные выдержки и SQLite хранятся
  локально в игнорируемой Git папке `day20/data/`.

Ручная сверка: четыре заявленных инструмента, реализации TS/Python/C# и
`/etc/os-release` есть в статье; README подтверждает инструменты, структуру,
npm-пакет и MIT. Релиз действительно опубликован 15.04.2026 и касается
калькулятора. Вывод «для диагностики VPS не подходит как сборщик метрик» —
оценка назначения проекта по доступной документации, а не тест работающего
продукта. Фраза модели «единственный релиз» сильнее выполненной проверки:
был прочитан **последний** релиз, список всех релизов не проверялся.
Утверждение статьи про безопасность `calculate` не заменяет аудит кода.
Модель также предложила «read-only проверку вывода» инструмента; для получения
вывода понадобился бы запуск на тестовой машине, которого здесь не было.
Честный первый шаг по текущим доказательствам — просмотр README и кода
`get_current_system` без запуска проекта.

Ранние реальные попытки корректно отклонены проверкой финала
(`final_not_json`, `unsupported_fact_reference`) либо завершились `limited`
из-за варианта пути `/README.md` или исчерпали лимит после ошибочного
служебного `run_id`. После нормализации пути и внутренней привязки `run_id`
итоговый запрос прошёл без ремонта финала. Для Telegram выполнен только
[read-only preflight](telegram-readiness.md); доставка и подтверждение
пользователя здесь не проверены.
